# 开发试跑独立审查 · 2026-09-10

结论：保留n=300，修正测量与证据后再验证两路并行；当前不通过正式冻结验收。此次只审核，未修改试跑源码、测量规格或已有结果，未新增网络请求。

## 1. 阻断：成功执行不能证明跨期持仓适配充分
位置：MEASUREMENT_SPEC.md §2 H1；pilot_measure.py:179–181。

stage0、token_before==amount、token_after==0证明“在本次注入的状态中，该调用完成且余额归零”，不证明注入状态等价于真实买入后的退出状态，也不证明任意状态下balanceOf/transferFrom共用同一套账。

具体反例（源码语义反例，未声称本次在EVM部署复现）：代币买入时设置unlockAt[buyer]=buyTime+90天，卖出要求timestamp>=unlockAt[buyer]。真实持有30天仍应拒绝；只注入余额而让unlockAt保留默认0，卖出成功且清零，完全满足当前H1。反射/重基导致30天后应卖数量不同也不能由该判据排除。

应保留模拟余额证据，将holding_state改为未证明/部分适配；只有另有可审查状态语义依据才能升级充分。本轮5个measured_exit只能列为注入状态下模拟完成，不能因此将M/Z视为已经可判定。不能仅改标签而保持经济统计可用标志不变。

## 2. 阻断：首次Mint和无Mint结论缺少核验
位置：pilot_measure.py:55–69。

只取Etherscan第一页1000条，不检查截断/分页、address/topic/块范围/removed/块hash，不验证最早事件或相邻totalSupply状态。status1空数组直接记no_mint_by_cutoff。总池数对账不能替代每池Mint核验。

本次无网络mock复现：
- 响应{'status':'1','result':[]} → (None,'no_mint_by_cutoff')，没有链上状态交叉核验。
- 响应仅含{'blockNumber':hex(24136000),'logIndex':'0x0'}，请求from=24136053 → (24136000,'ok')；连事件地址/topic都缺失且块号越界仍接受。

应复用已验证的首次Mint方法，以创建块为下界验证totalSupply边界并核对单块事件；或使用有完整性保证的日志路径加状态核验。声称独立确认无Mint须附原始响应，当前交付目录未找到该独立证据。0 RPC的该候选还发生了Etherscan调用，不能称零网络成本。

## 3. 阻断：规格中的状态覆盖检查未在候选编排执行
measure只取一次finalized，没有eth_chainId核验，没有逐候选钱包代码/余额原值与恢复检查、协议身份/字节码校验、结束时块hash复读。仅调用probe_call不等于调用Verifier.override/buy中的校验。历史控制币端点8/8不能替代候选对应快照校验。缓存与复用应显式绑定chain/块hash/代码/完整覆盖参数。

首次Mint→入场和30天退出的块号/hash、相邻时间戳应保存并复核。当前只在全局保存finalized hash，候选行不保留所有原始状态块证据。

## 4. 阻断：失败分类与成本不一致
- MEASUREMENT_SPEC §3的stage20统一映射未知，但编排表和pilot_measure.py:151直接把买入stage20映射entry_failed_verified。未验证钱包/持仓模型时不能把通用revert升级为已验证入场失败。
- stage10/11可保守记模型不支持/环境未知，但不能声称已经查明原因必是注入不足；代币行为也可能令授权不足。
- gas_table调用固定买入1、卖出1、approve2；stage10在授权前返回、stage11/12可能尚未到swap，固定次数不反映路径。买入失败以及买入后中途data_missing/适配失败又没有cost记录，会漏掉已到达阶段的设计成本。
- baseFeePerGas缺失默认0，与缺失不记零原则冲突。
- 应按阶段记录模拟策略的交易/授权尝试、成本情景和未发生/未知，不把HTTP重试或诊断调用自动当成交易尝试。helper内联授权与独立EOA授权的区别继续保留。

## 5. 阻断：原始证据、退出状态和续跑尚未接入
pilot_results.json没有rpc.records，没有Etherscan原始响应，没有pilot脚本hash/规格hash、资源采样和阶段耗时。数据仅最终一次write_text；所有候选失败也会return0，started_at是在结束时填写。right_censored分支提前continue，漏写elapsed_s/rpc_calls。measure未检查声明中的universe hash是否仍匹配实际台账。

因此能复核状态汇总，不能凭此包独立重放全部链上响应，也不能确认并发或缓存性能。应复用现有证据保存/资源限制能力；记录每次候选尝试并持续落盘。续跑绑定同一冻结样本、规格、脚本版本和状态块，保留失败历史，不用最终成功覆盖原失败。采集失败/未完成应在退出码或明确的机器验收状态中阻断正式结果。

## 6. 报告中未被证据支持的推断
- 实际包RPC.request对URLError/TimeoutError/OSError立即抛transport；只对特定HTTP状态重试一次。RemoteDisconnected属OSError一类，当前“包内重试仍失败”与源码不符。现有结果缺attempt明细，不能确认额外外层重试；一次错误不能证明其后恢复或排除客户端连接处理问题。
- identity_probe不在pilot_measure的诊断实现中，结果JSON仅有size_probe_stage；若另做过诊断，应补原始调用。两个无买入历史的地址都失败，也不能排除两者都缺历史状态。
- 最小单位仍失败不能排除规模相关机制；可能最低输出取整为零或其他限制共存。
- 6个完整路径成本接近，不能推出没有长尾；1/8失败不能预测300例必有30–40个失败。3rps→15rps耗时变化也不能分解出节点计算/网络时间。
- slot_scan_calls=34漏计扫描前原值读取。唯一命中时实际find_slot为35次：原值1+第一哨兵32+第二哨兵1+恢复核验1。32槽只给有限搜索范围内唯一性，不是任意布局的充分性。规格D1的“固定2×limit”也不符合当前按首次命中才试第二哨兵的分支。

## 7. 实际资源复算与并发决策
原JSON全局RPC370，其中1次共享finalized，逐候选合计369；至少另有8次Etherscan请求，未纳入RPC数。候选耗时总和600.33秒，与记录总耗时600.3秒取整一致；8例均值75.04125秒。原报告86.9秒含重试的加权算法没有相应记录，不能复算；机械乘300约6.253小时也不能当预测，因为失败候选没有完成后续工作，样本小且分支不全。

8小时上位约束是追加主动工时，墙钟/人工/额度分别记账，不能仅以7.24小时机器耗时判定超主动预算。

建议：不因未验证的耗时预测降低n。先修上述阻断，再在同一固定开发集合比较串行与2路并行；验证逐条状态、金额和输入一致、全局限流/预算和请求ID隔离、资源上限、错误率、断点恢复。3.14小时只是理想除2情景，不是承诺。时间插值仅产生二分初始边界，必须证明左右时间戳包围目标、失败时扩展，并核验最终块及前一块；不能用平均出块时间替代精确定位。
