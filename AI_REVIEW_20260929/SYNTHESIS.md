## 0. 前置拆分

**目标**：从首笔实盘起 3 年，累计净收益约 100 万（背景.md 口径；B2 转述为含未平仓净清算值、扣应付税费，任一时点达标）。

**资金约束**〔双，细节来自 B2〕：

- 首笔 1 万；一年内权益 ≥10 万可追加 2 万；
- 首笔亏完可再投 1 万；累计亏 2 万暂停；
- 第三笔 1 万须先过模拟盘标准（未定）；累计亏 3 万永久停止。
- → 约需 100× 权益增长。

**时钟**：从首笔实盘起算〔双〕。研究期不消耗目标时钟，研究不会因“时间到了”而自然停止。

**数据资源**〔用户〕：

- Dune 仍有额度，另新充 2500 credits；付费 SQL 须用户在网页手动运行。
- Helius 约 90 万 credits。
- 额度目前不是瓶颈。

**事实**〔双〕：

- 右尾母体存在；
- 多组 summary/state/exit/wallet-activity 规则在各自范围内未形成优势；
- 没有已验证 edge，也没有证明公开链上选择无效。

**核心未验证假设**：存在当时可见、在剩余可兑现空间耗尽前可识别、扣现实成本后仍足够大的机会。

**上游检查**：

1. **规则已有，故障在执行点**〔双〕：取数、复用、结论升级、修订同步 → 规则按触发时刻写。
2. **缺少资源分配层**：v1–v3 把下一步定为 R1a，主要因为它已在队列里。“已批准”不等于“当前价值最高” → 在决策点设组合门。
3. **两层分开**：场所无关的长期规则，和当前 pump / DQ-21 的程序契约，必须分开写，否则当前状态会冒充长期方法（P18）。
4. **确认数据是紧约束之一**——这是工作判断，不是事实。根本瓶颈在哪里 UNKNOWN。“先定确认去向”的依据是事实，不依赖这个判断：
   - 开发周已被约 11 条路线复用〔B2〕；
   - 封存窗 NOT CERTIFIED〔勘〕；
   - 看过结果再挑确认窗，本身就是研究者自由度。
5. **研究问题**（B1 的重述）：何种当时可见信息，在完整生命周期、错选损失与资金占用下，具有值得继续验证的净经济增量？富集、净回收、账户路径是三个不同层级的主张。

- 要点击的步骤；
- 下载文件名、预期字段与行数；
- 放置位置。

你只做机械操作。执行者收到文件后先核对行数、字段和哈希，再往下做。

### Research

一个当前有额度的强模型；Research 是模式，不是常驻角色。

- **搜索**：按供给类别覆盖——项目已有资产、现成数据集/论文、托管查询、API/RPC、批量归档。凡可能改变 BUILD/BUY/USE 决定的类别，各看一个代表。已有满足字段、时点、成本、历史覆盖要求的路径，且再搜不太可能改变决定，即停。
- **开发期**：允许 winner-first、局部模式、纯统计探索，并记入研究记录。
- **候选池**：新想法随时可以进入。只在决策点经组合门重新分配资源。

### Engineering

现有 VS Code→WSL→Git + 一个 coding agent（Claude Code 或 Codex，按额度）。复用现有 SQL、估值栈与缓存。新增产物都是文件，不是系统：

1. **事故与边界病例集**：两个用途——

   - 复用任何实现前跑回归；
   - 新语义映射拿其中的原件做病例追溯。

   通过回归只说明已知事故没有复发，不认证新语义。当前内容见输出 7 的程序契约。
2. **研究记录**（只追加）：记录每批评估的变体数，以及每个改变检验空间的决定（候选、指标、窗口、阈值、样本）；按信息族 × 数据窗口计数。
3. **数据契约**：每次取数前写一张——查什么、日期窗口、字段、可见时点、预计消耗。取回后在 git 记路径 + 校验和。
4. **冻结的评分器**：每个进入确认批次的主策略，都配一份事先冻结的评分代码和评分 SQL，拿到数据直接出指标。

### Evidence

**证据必须匹配主张：**


| 主张                         | 需要的证据                                                       |
| ------------------------------ | ------------------------------------------------------------------ |
| 某能力存在                   | 官方文档                                                         |
| 本账户、本路径的费用与可用性 | 小批实测 + 控制台增量                                            |
| 当时算出了什么               | 保存的产物 + commit                                              |
| 计算是否正确                 | 从原件独立复算、反例                                             |
| 新的语义映射是否成立         | 原件病例追溯（含边界类型）对照一手规范；模型意见只能提供待查反例 |
| 策略是否样本外成立           | 按规则评分的确认批次                                             |
| 能否成交、延迟多少           | 真实执行观察                                                     |

**确认数据的等级：**

- **T1（采用）——日历批次**：
  - 批次按代币创建时间划分，边界提前固定。
  - 策略、评分代码、评分 SQL 在批次开始前冻结，就进入这一批；否则等下一批。
  - 批次长度由主指标的事件率和观察期推出，最迟在第一个候选冻结时定。
  - 每批只有一个主策略；次要策略须事先登记，只作诊断。
  - 批次结束且观察期满之前，不取这段数据；评分确定性、只做一次，不得事后剔除样本或换指标。
  - 评分后，该批变为开发数据；任何改过的策略只能进后续批次。
  - 评分时在 Dune 网页看到结果，不污染已冻结的策略；需要防的是评分前有人使用、以及评分时的事后选择。
- **T2**：元数据暴露审计支持的历史窗口，较低等级的 OOS。“未发现暴露”不等于证明洁净。
- **T3**：06-15～07-12 为 NOT CERTIFIED，至多作辅助，永远不称 clean holdout。

**其他：**

- 不算证据：模型一致（包括第二模型读过程稿后的“校对通过”）、文档单价、Legacy 摘要、聊天推论。
- 用户裁决是授权，不是认证。
- 层级分开标：开发 / 确认（T1/T2/T3）/ 前向 / 实盘；富集 ≠ 净回收 ≠ 账户路径。

### Second Model

**三道固定门：**

1. 某个确认批次评分之前：审冻结的策略、评分代码与 SQL；评分后可独立复算指标。
2. 真实资金或签名相关动作之前。
3. 宣布关闭一个完整信息族之前。

形式：读冻结 commit 与规格，从原件独立复算或构造反例，写进 `3_审计`；一轮审计，修复后只查相关改动。

**一个语义例外**：出现新的承重语义映射（如“此关系＝funding/source”“此事件＝owner/control”“此价格/退出＝可执行经济量”），且它将支撑超出冒烟规模的取数，或 ≥2 张后续卡片。

- 先由执行者做原件病例追溯；
- 第二模型可以专门构造反例病例，它的赞同不算证据。

理由：nonce 案例中两个模型最初都接受了错误归因〔B1〕；F116、F85 都是由原始数据纠正的〔B2〕。

### Security

- 研究环境永不持有钱包种子、私钥或签名权限。
- 旧 key 已无用，不撤销〔用户〕；不在任何文件或报告中展示。
- repo 公开〔用户〕 → 批次数据在评分前不取；首个开发正结果出现时，再决定一次可见性。
- 主研究环境里有 Dune/Helius key 和 GitHub 写权限。第三方 skill/MCP 按“发现 → 检查指令与源码 → 在无凭证环境低权限试用 → 只给必要权限 → 决定采用或拒绝”处理。官方工具不等于自动可信。
- 外部网页、仓库、MCP、代币元数据都视为不可信输入；不开全权/bypass 模式；权限配置用一次实际读取验收〔B1〕。

## 输出 3 — Hard Rules（7 条，按触发时刻；与场所无关）

1. **分配研究资源时（组合门）**
   - 只在决策点重新分配：某信息族完成或停止时。提前中断只能出于改变可行性的事实——数据路径不存在、成本超出预算、严重语义错误、经济上限被推翻。
   - 每个候选按区间判定：经济上限、该决策时点的保本所需富集、剩余可兑现空间、按时点取数的可行性与成本、结构新颖性、确认就绪度。
     - 乐观而自洽的上界仍不够 → 不通过；
     - 保守下界也够 → 通过；
     - 区间跨越准入线 → 先解决再说：点名一个变量、一个最便宜的测量、一笔预算。无法便宜解决的，移出活跃组合、留在候选池。
   - 所有候选共有的未知，只做一次程序级基础测量。
   - 多个候选通过时，选下一步最便宜、最可逆、最快能改变决定的。
   - “未测”本身不是理由。
2. **取数前**
   - 写数据契约，日期窗口不得越过任何未评分确认批次的边界。
   - 搜索按供给类别覆盖，满足停止条件即停。
   - 预计消耗占剩余额度比例较大或单价不明时，先小批实账。
   - 需要用户手动执行的步骤打包交付；取回的文件先核对行数、字段和哈希。
3. **定义或复用变量前**
   - 写语义契约：含义、可见时点、总体、缺失、分母、模型假设。
   - 新的承重语义映射，先过原件病例追溯。
   - 复用旧实现，先过事故与边界病例集。
   - 估值假设有争议时，按每个边界假设分别报告。
   - 通过回归 ≠ 语义认证。
4. **冻结时（看结果之前）**
   - 写定指标、升级/停止条件、入场经济栏，以及确认去向——其截止日在冻结之后的下一个 T1 批次。
   - 指定主策略，冻结评分代码与评分 SQL。
   - 富集门、经济门、账户门分开写。集中度、去最大赢家、分周稳定只报告，不作淘汰门。
   - 看过开发结果后再改确认去向，必须记录原因并下调证据等级。
5. **写结论或更正时**
   - 写明范围（母体、窗口、决策时点、信息表示、退出、估值口径、成本）、证据层级和停止层级（实现 / 程序 / 领域；有限实验只支持前两层），并在研究记录追加条目。
   - 富集等筛选量不得代替净回收。
   - 一个信息族算不算新，最终看它在同一决策时点、同一成本下，相对已有信息有无经济增量。
   - 更正时，同步所有承重引用（总入口、事实库、卡片、代码消费者），旧文保留并指向更正。
   - 用户裁决授权资源，不认证事实。
6. **不可逆动作前**
   - 评分确认批次、超出授权付费、前向、真实资金、凭证权限，只由用户触发，且须有冻结 commit、暴露登记和第二模型把关。
   - 其余已授权工作不逐项请示。
   - 研究环境永不持有签名权。
7. **交付与元工作**
   - 交付＝一屏决定块＋证据路径；模型之间只经 repo 文件交接。
   - 研究程序在“证据耗尽（无通过候选，也无可便宜解决的先解决候选）”或“资源耗尽（用户设定的上限）”时停止。两者都不宣称领域证伪。
   - 除非同一具体故障重复出现，或供应商变更使管线失效，不新增流程、工具、agent，也不修改本文件；不恢复工时硬停。

## 输出 7 — Next Real Research Stage

**问题类型：候选信息的可测性与经济增量检验（开发期），前面加一道组合门。**

> 一种当时可见的信息表示，是否被正确测到？相对已有信息，它在剩余可兑现空间仍然足够时，是否带来值得进入确认的净经济增量？它是否仍是当前最值得投入的方向？

### 行动顺序

1. **现在**：跑 S1 A/B（交接包 → 你手动运行 → 执行者核对文件）。同时，候选池里每个活着的方向各填一行组合表，深度相同，不细化 R1a。
2. **S1 出结果后——组合门**：每项按“通过 / 不通过 / 先解决再说”判定，选出当前唯一的活跃信息族。
3. **选中者冻结前**：补定义缺口；定 T1 批次节奏；指定主策略，冻结评分器；做承重语义的原件病例追溯。
4. **开发检验**：数据契约 → 你手动取数 → 核对文件 → 检验。交付三个判断：
   - 测到了什么；
   - 相对已有信息的净经济增量（富集只作诊断）；
   - 证据能走多远——进入预定 T1 批次，或修正数据路径，或实现 STOP。
5. **10-16**：治理复核，定程序资源上限，并复核候选池。

**不做**：重跑旧负结论、重做母体普查、设计交易策略、建高维发现平台、同时推进第二个信息族。

### 当前程序契约（pump / DQ-21；换场所时整体重写，不进入长期规则）

- **估值**：A/B 双口径并报；B 不是真实执行上界〔B1〕。
- **事故与边界病例集**：
  - 34 笔链上立即往返〔B1〕；21 个同状态币〔B2〕；
  - DQ-1M v1 卖出口径（0.753→0.969）；
  - 创建者“此前 30 天”实为固定起日累计；30 天标签误用 60 天峰值日期；DQ-18 取整尘埃伪穿越〔B2〕；
  - 边界类型的真实交易：nonce 提款、服务/交易所地址、PumpSwap 反向池、尘埃。
- **复用**：旧特征复用前，过 §5.1 缺陷表中的相关项；R0 旧 flows 只供复现。
- **基础比率参考**：全买回收——早期 0.74–0.98、+30m 0.969、晚期 0.43–0.74；≥2× 固定退出赢家每日约 86–165 个〔B2〕。这些用于推算保本所需富集和 T1 批次长度。
- **开发数据**：06-01～14（A/B 两周，已高度复用）；新开发取数的日期不得越过未评分 T1 批次的边界。
- **执行**：Dune 付费 SQL 由用户网页手动运行；Helius 可由 agent 调用。
