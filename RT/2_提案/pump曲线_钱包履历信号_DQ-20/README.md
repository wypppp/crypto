# DQ-20 提案：钱包履历信号——“谁在买”能否挑出净回收 >1 的币

> **状态：提案 v1（2026-09-25，待用户裁决），没有产生任何数据**｜起草：Claude（上位模型）｜依据：用户 09-25 “深度分析链上信息”“直接在 Dune/Helius 查”｜现状以[总入口](../../00_总入口.md)为准

## 1. 问什么

在 pump +30 分钟活跃池里，如果一个币被一批**在别的币上反复早买中赢家的钱包**买入，之后按 `b50` 持有的净回收是否 >1？

- 这是**参与者层面**的链上信息：谁在买、他们过去在别的币上的记录；
- 此前所有 pump 实验用的都是**聚合状态**（成交笔数、买卖额、价格、控盘），DQ-19 已判定这一类停止。

## 2. 按总入口 §6 第 5 条

| 项 | 内容 |

## 3. 定义（草案，批准后冻结）

- **A 周（06-01～07 创建）定义钱包，B 周（06-08～14 创建）检验。** 只在 B 周判定；A 周内的结果属于样本内，只作描述。
- **赢家**：F3 面板中的 A 周币，从 +30 分钟入场起路径最高 ≥10×，而且在 **06-08 00:00 UTC 之前已经达到**（按面板中已经结束的区间保守计）。这样 B 周决策时只用到当时已知的结果。
- **早买**：币创建后 30 分钟内（即我方 +30 分钟入场之前）的买入，含曲线与 pump 创建的 PumpSwap 池；排除该币的创建者。
- **履历钱包集 𝒲**：
  - 在 A 周早买过 ≥2 个不同的赢家；
  - 并且早买命中率（早买过的赢家数 ÷ 早买过的币数，分母含 A 周所有 SOL 币）≥5%，约为基础比率的 5 倍。

  第二条是为了排除“什么都买”的抢跑机器人。
- **B 周信号**：检查点 j ∈ {+30 分钟入场、15 分钟、1 小时、4 小时}。截至该时点，买入过该币的 𝒲 中不同钱包数 ≥2 时触发。
  - 每币只在首次触发时买入 0.5 SOL，之后按 `b50` 持有；
  - 估值直接用 DQ-19 的 R_j（F3 面板，扣 0.004）；
  - 阈值 ≥1、≥3 只作敏感性描述。
- **判定**（B 周，同 DQ-19 §6）：
  1. `E[R|S]` ≥1.00；
  2. 去掉贡献最大的 1 个币后 ≥1.00；
  3. 触发 ≥20 币；
  4. 高于随机签名基线的 95 分位。

  全部满足才叫“信号候选”，仍不叫经济可行。

## 4. 同时报告（描述）

- 𝒲 的规模与画像：钱包数；每个钱包在 A 周早买的币数（是否仍像抢跑机器人）；与创建者的重合。
- **跟随反应曲线**（对应用户 09-25 的判据 A/B）：对 B 周触发的币，看 𝒲 钱包买入之后第 +1 个 slot、+5 秒、+30 秒、+2 分钟的价格变化，以及这期间还有谁在买。
  - 如果大部分涨幅在 1–2 个 slot 内就完成，而且先动的总是同几个地址，那就是事实上的排他机会，我们做不了；
  - 如果涨幅在几十秒到几分钟里逐步展开，才是“够快就能分”的非排他机会。
  - 这一步只为触发的币取逐笔数据，Dune ≤20 credits，计入总额。

## 5. 查询设计要点

- 一条单链查询：A 周早买 → 𝒲 → B 周 𝒲 的买入 → 按（币, 检查点）聚合。每个 CTE 只引用一次（Trino 会把多次引用的 CTE 重复展开）。
- 输出只含被 𝒲 买过的 B 周币，另加一行汇总。
- 先用 H1 的 6 个案例币做固定对照，核对 `user`、方向、金额字段。
