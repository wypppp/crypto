## 一、只回答一个问题

**对于在代币创建 30 分钟后才行动的人，"现实世界注意力 → 代币"这条链上，是否经常存在一个"注意力还没见顶、价格还没走完、该买哪一只已经看得出"的时间窗？就算事后挑最好的情况，它的经济上限够不够？**

- 时间窗很少出现，或者乐观上限都达不到目标 → 关闭 pump 上的注意力路线，不跑 2.9 万个币的收益检验。
- 否则进入 R1 开发，并由本卡的映射结果决定信号形式。

## 三、步骤

1. **匹配**：
   - 名称和符号规范化后，与事件实体做字符串候选匹配（英文 ≥4 个字符，中文 ≥2 个字）；
   - 候选对由便宜模型判断是否指同一事物，模型看不到任何价格或结局；
   - 规则写成脚本并记录 sha256 后才运行。
2. **定义事件**：一个实体在某日的注意力突增，满足以下任一条：
   - 维基百科：当日浏览量 ≥ 前 7 日中位数的 3 倍，且 ≥2 万；
   - 微博：首次上榜。
   - 只保留至少匹配到 1 个 A、B 活跃币的事件。
3. **抽样**：从合格事件中**按事件随机抽 60 个**，不看任何代币结局；逐个标注来源类型：
   - 主流外生：影视、体育、政治、名人、社会新闻；
   - 加密圈内：加密人物、项目、交易所；
   - 是否为事先排期的事件。
4. **逐事件测量**：

| 量 | 定义 |
|---|---|
| 注意力起势日、峰值日、半衰天数 | 维基百科日度；微博以首次与末次上榜估计 |
| 首个匹配币创建时刻、创建后 24 小时内同名活跃币数 | Helius + 面板 |
| **入场时焦点币** | 在该币 +30 分钟时刻，组内（已创建的同名活跃币）储备最高者 |
| **7 天焦点币** | 7 天检查点时组内储备最高者 |
| **焦点是否在入场后换手** | 入场时焦点币 ≠ 7 天焦点币 |
| 入场焦点币的创建次序 | 是否为组内最早 |
| 入场焦点币 +30 分钟之后的最高倍数、到达最高价的检查点 | 面板 11 个检查点；7 天后用 `ms_30d` 补充 |
| 入场容量 | +30 分钟储备按 5% 价格冲击折算美元（F56 口径） |
| **事后时间窗（乐观）** | 入场焦点币 +30 分钟后最高倍数 ≥2，**且**注意力峰值日不早于该币创建日 |
| **同日不可辨** | 注意力峰值日等于创建日，且无法用微博提交时间分出先后（日度数据看不出注意力是在发币之前还是之后爆发） |

5. **覆盖与上限**（描述，使用已看过的标签）：A、B 两周事后 ≥10× 的币中，能锚定到事件的占比；这些币在 `b50` 下的盈利占全部赢家盈利的比例。
6. **经济包络**（按背景.md 口径：任一时点累计净收益 ≥100 万元，主要靠极端右尾跃迁）：
   - 对每个落在事后时间窗内的焦点币 i：Pᵢ = Cᵢ × (Rᵢ − 1)，其中 Cᵢ 为该币入场容量（美元），Rᵢ 为 `b50` 净回收（事后挑选，**乐观**），**保留逐币的容量与收益相关性，不取中位数**；
   - **累积路径上限** = 抽样事件的 ΣPᵢ ÷ 抽样比例 ÷ 观察周数 × 52，与每年约 33.3 万元比较；
   - **单次跃迁上限** = maxᵢ Pᵢ，即 Cᵢ(Rᵢ − 1)，与 100 万元比较；
   - **可验证性** = 4 个封存周内预计出现的合格焦点币数（按抽样比例折算）。

## 四、判定（冻结于运行前）

| 结果 | 动作 |
|---|---|
| 只算明确落在时间窗内的事件，累积路径上限与单次跃迁上限**都**达不到目标；**且**把"同日不可辨"事件全部当作有时间窗也达不到 | **KILL**：关闭 pump 上的注意力路线；是否用同一审计看 BSC 或更大市值的币，另行裁决 |
| 只算明确事件达不到，但算上"同日不可辨"事件能达到 | **历史数据无法判断**：不进入 R1；是否开前向采集（逐小时抓取注意力），另行裁决 |
| 只算明确落在时间窗内的事件，至少一个上限达到目标 | **进入 R1 开发** |
| 可验证性 <10 | 不影响进入 R1，但 R1 通过后不开封存周，改为前向纸面采集确认 |

**映射结果只决定 R1 的信号形式，不作为淘汰依据**：
- 在事后时间窗事件中，焦点在入场后换手的占比 ≤1/3：R1 只测"焦点币上的注意力"，原创性只作诊断（入场时它已体现在公开储备里）；
- 占比 >1/3：R1 加入"注意力 × 原创性/权威性"变体。

**R1 预告**（本卡不执行）：
- A、B 两周均为开发样本，事先列出不超过 3 个信号定义；
- 主估计量为每个机会的净回收（扣 0.004），同时报告到达率、容量、持有时长、并发资金与前 1/5/10 个币的盈利集中度；
- 不剔除尾部；先做功效计算，再决定开封存周还是前向采集。

## 五、预算与分工

- 主动工时 ≤5 小时；Dune ≤10 credits（创建事件名称，用户运行）；Helius 约 30 次批量调用 + ≤300 次签名查询；
- 名称匹配核对、事件类型标注交给便宜模型，执行端抽查 10%；
- 包络计算、判定、报告由执行端完成。

## 六、不能推出

- 任何可实现收益：包络全部基于事后挑选，只能用于淘汰；
- 小时以内的领先关系：数据粒度为日度或 3–6 小时；
- BSC 与中文币的情况（本卡以 pump 为主）；
- 注意力之外其他信息类别的价值。
