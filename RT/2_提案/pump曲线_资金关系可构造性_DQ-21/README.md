# DQ-21 提案 R0：资金关系信号的可构造性审计（不看收益）

> **状态：提案 v1（2026-09-27，待用户裁决），没有产生任何数据**｜起草：Claude（上位模型）｜依据：F101（点火由创建者或其关联钱包群发起）、F113（履历与构成两层已测、不通过）、09-27 外部复核建议的三段式（R0 可构造性 → R1 开发期经济检验 → R2 封存确认）｜现状以[总入口](../../00_总入口.md)为准

## 1. 问什么

在拟定的决策时刻之前，能否用**当时已经存在**的链上关系，重建创建者、早期买家、付款人与资金来源之间的关系？覆盖率、公共节点污染和实时成本各是多少？

**本段不看任何收益**，只决定“资金关系信号能不能做出来”。

## 2. 按总入口 §6 第 5 条

| 项 | 内容 |
|---|---|
| 新证据 | F101：3 个赢家中 2 个的点火由创建者本人，或与创建者同属一个代币转移连通分量的钱包群发起。F113：钱包履历与买家构成两层已测，均不通过。资金关系层尚未测 |
| 与已失败实现的差异 | DQ-10M 做的是完整实体聚类（成本超 Helius 额度），F88 用的是币内协同代理；本卡只重建“决策时刻之前”的直接资金边与代付边，先测能否做出来、成本多少 |
| 首测成本上限 | Dune ≤10 credits（样本币的早买名单）；Helius ≤100,000 credits（按 F101 的实测，每次调用约 10 credits 保守估计，约 1 万次调用）；≤1 周 |
| 正负结果改变什么 | **能做出来**：写 R1，只冻结一个主关系信号（最多加一个反向对照），在 A、B 两周作为开发集做经济检验。A、B 都已打开多次，B 周不算独立验证，确认只能用封存周（R2）。**做不出来**（覆盖太低、被公共节点主导、实时成本过高、只能靠事后完整实体图）：停止这一实现，不扩展到全实体聚类，转机器版 DQ-6 |
| 为何优于其他选项 | 链上信息里只剩这一层有具体机制线索（F101）；复用 Solana 数据与既有估值；机器版 DQ-6 要为 BSC 新建管线，而且还没有证据说明我们在那里有不同的信息位置 |

## 3. 设计

- **样本**：A、B 两周 F3 面板中 100 个币。
  - 40 个随机；30 个入场后 30 天 ≥10× 的币；30 个按 F3 入场状态近邻匹配、但没到 10× 的币。
  - 结果标签**只用于分层抽样**，保证赢家和失败币都覆盖，本段不比较两组的关系多寡（那是 R1 的事）。
- **对象**：每个币的创建者，以及全部早买者（创建后 30 分钟内、≥0.1 SOL、非创建者）。早买名单用一条 Dune 小查询取得（VALUES 传入 100 个币）。
- **关系边，只取决策时刻之前的**：
  - 对每个钱包，从它在该币的首笔买入往前翻签名（每页 100 条，最多 3 页），记录买入前 7 天内收到 SOL 的来源（出资方）、时间与金额，以及钱包的首笔交易时间（若在翻到的范围内）；
  - 另记录买入交易的付费方与签名者；
  - 在同一窗口内，记录创建者与早买者之间的直接 SOL 或代币往来。
  - 决策时刻之后发生的转账、事后生成的标签、事后聚类结果，一律不回填。
- **公共节点识别**（先写定）：
  - 在样本中为 ≥20 个不同钱包出资、横跨 ≥5 个币的出资方，记为“疑似公共节点”，例如交易所热钱包、交易终端、中继；
  - 付费方同理；
  - 另报临时 wSOL 账户关闭、第三方代付造成的漏边个数。

## 4. 报告与通过条件（写定，不看收益）

**报告**：
- 早买者中能解析出至少一个买入前出资方的比例（总体，以及按样本分层）；
- 每个钱包平均用了多少次调用；
- 出资方里疑似公共节点的占比；
- 有 ≥2 个早买者共享同一非公共出资方的币占比；
- 创建者与早买者之间有买入前直接往来的币占比；
- “出资 → 买入”的时间间隔分布；
- 每个币的重建成本（调用次数）与所需时间。

**进入 R1 的条件**（全部满足）：
1. 早买者出资方可解析比例 ≥70%；
2. 已解析的出资方中，疑似公共节点占比 ≤50%，否则“共同出资”主要来自公共服务，不携带协同信息；
3. 单个币在实时决策中的重建成本 ≤200 次调用，按 30 分钟决策窗计可以完成；
4. 可解析的关系在决策时刻之前就已存在，不依赖事后完整实体图。

不满足即停止这一实现（见 §2）。

## 5. 不做什么

- 不做收益检验；不开封存周；不做全历史实体聚类。
- 不把 F101 的 3 个案例当样本主体，它们只作字段核对。
