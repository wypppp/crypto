# 2026-09-29 研究方式重构与用户决定

> 本文件记录当时的理由，**不是当前指令**。现行决定只以[总入口](../00_总入口.md) §0、§3.1 为准。

## 1. 为什么重构

09-28 前后，项目开始从交易研究转向讨论“怎么研究”（Research OS、多 agent、MCP 等）。本轮用一次受约束的元评审回答：**最少需要改变什么**，然后停止。

## 2. 怎么做的

- **两条独立路线**：Clean-room（不看旧项目，从零设计）与 Legacy-aware 法证审计（对 snapshot `37f1a295` 核验）。每条路线各由两个模型独立完成，互不回应。
- **一份差异综合**：综合期间收到另一模型的综合和三轮外部评价，经批判性吸收后定稿。
- **原始材料**：见 [3_审计/2026-09-29_研究方式重构/](../3_审计/2026-09-29_研究方式重构/)。

## 3. 主要发现（限定范围）

- 旧项目缺的不是 Research OS。规则多数早已写入研究方法，故障发生在执行点：取数、复用、结论升级、修订同步。
- 缺一层研究资源分配：下一步常因“已在队列”而定，没有和其他候选比较。
- 06-15～07-12 封存窗不能认证为干净；开发周已被多条路线复用。
- 所有综合与评价都是同一组输入上的 LLM 产物，彼此一致不增加证据。

## 4. 决定（用户 09-29）

- **采用触发式规则**：02_研究方法 §10，与场所无关。当前 pump 口径写在 DQ-21 程序契约。
- **组合门**：S1 A/B 之后比较候选池，用户裁决唯一活跃信息族。R1a v2 是候选之一。
- **确认**：T1 日历批次；06-15～07-12 为 T3。
- **第二模型**：三道门加一个语义例外；语义例外以原件病例追溯为主。
- **程序停止**：证据耗尽或资源耗尽；不宣称领域被证伪。
- **U1**：额度充足，运行 S1 A/B。**U2**：继续 Dune + Helius；Dune 付费 SQL 由用户网页运行。**U3**：旧 key 已无用，不撤销；repo 保持 public。**U4**：T1。**U5**：过渡期约束至 10-16，10-16 定程序资源上限。**U6**：接受纯统计 edge，不要求因果解释。
- **执行分工**：默认一个执行模型（当前 Claude Code）。
- **进入确认的准入顺序**：开发正结果 → 账户级确定性上界 → 承重执行假设实测 → 第二模型 → T1。账户上界比目标低一个数量级的，标为“组合成分，非主引擎”，由用户决定是否消耗批次。评分器输出事先登记的市场状态描述量，只作诊断。
- **工具**：Dune 官方 MCP 先冒烟，通过则采用、不通过则回退网页手动执行；Helius 官方 MCP/插件不装（含交易发送与密钥生成能力）；不新增自定义 skill；不用自动实验循环类工具搜索交易规则。
- **退役**：DOMAIN_LEGACY 不再维护。

## 5. 明确不做

多 agent 编排、自动互审、自建 MCP、向量库、知识图谱、benchmark、实验追踪平台、仪表盘、通用回测引擎、工时硬停、固定数量的搜索上限、每卡强制多重检验统计、独立的“组合重置”阶段、候选专属确认窗口。
