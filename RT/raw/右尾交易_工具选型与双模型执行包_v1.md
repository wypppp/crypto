**对另一模型收益引擎定义的必要修正。** 遍历未来退出时点后选择最高回收倍数，得到的是指定时点网格、状态与成本假设下的事后机会标签：

\[
M^*(Q,T)=\max_{t\in\mathcal T} M(Q,T,t).
\]

它可以用于研究右尾是否出现、哪个筛选误删赢家；策略收益必须另用事前定义、仅依赖届时可见信息的退出规则计算：

\[
M_\pi(Q,T)=M(Q,T,\tau_\pi).
\]

例如买入后从 1 涨到 10 再回到 1，事后最高为 10，固定末期退出只有 1。即便每个历史时点的执行估计都正确，也不能把未来最优退出直接计入账户。若仿真状态或费用不完整，M* 还只是条件性估计，不能无条件称为“可兑现上界”。机会标签与策略结果都值得保留，用途不同。

报价、可构造交易、模拟成功与真实成交分别记录。Jupiter 当前 Swap V2 官方文档明确：未提供 taker 时 transaction 为 null；可报价但无法构造交易时为 empty string（""），同时核对 router/errorCode。非空交易也不能证明后续执行、确认和结算成功。旧 Swap V1 文档已经标为不再主动维护。[V2 订单语义](https://developers.jup.ag/docs/swap/order-and-execute)、[旧 V1 文档](https://developers.jup.ag/docs/api-reference/swap/v1/quote)

Surfpool 的按需远程账户克隆和时间推进适合执行测试，但不会自动重建过去某时点的所有账户、程序与后续状态。分别取历史买入和历史卖出时点执行，也不自动保存钱包持仓产生的影响。当前必须写出可取得的状态、如何连续处理持仓以及对其他交易不变的假设；缺失部分报告为未测，不能用价格路径替代。[Surfpool 参考](https://github.com/solana-foundation/solana-dev-skill/blob/main/skills/solana-dev/references/surfpool/overview.md)、[Solana 模拟接口](https://solana.com/docs/rpc/http/simulatetransaction)

**两个模型围绕同一工作单协作。**

| 时点 | Claude Code | Codex | 用户 |
|---|---|---|---|
| 开工前 | 提出最短取证路径与需要的新代码 | 从原问题独立列出关键反例、验收证据；检查工具语义 | 只裁决必要的目标或资源变化 |
| 实现 | 唯一主写入者，运行并保存证据 | 对决定性的样本独立复算；默认只读 | 不搬运重复摘要 |
| 交接 | 固定代码版本、规格、命令、原始结果、成本、已知限制 | 一次集中列出影响当前结论的问题 | 查看结论与需要裁决的分歧 |
| 修复与结束 | 集中修复并运行受影响的检查 | 核实缺陷是否关闭及是否出现相关回归 | 根据有范围的结果选择下一投入 |

同源数据独立重算属于计算复核，不标成独立信源。审阅意见须包含影响、最小反例或缺失证据、解决方法与验收方法。架构偏好不单独构成阻断。建议预留两轮集中修复；超过预算仍有关键错误，停止该工作包并报告未解决状态，不能为结束评审降低正确性标准。

审阅固定到代码提交和输入版本，不一边审一边追着实现者的工作目录变化。Codex 先从有效约束和原始证据独立写出关键判断，再看实现与设计理由；减少结论锚定，但不删去用户裁决、已关闭问题和必要历史。实现者仍需自测，独立验收在此之上增加证据。默认不每个任务交换两模型角色，也不让两者分别重写整套方案；只有小而承重的计算值得独立实现比较。

有并行写文件、运行会生成产物的审阅或独立小实现时，可用独立 worktree/固定提交检出；单纯只读审阅不强制新建。worktree 隔离源文件，不自动隔离数据库、端口、原始数据或 API 额度，运行产物用各自目录。[Git worktree](https://git-scm.com/docs/git-worktree)

功能正确、观察到的经济结果、用户是否投入真实资本是三种不同决定。不设伪精确的最低成功概率；实盘由用户结合已知证据、预算和明确风险裁量，且需要实际授权。

**三类自动化不能过度承诺。**

- Hook 只在它实际覆盖的事件、配置与执行环境里起作用。Claude 的 Hook 不自动约束 Codex；异步 Hook 不能阻止已经发生的动作。Stop 检查还需防止无解条件造成反复续跑。采用“阻止未验证结果被标为通过、允许以失败/阻塞状态结束”，而非检查一失败就永远不准结束。[Claude Hooks 文档](https://code.claude.com/docs/en/hooks)
- Schema 能检查类型与已定义的关系，不能独立发现两个同类型时间字段在源头被交换；先定义事件发生、首次可得、实际观察和决策时间，再写关系式。Hypothesis 的不变量也需限定场景：提高费率若同时改变路由或成交选择，未必构成可直接比较的同一反事实。固定输入、路径和适用域后再检查。
- “已搜索=true”、测试数量、覆盖率或字节完全一致都不能单独证明研究正确。复跑优先比规范化事件、金额和状态；运行时间、日志顺序等非经济字段不必逐字节相等。来源、版本、样本范围与可复算结果比一个通过数字更重要。

**进一步提效：先缩短从问题到证据的距离。** 以下是管理建议，不是额外统计闸门：

1. **让每项工作对应一个决定。** 开工写明：结果 A/B 各会改变哪项选择。优先找最便宜的决定性证据，可能是一条官方说明、一个已有 SQL、一个失败样本或一次付费数据取样；不默认写程序。数据付费时先明确需要的字段、时间范围与样本用途，再比较采购与自建总成本。
2. **限制同时推进的经济问题。** 默认一个主实验在做，独立案头查证可并行。不为了复用价值把每个实现扩成平台；每个工作包先交一条真实数据贯通的结果，再决定是否批量化。
3. **增量复核，按影响使证据失效。** 记录本次改了什么、影响哪些结论。仅改报告格式通常不重采；费率语义改变重算受影响交易和账户，不自动重建母体；母体纳入规则改变则重新检查分母和下游比较。依赖判断先用表述完成，不为此先建工作流引擎。
4. **让模型争论落到可执行反例。** 审阅者提出具体触发条件、影响及最小复核；实现者修根因并保留反例。遇到需要新实验才能解决的方法分歧，作为单独决策处理，避免无限混入当前代码修复。
5. **一次抓取，多次解释。** 对已取得且可留存的原始数据按版本保存，重跑解码与分析优先读同一输入；采集失败登记并定点补齐。实际前向观察时间不能伪造成历史已知，也不能把缓存当作永远有效的当前状态。
6. **记录少量真实效率结果。** 每个工作包记录到首个有效证据的用时、修复轮数、数据/运行用量和最终改变的决定。一个新增工具只有减少这些负担才值得保留；仓库数量、代码行数、agent 数量和厂商速度倍数不是项目进度。

**个人 skill 的落地裁决。** 值得沉淀一个薄的项目 skill。第一工作包即可共用本文件的稳定规则，边执行边删掉无效要求，随后固化；不需要为写提示词再先建一个平台。本次提供的是内容规范，尚未创建或安装 skill，也未修改两个客户端的全局指令。
