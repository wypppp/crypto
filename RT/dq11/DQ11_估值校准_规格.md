## 0. 这张卡怎样通向百万净收益

它只为具体候选的经济判断界定误差。初筛可以用费用范围、容量线索和未知项排序；接近确认门槛时才补足会翻转判断的测量。pump 的 0.5 SOL 成本不能未经检验迁移为其他场所、金额和执行方式的成本。当前没有使用这套执行方式的在途候选时，本卡保留规格，不为使数字更精确而付费。

## 1. 决策分叉（开工门槛）

| 结果 | 我们做什么不同的事 |
|---|---|
| **带方向的测量误差区间不跨候选判定边界** | 就该误差项而言，决定稳健；不继续为提高精度付费。统计不确定性仍单独处理 |
| **误差区间跨边界，且补测能改变行动** | 只校准该项，写出两种结果对应的行动与适用人群／金额 |
| **仅漏计非负成本，原回收已低于 1** | 补成本只会降低回收；不能以误差超过 2pp 为由作废负结果。其他可正可负的估值错误另审 |
| **测不出或不是同一执行对象** | 标未知；不得自动降级为“相对比较可信”，候选与对照的测量偏差也可能不同 |

原 0.5pp／2pp 分档作废：0.4pp 可以把 1.003 变为 0.999，3pp 漏计成本却不会把 0.974 变成通过。门槛须与具体决定的余量及误差方向相联系。

## 2. 冻结指标契约

被校准的对象固定为：**pump.fun 曲线阶段，创建后 +30 分钟入场，0.5 SOL，`b50`/`x50_24h`/`x50_1h` 退出族，逐币一行，分母 = 被选中的实际交易笔数（不含"跳过=现金"口径）**。
- 决策时点：入场为创建后 1800 秒的首个可成交事件；退出为规则首次触发行。
- 不可得值：无后续状态者按入场费率折算（沿用 `build_f1.py` 头部口径）。
- 并列阈值：同秒多行按 `(ts, venue, slot, tx_index, outer_instruction_index, inner_instruction_index)`（F81 修复后）。
- 成本版本：双边费率按入场时曲线费率；固定成本 0.002 SOL/往返。
- **任何一项变更都要重列受影响的既有判定。**

## 7. T1a 结果（2026-09-20，0 credits，已完成）

**做法**：Dune 只读账户取不到表目录（`/api/v1/table/...` 与 `/api/v1/usage` 的 GET 均返回 HTTP 405），改用 Dune 官方文档核对，并用项目已有 SQL 与探针 CSV 核对连接键。

| 问题 | 结论 |
|---|---|
| 优先费能否取到 | **能（间接）。**`solana.transactions` 有 `fee`（BIGINT，lamports，**总交易费，含优先费**），**没有**独立的 `compute_unit_price` 列。Solana 基础费 5000 lamports/签名，故优先费 = `fee − 5000×签名数` |
| 失败标志 | **有。**`solana.transactions.success`（BOOLEAN）；`solana.instruction_calls.tx_success`（BOOLEAN，"父交易是否成功"） |
| 连接键 | **有。**pump 事件表含 `evt_tx_id`、`evt_tx_signer`（见 `dune_entity_pump_trade_probe.csv` 第 12–13 列），可连 `solana.transactions.id`/`signature` |
| 计算单元 | `compute_units_consumed`（BIGINT）有 |
| 分区/成本 | **文档未说明。**项目已有 SQL 全部按 `evt_block_date` 过滤，`solana.instruction_calls` 与 `solana.transactions` 均有 `block_date`，据此设计扫描边界 |

### 一个会毁掉 E2 的坑（已识别，未解决）

**成交事件不能提供完整的交易尝试分母。**但“失败交易不发出事件”也不正确：本地 F60 已记录一笔发出 SellEvent 后整笔失败的交易；该笔被 Dune 解码事件表过滤。过滤行为不能从一例推广至所有时期和表。

正确方向是 `solana.instruction_calls` + `executing_account = '6EF8rrecthR5Dkzon8Nwu78hRvfCKubJ14M5uBEwF6P'`，按 `tx_success` 分组。**但 Dune 文档只说 `tx_success` 是"父交易是否成功"，没有明说失败交易是否入表。**该列存在本身暗示入表（否则恒为 true 无意义），但这是推断，不是证据。

**单小时未见失败，只能说明该筛选下未见失败。**验证收录应使用已知失败交易作阳性对照。即使查到，也不能证明表包含未上链订单或到达目标程序之前失败的全部尝试。
