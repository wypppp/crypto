# RT-W00 / RT-W01 执行清单与复用矩阵 v0.3

日期：2026-09-14。性质：经用户认可的当前执行规范；在 v0.3 内做字段级修订，不新增阶段。合并用户提供的 v0.1 执行清单、v0.2 Reuse-First 矩阵及反思形成的执行稿，供 Claude Code 与 Codex 接手；不代表任何实验已经执行或通过。每项承重任务同时规定默认工具路径、仅需补写的缺口和验收证据。W01 的链、协议、金额与时间窗口尚未冻结；W00 以各次运行规格声明工程探针范围，不自动冻结 W01。原附件保留为审阅来源。

本清单负责 W00/W01 的具体执行约定；《右尾交易：工具选型与双模型执行包》保留目标、工具比较与协作原则。研究目标与资金约束沿用用户有效约定，不把旧 ETH V2 配置自动继承为全局范围。本次没有实盘下单授权。

**本次裁决。** 接受 W00 测量可行性与 W01 研究切片的区分。一个固定金额、固定退出规则的系统性研究本身可以是研究 MVP；真正需要补齐的是取样、分母、随访与推断范围，不是增加更多规则。W00/W01 是当前两张任务单，不建立所有方向必须依次通过的永久闸门。

**共同口径：对象、样本与证据。**

- `object_id` 标识链上的对象；`opportunity_id` 标识冻结的经济机会单位；`record_id` 标识一次测量或原始记录。多池/迁移是否同一机会由规格决定，不一律合并，也不一律当独立样本。
- `run_role`：`engineering_fixture`、`research_slice`、`api_smoke`、`independent_review`。这是运行用途，不能作为币地址的永久属性。
- `membership_status`：`eligible`、`ineligible`、`unresolved`。与结果是否可测分开。
- `prior_exposure` 记录已看过哪些结果、何时查看、是否影响了规则。已看过的数据可以描述和开发，不能重新包装成未查看的确认样本。
- `analysis_role`：`development / descriptive / confirmatory`，绑定具体分析及规则版本；与 run_role、membership_status、prior_exposure 分开。确认性用途须有事前规则与数据隔离依据，不能仅靠填写 confirmatory 成立。
- `capital_scope / entry_Q / currency` 绑定投入单位、总预算与费用是否包含在 Q；原币整数数量与 decimals 留存。结论限定为该 Q 下的 M*(Q)、Mπ(Q)，不外推其他金额；人民币换算另带日期与来源。
- 每个测量节点保存 `execution_venue / venue_version` 及池/程序地址、状态时点和证据；版本未知明写未知。跨迁移按当时实际场所取证，不能只填机会最初的协议名称。
- `data_mode`：历史观测/历史仿真/前向 shadow/真实交易/合成测试，逐项保留来源；这些方式不是从低到高的单一等级。
- `execution_check_status` 按入场/每次退出、各检查步骤分别记录 quote、build、simulation、submission、landing、finality 的检查状态及证据。检查结果用 `PASS/FAIL/UNRUN/NOT_APPLICABLE`；没有执行的步骤不推定通过。
- 每个结果量单独有 `measurement_status`：`known`、`interval`、`unknown`、`censored`、`not_applicable`。独立的 `economic_status` 记录该规则下的经济事件（如 not_entered、entered、partially_exited、fully_exited、exit_failed、undetermined），不代替损益金额；一个事件可以有多次尝试，需绑定节点/尝试。`exit_failed` 须有足以归因于交易条件的证据；RPC 超时仅形成测量未知和错误原因，不能推定卖不掉。三类字段分别赋值，不以检查 FAIL 自动推出经济失败或资产归零。

`run_manifest.json` 是证据索引，不是正确性证明。运行完成、工程验收、经济发现分开记录；进程退出 0 只说明该进程按它的语义成功结束。

**复用裁决：实施选择必须跟着任务走。**

默认先查当前任务相关资产，然后针对明确缺口查最贴切的官方或第三方能力；不规定所有任务都走完“官方 SDK→RPC→第三方”的阶梯。直接使用、薄适配、定点修改、有限自研，按接入、验证、数据、维护和许可证的总成本比较。比较可以依据文档或源码，不要求为了证明不合适先部署或付费实测。

新增承重模块只需在工作单记一行：`任务 → 选择的组件/已有代码 → 直接用或需补的具体语义 → 选择依据与总成本判断 → 验收证据`。现有记录有效时引用，不重复全网检索。修一个错误、写一条 SQL 或几个字段映射不需要重新走选型审批；更换采集器、执行运行时、账户引擎才值得明确比较替代方案。不设代码行数目标，不要求穷尽所有工具。

**工具搜索停止规则。** 已找到满足必要能力、预算与许可证无已知阻断的方案，且当前有界比较内没有已知替代方案会改变决定时，停止搜索并进入验证/实施。记录判断依据及仍未验证的假设；这不是全市场最优证明。只有实际出现具体缺口或足以改变决定的新证据才重开，不因可以再找到一个项目而延长。

| 后续按需：账户时序与资金路径 | 优先复用已有相容账本/回放；简单现金流水用 SQL 排序与累计，内生的占资/拒单决策才用事件循环或相容框架 | 注资、并发、blocked、部分退出无法由现有政策表达 | 只补政策或必要循环；不预先宣告通用回测框架都不适用 | 时间有序流水、三条资金政策、费用、未用资金、blocked、对账；模型账户与真实账户分开 |

矩阵中的默认项是当前工程判断，不是已部署或已通过的声明；具体 Dune 协议表、服务套餐权限及历史状态覆盖仍须对目标问题确认。没有必要为每一行安装一个新工具。

| 项目 | 可执行要求 |

| 独立复核 | Codex 从固定输入复算一个会改变当前判断的事件或金额，并核对最关键的状态假设；小型独立实现仅在有帮助时采用 |

**W00 的结束与下一步。**

| 结论 | 条件 | 下一步 |
|---|---|---|
| `VERIFIED_WITHIN_SCOPE` | 声明目标和承重假设有证据支持，所测金额或失败事件可复算 | 对照 W01 所需能力，仅补新缺口 |
| `BLOCKED` | 缺权限、数据、状态或资源，尚不能判断目标结果 | 交付缺口、证据、影响、最便宜替代路径；可结束任务 |
| `INVALID_METHOD` | 实现错误、口径矛盾或反例推翻了当前测量办法 | 修根因或更换办法；不扩大该办法的正式运行 |

“已确认该笔买入被拒绝”可以是正确测得的结果；“SDK 不会构造正确交易”是技术问题；“RPC 超时所以不知道能否卖出”是测量未知。三者不能混用。

若历史持仓状态不足，前向测量是候选替代方案，不是自动通过。前向 shadow 需要记录虚拟仓位如何延续、如何取状态、对自身冲击和其他交易不变作了什么假设；它仍然不能验证真实广播、打包及真实钱包特有的全部限制。不能以“把时间改成现在”绕开同一测量缺口。

**W01：冻结的研究切片。**

| 项目 | 可执行要求 |
|---|---|
| 目标 | 在一个有界、明确的候选集合中，描述条件性右尾机会、固定规则回收分布、不可执行与未知情况，决定下一笔研究投入 |
| 前置证据 | 所选测量办法有与本次范围相容的 W00 或既有证据。单例通过不是全母体通过；新增代币行为、版本或迁移路径继续标注覆盖缺口 |
| 冻结输入 | 机制/协议/阶段；机会单位；窗口及边界包含规则；母体来源；纳入/排除规则；金额；入场、退出、重试和持有规则；随访截止；费用；状态假设；M* 搜索定义与预算；缺失政策 |
| 候选登记 | 默认选择预算内的小窗口，系统登记全部满足条件的候选；纳入不依赖未来结果。平台可见集合须如此命名，不外推全链发行 |
| 测量 | 分别产生 Mπ 与 M* 的值、区间或未知状态；每个合格候选保留一行，不因失败/数据缺失删除 |
| 输出 | 原始输入索引；候选及归属表；结果表；覆盖与费用汇总；manifest；独立复核；有范围的结论 |
| 工程验收 | 冻结边界与输入可复算；没有静默遗漏；身份/金额/时间/状态的承重问题已修复或明确限制了主张；非成功结果同样被记录 |
| 研究结论 | 仅描述该切片和测量模型，不据一次未命中判死整个方向，不给未经支持的三年达标概率 |

若全量测量超预算，可以在看结果前缩小窗口，或另行声明概率抽样设计并保留抽样概率与总体信息。不能改成手挑数据丰富者、只测存活者。系统枚举与对每个候选完成所有计算是两件事。

需要保留不可事后补取的可见性信息时，可在 W00 期间开展有明确范围、预算的只读登记；经济结论仍等待对应测量验证。记录登记范围何时冻结、哪些数据已经被查看，不能把事后改过的规则称为预注册。避免把测量验收变成阻止保存易失证据的理由。

冻结的是退出政策 π，不要求入场时知道未来实际退出时间 τπ。若政策会分批卖出，必须连续更新余仓、费用及成本基础；不能把各时点都卖出完整原仓位后再累加收入。

开始统计前冻结窗口，随访可以按事先规定延续至窗口结束加持有期。不得看见结果后为等到赢家而延长；发生资源中断则报告删失与实际覆盖，不偷改既定期限。

**收益量如何落表。**

- `M_pi`：冻结退出政策得到的同口径回收倍数。必须绑定金额、计价、现金流、状态假设与证据类型。历史仿真/前向 shadow 结果只进入相应的模型结果表，不能记为真实已实现利润。
- `M_star`：在预先声明的退出时点集合及允许的退出方式中求事后最大值。每个备选退出是同一次入场后独立的反事实分支；不是在同一条仓位路径上重复卖光。它不自动覆盖连续时间最高点、其他退出方式或真实介入后的全部路径。
- M* 搜索节点缺失时，`observed_max` 不能当精确最大值。保存 `lower/upper` 与缺失范围；没有依据的上界为未知。已验证节点足以支持某阈值命中时可以标是；要标否，需要在声明范围内有足够的未命中证据，否则标未知。
- Mπ 与 M* 可以有不同的完成状态。M* 的未识别不得使已正确测得的 Mπ 消失；也不得让 Mπ 已算出掩盖右尾机会仍未识别。
- `hit_star_100x` 与 `hit_pi_100x` 分列，10×/50×同理。阈值是回收倍数，不能与“上涨 100%”混用；阈值集合预先登记。

成本与残值至少明确：请求投入、实际支出、未动用现金、卖出回款、剩余资产数量、已经扣除的费用、额外费用、估值方法。费用只扣一次。买入失败时未动用本金仍是现金，不能把整个计划仓位记为归零；若没有建仓，持仓倍数可以不适用，但尝试的现金损益和费用仍须记录。部分卖出不代表余仓已实现；卖不掉也不自动证明永久价值为零。

“成功建仓后的持仓倍数分布”与“全部候选的可参与右尾事件率”分开报告分母。已证明按冻结入场规则无法参与的候选，在后者中计未命中；因端点或状态缺失尚不能判断是否可参与的候选计未知。两者的尝试费用与资金占用都不从账户记录中消失。

**分母、污染与未知值的处理。**

| 情况 | 登记与统计处理 |
|---|---|
| 手挑工程运行或根据已知涨幅挑来的测试记录 | 不直接拼接为 W01 研究观测，不估计发生率 |
| 同一真实对象恰好也属于 W01 冻结母体 | 保留对象在分母；按冻结测量规则形成研究记录；标 `prior_exposure`，不称未查看确认样本 |
| 人工合成、mock、devnet/localnet 数据 | 不作为真实母体经济观测；可以验证实现 |
| 主网真实对象曾用于教程或 SDK 示例 | 示例身份不是永久排除理由；是否属于母体按冻结规则判断，避免直接采用示例输出作为研究结果 |
| 母体外事后追加的赢家 | 不纳入该母体分母，只能作为另行标记的开发或个案证据 |
| 身份、协议版本或资格尚未识别 | 保留待识别集合与数量，不能当成已证实不合格后删除 |
| 合格但不可构造/无法退出/消失/缺数据/未随访完 | 仍在合格母体；交易结果、测量错误、未知、删失分别记录 |
| 重复原始事件 | 保留原始记录，建立映射；一个冻结机会只计一次。关联但不同机会不假装独立 |
| 首次可见时间缺失 | 留在母体与缺失统计，不用于“当时可识别”点估计；必要时给时间区间或缩小主张 |

例：冻结母体 100 个，其中 1 个大赢家曾用于 W00。研究分母仍是 100，不能以“工程用过”为由变成 99；但若规则受该赢家启发，这批资料只能承担相应开发/描述用途，规则确认另用未查看资料。

当母体归属与枚举完整已成立，N 个候选中 H 个确认超过阈值、U 个尚不能判断时，该冻结集合的发生比例可保守报告为 `[H/N, (H+U)/N]`。这不是未来概率置信区间。若还存在归属未识别或采集缺口，应另报数量及其影响，不能把它们隐藏在这个 N 之外宣称全母体发生率。

不使用 `PASS-NO-RIGHT-TAIL` 推导全方向无右尾。结论写为“在该窗口、金额、时点网格、测量假设与可判断记录中未观察到阈值事件”；存在关键未知时连整个切片零发生也不能断言。

**fixture replay、live smoke 与运行隔离。**

- Fixture replay 读固定输入，检查既有逻辑；live smoke 少量调用当前端点，检查访问、返回结构、版本与用量。二者分别运行、分别记录，不互相替代；smoke 记录不直接混进研究结果。
- Live smoke 在此仅指获授权的只读查询/适用仿真，不包含签名广播或真实下单。Jupiter `transaction=null`（未提供 taker）与 `transaction=""`（可报价但无法构造）分开保存，连同请求是否提供 taker、router/errorCode；非空交易也不是已成交。[官方字段说明](https://developers.jup.ag/docs/swap/order-and-execute)
- 每次用唯一 RUN_ID，输出到 `artifacts/<run_id>/`；Codex 审阅使用新 run_id 并引用原 run。临时 DB、会写入的缓存与测试输出独立；不可变原始数据可以只读共享，不要求复制全量数据。
- 同源数据独立重算是计算复核。抽查另一数据路径时说明底层来源；行数相等或几个样本一致不能单独证明全量完整。
