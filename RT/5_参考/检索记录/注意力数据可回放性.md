## 1. 微博热搜历史存档

`justjavac/weibo-trending-hot-search` 明确写“从 2020-11-24 开始、每小时抓取一次、按天归档”，2026 年页面仍显示当日热搜，因此**2026-05～09 至少存在持续更新证据**。但当前类型定义只有 `title` 与 `url`，抓取代码把当天结果合并写入单个 JSON，并未给每个小时快照加独立采集时间，也未保存热度值，所以更适合回答“某词当天是否曾上榜”，不宜直接当作精确小时级强度序列。来源：https://github.com/justjavac/weibo-trending-hot-search 、https://github.com/justjavac/weibo-trending-hot-search/blob/master/types.ts 、https://github.com/justjavac/weibo-trending-hot-search/blob/master/main.ts

另有 `v5tech/weibo-trending-hot-search`，页面样例明确带热度数值（例如标题后跟 798707），并显示“最后更新时间 2026-05-28 07:24:02”；它对热度建模更有吸引力，但检索未确认 5 月 28 日之后是否仍持续更新。来源：https://github.com/v5tech/weibo-trending-hot-search

GitHub 最近一次提交日期：上述仓库的 GitHub 页面在本检索环境里“Latest commit / Last commit date”栏没有渲染具体日期，因此**未确认**，不以 README 的“更新时间”冒充 commit date。

## 3. 百度指数

官方帮助确认：登录百度指数后，可输入关键词，在“指数趋势”里按自定义时间段与地域查询搜索指数/资讯指数/媒体指数，搜索指数可分整体/移动端；“指数概览”给出所选时间段的日平均值。页面明确有登录/注册，2026 年首页还出现“API加词功能，150元立即体验”的入口。来源：https://index.baidu.com/Helper/?usg=AOvVaw0EHg3eC6GKm6HiTcZufdym 、https://index.baidu.com/v2/

历史研究和第三方工具长期能获取 2011 年以来的**日度**百度指数；非官方包通常需要从已登录百度指数网页取得 Cookie，再调用内部接口。对于“任意关键词、2026-05～09 日度回放”，可行性高；但本轮没有找到百度官方文档证明普通百度指数支持任意历史日期的**小时级**关键词指数，因此该项标“未确认”。第三方示例：https://pypi.org/project/PPshare/0.1.3/

## 4. Google Trends

Google 官方 2026 帮助页明确：Explore 里，7 天或更短的范围通常对应小时等亚日粒度；30 天或更长使用 UTC，粒度为日/周/月。经典公开规则（RBA 2022，引用 Google）是：<7 天小时、7 天～<9个月日、9个月～<5年周、≥5年月；这说明**真正的小时级历史只在最近约 7 天**，不能在 2026-09 回头拿 2026-05 的原生小时序列。官方 FAQ：https://support.google.com/trends/answer/4365533 ，规则参考：https://www.rba.gov.au/publications/bulletin/2022/dec/new-measures-of-financial-stress-from-non-traditional-data.html

Google 现已推出官方 Trends API Alpha：滚动 5 年，支持**日、周、月、年**聚合，但未提供小时级；需要申请测试资格。另一个 BigQuery 数据集的“小时”只针对热门查询 Top 25，且美国数据是每 6 小时/每天 4 次、滚动 1 年，不等于任意关键词的 Explore。来源：https://developers.google.com/search/apis/trends 、https://support.google.com/trends/answer/12764470

`pytrends` 已于 2025-04-17 被作者归档，只读；2025 年 issue 已报告 Google endpoint 改动与 429，因此 2026 年不应把它当成稳定数据通道。来源：https://github.com/GeneralMills/pytrends 、https://github.com/GeneralMills/pytrends/issues/638

## 5. X（Twitter）历史推文检索

官方 Full-Archive Search 仍可搜索从 2006 年 3 月至今的完整 Post archive，支持 `start_time`/`end_time`，每页最多 500 条；官方文档写明需要 Self-serve（pay-per-use）或 Enterprise。因此 2026-05～09 的历史推文回放是官方支持的。来源：https://docs.x.com/x-api/posts/search/quickstart/full-archive-search

官方当前价格页写明 pay-per-usage、无订阅最低承诺，`Posts: Read` 为 **$0.005/返回的 Post**，即 **$5/1000 条**；pay-per-use 账户每月最多 300 万次 Post reads。官方还说明同一资源在同一 UTC 日内通常去重计费。来源：https://docs.x.com/x-api/getting-started/pricing
