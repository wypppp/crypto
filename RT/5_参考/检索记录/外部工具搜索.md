## 6. 原始钱包历史：Helius / Dune / QuickNode 都可以历史重建

# 四、代币名称、图片、description、外链

## 9. 链上 metadata + URI：A/B｜部分可以精确历史重建

Solana/Metaplex 元数据体系把：

**链上：**

* name；
* symbol；
* URI；
* update authority；
* mutable/immutable 状态等；

与 URI 指向的：

**链外 JSON：**

* description；
* image；
* external URL；
* 其它扩展属性

区分开。([Metaplex开发者中心][26]https://developers.metaplex.com/tokens/update-token?utm_source=chatgpt.com)

### 历史能否重建

链上 metadata 的 update transaction 是链历史的一部分，因此：

> “T+30min 时链上的 name/symbol/URI 是什么”可以从 archive transaction/state change 重建。

问题出现在 **URI 内容本身**。

Metaplex 明确说明，如果 token 可修改，update authority 可以换：

* name；
* symbol；
* URI；

从而让新的 URI 指向新的 JSON / image / description。([Metaplex开发者中心][26]https://developers.metaplex.com/tokens/update-token?utm_source=chatgpt.com)

如果 URI 指向的是永久内容寻址对象，例如固定的 Arweave transaction / immutable content，则原始 JSON 可以保留下来；如果是可变 HTTP 地址，就不能假定今天取得的 JSON 与 T+30min 相同。

### 价格/限流

链上部分沿用 Dune/Helius/RPC 的价格。

访问公开 URI 本身通常无需专门链 API；其可用性由实际 storage/host 决定，Metaplex 没有统一价格或 retention SLA。

[Metaplex Token Metadata 更新规则](https://developers.metaplex.com/tokens/update-token?utm_source=chatgpt.com)

### 不能推出什么

今天 token 页面上的 image、description、Twitter URL：

**不能自动视为创建 30 分钟时的 metadata。**

必须保存/恢复当时 URI 或证明内容不可变。

# 五、Twitter/X、Telegram 账号存在与年龄

## 10. X API：B/C｜“账号年龄”可以取；“历史 profile 状态”不完整

### 能提供

官方 user lookup 可以返回：

* user ID；
* username；
* `created_at`；
* description；
* avatar；
* verified；
* followers/following counts；
* website。([X Developer Platform][27]https://docs.x.com/x-api/users/lookup/quickstart/user-lookup?utm_source=chatgpt.com)

其中：

> `created_at` 是账号创建时间。

所以如果一个 pump token metadata 在 T+30min 已经给出了某个 X 账号，并且今天还能把它稳定解析到**同一 user ID**，可以得到“该账号在 token 创建时已经存在多久”。

### 历史能力

但普通 User Lookup 返回的是**当前 profile**，不是任意过去时点的 profile snapshot。

更重要的是官方写明：

* suspended/deleted user lookup → **404**。([X Developer Platform][28]https://docs.x.com/x-api/users/lookup/integrate?utm_source=chatgpt.com)

因此历史样本会出现严重的 surviving-data 问题。

### 价格

# 11. Telegram：B/C｜历史消息可以读，但账号/群组“创建年龄”没有直接字段

Telegram 需要分 Bot API 和 MTProto。

### Bot API

`getChat` 取得的是**当前 chat 信息**。官方没有返回 channel/group creation timestamp 字段。([Telegram][31]https://core.telegram.org/bots/api?utm_source=chatgpt.com)

所以 Bot API 不能直接回答：

> “这个 Telegram 群是在 token 创建前 3 天还是 300 天建立的？”

### MTProto `messages.getHistory`

官方 API 可以获取 peer 的历史 message history，并支持：

* `offset_date`；
* message ID；
* 分页；
* 历史 message date。([Telegram][32]https://core.telegram.org/method/messages.getHistory?utm_source=chatgpt.com)

因此对于仍公开、历史未删的 channel，可以寻找最早可见消息，用作“**可观察历史下界**”。

但官方明确：

* 该方法 **only users can use**；
* private channel 可能不可访问。([Telegram][32]https://core.telegram.org/method/messages.getHistory?utm_source=chatgpt.com)

### 价格

Telegram 官方 API 本身没有按请求计费的 API 月费。

### 不能推出什么

“最早还能看到的一条消息日期” **≠ channel 创建日期**。

管理员可能删历史、迁移群组、改 username，因此不能把它作为无偏的 Telegram account-age ground truth。

# 九、按四类信息看“历史 T+30 到底有没有来源”

### 1. 链上交易与持仓

**有，而且覆盖很好。**

Dune、Helius、QuickNode，以及跨链的 Alchemy archive 都能从历史 transaction / transfer / balance change 重建。

早期买家、developer action、holder concentration、同 slot/同 block 买入都属于这一层。

但**Jito bundle 的精确历史 membership**没有找到长期官方归档 API；只有链上迹象和近期 Jito status。

### 2. 钱包历史与标签

这里分开：

**钱包自己的历史行为：有。**

Dune/Helius/Nansen 都能回答创建前发生了什么，因此“过去发过几个币、历史买过哪些币、此前交易表现”可 point-in-time 构造。

**第三方机器人/Smart Money 标签：部分有。**

Nansen 是我找到的最明确支持 point-in-time labels 的供应商，但目前公开资料还不足以证明标签可以精确到“创建 +30 分钟”的分钟级历史快照。([Nansen][19]https://release.nansen.ai/changelog?utm_source=chatgpt.com)

### 3. metadata 与 social

**链上 metadata：有。**

**历史社交 profile：不完整。**

* X account `created_at`：有；
* X 当时 username/avatar/bio/follower 数：普通 API 不能完整倒放；
* deleted/suspended account：今天可能直接 404；
* Telegram channel 创建日期：官方接口没有直接字段；
* 历史“是否冒名”：没有找到可批量、可任意过去时点重放的官方来源。

这是目前四类信息中最大的历史数据缺口。

### 4. Robinhood/Pons 与 BNB/four.meme

**链上部分都能做历史回测。**

Robinhood Chain、BNB Chain 都是 EVM，因此 archive RPC + launchpad contract logs 是核心历史层；Alchemy 当前同时支持 Robinhood 和 BNB，并且其免费/PAYG 价格体系在 $100/月限制内。([Alchemy][35]https://www.alchemy.com/docs/reference/node-supported-chains?utm_source=chatgpt.com)
