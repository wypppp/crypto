**这对复现意味着什么**（只限本数据版本）：
- S1／S2 的文本特征一律用链上创建事件（name、symbol、uri）重建，不用数据里的元数据列；
- 论文所用数据是否有同样的错位，从发布版本推不出，不下结论；
- 995 行多余的原因是元数据一对多连接；同一 token 的价格只算一次。

## S0b 错位的结构（10-06；[S0b_错位诊断.md](S0b_错位诊断.md)，脚本 `s0b_misalign.py`，只用元数据与时刻）

错位是确定的位置映射，不是随机打乱，也不是来自时间相邻的币。

- 按 token 在数据里首次出现的顺序编号，第 u 个 token 拿到第 10·⌊u/20⌋＋(u mod 10) 个 token 的元数据。8,960 行里 7,613 行符合；不符合的主要是重复 token 多出的 998 行。
- 这像是按每页 10 条取元数据时，每页都重复了一次，再按位置拼接。
- 名称、代号、描述、图片一起错位；`token_uri` 与价格列跟着本行 token。
- 所属 token 都在列表前一半，创建时刻与本行 token 几乎不相关。文本不带本币信息，时间信息也很弱。

## S1 三种文本对照（10-06；[预登记](S1_预登记.md) 读结果前提交于 `7e23e1b9`，结果见 [S1_结果.md](S1_结果.md)）

- 正确文本：名称、代号取链上创建事件；描述按 `token_uri` 取 IPFS（`s1_fetch_meta.py`，pump 自己的网关；开发 token 3,856 个里取到 3,656 个）。
- 模型：ModernBERT-base 均值池化 → PCA 128 维 → CatBoost 默认参数；03-24 周训练、04-07 周测试（都是开发周）。
- 运行环境：独立虚拟环境（Python 3.12、CPU 版 torch），`s1_run.py`；模型修订号与权重 sha256 记在结果里。
- **结果：三种文本接近，文本在时间特征之外没有增量。** AP 差的 95% 区间 V1−V2 [−0.016, 0.045]、V1−V3 [−0.042, 0.027]、V1−V4 [−0.025, 0.041]，都含 0。四个变体的 AP 为 0.327～0.347，随机为 0.317。按预登记读法，S2 的文本特征降低优先级。
- IPFS 描述与数据里认领到本币的元数据块，在两者都有的 1,729 个币上全部一致，验证了 S0b 的错位结构。
