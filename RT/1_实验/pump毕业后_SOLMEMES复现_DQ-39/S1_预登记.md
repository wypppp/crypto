# DQ-39 SOLMEMES S1：三种文本对照（预登记，10-06）

> 依据：总控第二十轮第五节（[存档](../../3_审计/2026-10-06_总控第二十轮_InitBoost扫描与F133错位诊断.md)）；推进方案 v1 阶段 1 第 7 项⑦。

> S1 的定位是“论文口径参考”，不作任何通过依据。

## 1. 母体与切分

S1 只用开发 token（S0 分类，3,856 个）。重复 token 只取数据里的第一行；S0 已核对重复行的价格列完全相同（161/161）。

切分按链上曲线创建时刻所在周：

- 训练：2025-04-07 之前创建的开发 token（主要是 03-24 周）；
- 测试：2025-04-07 周创建的开发 token。

论文的样本外测试是 04-14～04-19，属于 DQ-37 检验周，S1 不碰。

## 2. 标签

标签沿用论文：P15＝1 当且仅当 `average_price_14` 大于 `average_price_0`。论文写“第 1 分钟与第 15 分钟”，数据只有 0～14 共 15 列，读作第 0 列与第 14 列。

两列任一为空的 token 不进入 S1，个数单列。

收益另按论文的调整口径算一遍：投入 1 SOL，买入滑点 5%、卖出滑点 2%、DEX 费 0.3%、固定成本 0.00241 SOL。分钟均价不是可成交价，所有收益都标“论文口径参考”。

## 3. 特征

- **时间特征**：毕业用时（数据的 `graduated_date − created_at`，秒）与创建时刻（epoch 秒）。S0 已核对这两列与链上逐秒一致。
- **文本**：按论文拼成一句话：“The name of the token is = {name}, its symbol = {symbol} and Description = {description}”。
- **向量**：ModernBERT-base，取最后一层的均值池化，最长 256 个词元。论文写“ModernBERT-large, 768d”，两处互相矛盾；768 维对应 base，所以用 base。模型修订号与权重文件的 sha256 记在结果里。论文另用的 OpenAI 向量需要付费接口，S1 不做。
- **降维**：PCA 128 维，只在训练集上拟合。
- **模型**：CatBoost 分类器，默认参数，`random_seed=0`，不调参（对应论文的 Baseline）。

## 4. 三种文本与一个对照

| 变体 | 特征 | 文本来源 |
|---|---|---|
| V1（主） | 时间＋文本 | 链上重建：名称、代号取链上创建事件；描述取 `token_uri` 指向的 IPFS 元数据 JSON。IPFS 取不到时，用数据里认领到本 token 的元数据块；仍没有就留空。各来源的个数单列 |
| V2 | 时间＋文本 | 发布数据里本行的名称、代号、描述（错位文本） |
| V3 | 时间＋文本 | V1 的文本在同一创建周内随机打乱（种子 20261006） |
| V4 | 只用时间 | 不用文本。论文只做了“去掉时间”的消融，没有做“只用时间” |

## 5. 指标

- 测试集上的 AP（平均精度）与阈值 0.5 时的准确率、精确率、召回率；
- 阈值 0.5 时的交易数、平均 ROI15、平均调整 ROI15；
- 论文的置换 p 值：打乱测试集的收益 1,000 次，看交易收益不低于实际的比例。

## 6. 读法（写死）

- 测试集按 token 自助 1,000 次（种子 20261006），算 AP 差值的 95% 区间。
- V1−V2 与 V1−V3 的区间都含 0，记“三种文本接近”。按总控第五节，这表示文本没有带来币本身的信息，S2 的文本特征降低优先级。
- V1−V4 的区间含 0，记“文本在时间特征之外没有增量”。
- 任何结果都不作通过依据，也不改方向状态。
