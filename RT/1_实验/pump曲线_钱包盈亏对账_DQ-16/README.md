## 1. 这一步只回答一个问题

**用能扩展到全市场的工具（Dune），能不能把一个交易者在 pump 上的逐币进出、期初期末库存、转入转出和全部交易级成本算对？**

- 通过只说明“能测”。不说明任何钱包、时间档或路线有无优势，也**不授予开启或关闭“pump 吃单”任何一类路线的权限**（审阅 §2 表）。
- A/B 两周全市场的钱包检验**不在本卡内**。本卡通过后，如要做，须另写提案、另行裁决，并先回答审阅提出的四个问题：匹配对照（交易次数、资本、入场时点、发行日）；B 周不再出现的地址怎么处理（存活选择）；地址不等于经济主体（创建者受益实体、换钱包）；链上成交年龄不等于收到信号的时刻。

## 3. 抽样（先冻结，再取账本）

- **抽样框**：2026-06-07 UTC 全天（slot [424781069, 424998001)，二分 `getBlockTime` 得出）中，调用了 pump 曲线程序 `6EF8rrecthR5Dkzon8Nwu78hRvfCKubJ14M5uBEwF6P` 或 PumpSwap 程序 `pAMMBay6oceH9fJKBRHGP5D4bD4sWpmSwMn52FMfXEA`、执行成功的交易。
- **方法**：种子 `20260923`。在 slot 范围内均匀随机取 slot，`getBlock` 取整块，在框内交易中均匀随机取 1 笔。**首签名者名下的代币余额有变化**时，首签名者入样（A 类：自托管成交）；否则记为 B 类（代币变动在程序控制的账户里，例如自定义机器人程序、Mayhem 程序），只计数不入样。空 slot 或框内无交易时重抽。重复地址跳过，直到 30 个不同地址为止。
- **性质**（r1 更正）：先均匀抽 slot、再在块内均匀抽一笔，**不是按成交加权**：框内 35 笔和 232 笔的块各贡献一次机会。它适合作对账压力样本，不代表全市场交易者。B 类在 48 次有效抽取中占 18 次（0.375）；按块内框内笔数加权的比值估计为 0.378。**这只描述本抽样方案，样本很小，不能写成全市场成交占比。**
- 抽样脚本与名单在取任何钱包历史之前提交。

## 4. 真值账本（Helius）

- 每个入样地址取 06-07 全天**全部**交易，包括失败交易，以及只触及其代币账户的交易（`getTransactionsForAddress`，`tokenAccounts: balanceChanged`）。
- 逐笔拆出以下各项：成功与否；基础费和优先费（`meta.fee`）；Jito tip（转给 8 个 tip 账户的 SOL，名单取自 Jito `getTipAccounts`，09-23）；转给其他地址的 SOL，列出最大收款方，用来识别第三方发单服务的 tip；代币账户开立与关闭的租金；钱包 SOL 余额变化；按 mint 列出该地址名下代币余额的变化；程序分类（pump 曲线、PumpSwap、其他 DEX 或聚合器、纯转账、其他）。
- 每个 地址×mint：买卖（按场所）、转入转出、期初库存（首笔触及时的 `preTokenBalances`）、期末库存（末笔的 `postTokenBalances`）。
- 单个地址上限 3,000 credits。超过的记为“未取全”并如实报告，不静默丢弃。

## 5. 候选账本（Dune，r1）

`sql/` 下两条查询（由 [make_sql.py](make_sql.py) 生成），由用户运行，**只输出汇总行**：

- **Q2**：`solana.transactions` 中样本地址是签名者之一的全部交易（含失败）。按地址输出集合指纹（笔数、slot 之和）、失败笔数、所付手续费、失败交易手续费，以及本地址 lamports 的变化；按地址输出其名下代币账户的 lamports 变化（wSOL 与其他分开）；按 地址×mint 输出签名交易内的代币净变化、期初余额（首笔的 pre）和期末余额（末笔的 post）。
- **Q1**：pump 曲线 `TradeEvent` 与 PumpAMM `BuyEvent`/`SellEvent`（按 `user`），按 地址×币（PumpSwap 按池子，池子到 mint 用 Helius 读池子账户，offset 43）输出签名数、slot 之和、买卖代币量、用户侧 SOL；`tokens_solana.transfers` 输出 Jito tip、他人签名但触及本地址的交易集合指纹及其 SOL/代币进出、每个地址最大的 5 个 SOL 收款方。
- **不单独接入其他场所的成交表**：总额按余额核对，其他场所、终端手续费、租金都已计入余额变化；只有“归属到 pump 成交”这一步不覆盖它们，其规模在 C4、C5 单独报告。

## 6. 判据（r1，运行任何 Dune 查询之前修订；原 1–5 条作废，见 §9）

交易集合的定义：**签名集** = 样本地址是签名者之一的交易；**触及集** = 首签名者是别人、但本地址或其名下代币账户的余额有变化的交易。两边都按这两个定义各自统计，比较时一律用外连接，**任何一边缺失的格都算不一致**。

- **C1 覆盖**：a. 每个地址的签名集指纹（笔数、slot 之和）一致；b. 每个地址的触及集指纹一致；c. pump/PumpSwap 成交按 地址×币 的签名数与 slot 之和一致，不一致格对应的真值成交额 ≤1%。
- **C2 余额（盈亏的核心）**：a. 签名集内，每个地址“本地址 + 名下全部代币账户”的 lamports 总变化与真值**精确相等**；b. 签名集内，每个 地址×币 的代币净变化精确相等；c. 触及集内，每个地址的 SOL 净变化相差 ≤1,000 lamports × 笔数；d. 触及集内，每个 地址×币 的代币净变化精确相等。
- **C3 库存**：签名集内，每个 地址×币 的期初、期末余额精确相等。另外报告首次触及来自触及集的格数（这些格的期初余额，Dune 只能从转账额推算）。
- **C4 成本归属**：手续费、失败交易的笔数与手续费、Jito tip 逐地址相差 ≤1,000 lamports。另外报告“非 pump 成交的 SOL 流”（充提、其他场所、终端手续费等）占成交额的比例和最大收款方，只作描述。
- **C5 场所范围**（只报告）：同时调用其他 DEX 程序的交易，占触及交易的比例及其金额占比。
- 单位约定（Dune 代币余额是 UI 数量还是最小单位）按数据确定，不算判据修改。

**判定**：C1a、C2a、C2b、C3 全过，且其余各项也过 → **能测（余额口径）**。C1a、C2a、C2b、C3 过，其余有缺口 → **部分能测**（逐项写缺什么、多大）。C1a、C2a、C2b、C3 任一不过 → **不能测**。

**即使判定为能测，结论也只写成“抽样地址的一日交易账本可复现（余额口径）”。**期末持仓的估值、跨日跨地址的整钱包盈亏、“谁能持续赚钱”都不在本卡内，需要分别验证。

## 7. 不做什么
