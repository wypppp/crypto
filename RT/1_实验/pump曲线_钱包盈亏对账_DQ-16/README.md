## 3. 抽样（先冻结，再取账本）

- **方法**：种子 `20260923`。在 slot 范围内均匀随机取 slot，`getBlock` 取整块，在框内交易中均匀随机取 1 笔。**首签名者名下的代币余额有变化**时，首签名者入样（A 类：自托管成交）；否则记为 B 类（代币变动在程序控制的账户里，例如自定义机器人程序、Mayhem 程序），只计数不入样。空 slot 或框内无交易时重抽。重复地址跳过，直到 30 个不同地址为止。
- **性质**：按成交加权，高频交易者会被多抽，这对费用、tip、失败交易是更严的压力测试；**B 类占比本身就是结果之一**，它说明有多少 pump 成交不能按“钱包”归属。

## 4. 真值账本（Helius）

- 每个入样地址取 06-07 全天**全部**交易，包括失败交易，以及只触及其代币账户的交易（`getTransactionsForAddress`，按冒烟结果决定 `tokenAccounts` 选项）。
- 逐笔拆出以下各项：成功与否；基础费和优先费（`meta.fee`）；Jito tip（转给 8 个 tip 账户的 SOL，名单取自 Jito `getTipAccounts`，09-23）；转给其他地址的 SOL，列出最大收款方，用来识别第三方发单服务的 tip；代币账户开立与关闭的租金；钱包 SOL 余额变化；按 mint 列出该地址名下代币余额的变化；程序分类（pump 曲线、PumpSwap、其他 DEX 或聚合器、纯转账、其他）。
- 每个 地址×mint：买卖（按场所）、转入转出、期初库存（首笔触及时的 `preTokenBalances`）、期末库存（末笔的 `postTokenBalances`）。
- 单个地址上限 3,000 credits。超过的记为“未取全”并如实报告，不静默丢弃。

## 6. 判据（冻结）

对 30 个地址 × 06-07：

1. **覆盖**：真值里每笔成功的 pump/PumpSwap 成交，Dune 都有对应记录；缺失笔数和缺失 SOL 成交额都 ≤1%。
2. **金额**：按签名配对后，SOL 与代币数量一致（SOL 差 ≤1,000 lamports，代币为最小单位的精确相等）。
3. **成本**：钱包 SOL 余额变化能拆成“成交 SOL + 平台/创建者费 + 基础与优先费 + tip + 租金 + 其他”。逐项写出 Dune 能不能复现；**Dune 不能复现的部分合计 ≤该地址当日成交额的 0.1%**。
4. **库存与转账**：每个 地址×mint 的期初、期末库存和转入转出能由 Dune 复现。同时报告转出占代币流出的比例（换钱包的量级）。
5. **失败交易**：失败交易的费用支出能由 Dune 复现。

**判定**：1–5 全过 → **能测**。1、2 通过，3–5 有缺口但缺口可量化 → **部分能测**（逐项写缺什么、多大）。1 或 2 不过 → **不能测**。另外单独报告 B 类成交的占比。
