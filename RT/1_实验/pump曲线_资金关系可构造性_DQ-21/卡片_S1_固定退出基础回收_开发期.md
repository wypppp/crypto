# DQ-21 S1：事件时点固定退出基础回收（开发期卡片）

> 2026-09-28，在已看过 S0 最佳时点上界和池边际价漂移后制定。它是新的开发期诊断，不能追认成 S0 冻结前的规则，也不打开 2026-06-15 起的封存周。当前卡片只定义测量，不含资金关系或选择规则。

## 要回答的问题

对 2026-06-01～14 创建、第三位合格买家在 300 秒内出现的 SOL 计价 pump 币，如果在 `t3+5s`、`t3+30s` 或 `t3+120s` 买入 0.5 SOL，按固定规则卖出，基础净回收是多少？分 A/B 周、第三位买家到达时间层报告。S0 的“30 天内最优卖点”均值不能回答此题。

## 估值规则

1. 沿用 S0 v1.3 已核实的第三位买家、事件排序、曲线/PumpSwap 映射、入场 0.5 SOL 买单和池手续费口径。`t3` 之前的任何交易不得用于关系信号。三档延迟分别独立建仓和卖出，不共享入场价格。
2. 固定持有时间从**各自入场目标时刻**起算：30 秒、2 分钟、10 分钟、1 小时。退出使用目标时刻之前最后可核的池状态报价 0.5 SOL 买入所得代币的整笔卖出金额，扣池费用和曲线真实 SOL 储备限制。没有新成交并不自动判为无法卖出；保留状态时间与退出目标时间之差。迁移后从映射的 PumpSwap 池报价。若池状态缺失、储备不足或无法确定可用池，则记“退出未知”，不置零，也不从均值中静默删除。
3. 既有 `b50` 规则作为第五种退出：从各自入场后逐事件跟踪池边际价格，首次跌破历史峰值的一半时，按该事件后的池状态报价卖出；若 30 天未触发，按最后可核状态报价。另记止损触发时间、价格倍数和实际可卖回收。此规则沿用既有定义，不拿本次结果调止损比例。
4. 所有成交都是**池模型成交**，并非真实下单记录。链上池费计入；优先费、失败交易、额外捆绑小费、抢跑和落地偏差未计入，另以每笔额外固定成本和 +1 slot 延迟作敏感性，不把零摩擦模型称为实盘净收益。
5. 秒级边界单独验收：历史记录有同秒多笔时，基准状态按 `slot/tx/instruction` 截止；不得使用目标时刻之后的事件。S0 的 `e5_rn` 可能选到边界秒末的交易，因此基准及至少一个保守落地情形须并报。没有 slot 到真实接收/落地的映射时，5 秒估值只作模型情形。

SQL 草案由 [build_s1_baseline_sql.py](build_s1_baseline_sql.py)从冻结 S0 文件生成，输出 [S1_AB_固定退出基础回收_待验.sql](sql/S1_AB_固定退出基础回收_待验.sql)。`max_by/min_by` 汇总先把不可报价的 NULL 暂记为不可能的 -1，再在结果中还原 NULL，避免聚合跳过最新的不可报价状态而误用更早可报价状态。运行前还须验收此行为与 Dune 引擎一致。

两份 SQL 已通过本地 Trino 方言语法解析和“曲线/AMM 三张成交表各引用一次”的静态检查；这**不是** Dune 引擎执行验收。[Dune 原始 SQL API 执行文档](https://docs.dune.com/api-reference/executions/endpoint/execute-sql)只公布 `small/medium/large` 档位，没有单次 credit 硬上限参数，故不能用它替代网页上设定的 ≤100-credit 上限。

## 样本与统计

- 沿用冻结的 S0 v1.3 抽样框：病例超集全纳、其他适用币按 mint 哈希 2% 纳入；R0 已看过币仅作 QA，主估计排除。入样概率按 S0 冻结值，不按本次收益重新抽样。
- 每个币导出 12 个“入场延迟 × 固定持有期”的池模型回收、3 个 `b50` 回收、可报价/未知标记，以及报价对应事件序号与状态年龄。可另导出必要的费率、池储备、迁移标记以复核 10 个币。避免导出完整 30 天逐笔路径。
- 总体均值用已冻结入样概率的逆概率权重；同时报告中位、亏损比例、实际 ≥10 倍比例、最大 1/3/10 币的贡献、按创建日分块的区间和每层有效样本量。A 周 `t3=121–300s` 只有 10 个非病例样本，必须标为低精度；校准权重不能替代样本量。
- 不以全买基础回收低于 1 直接否决关系方向。基础回收的作用是给下一张 R1a 卡算所需优势、样本量和费用门槛。若某些分层缺估值，先报告缺失机制；不得只算可成功退出币的平均值。

[analyze_s1_baseline.py](analyze_s1_baseline.py)已准备：先将新结果与冻结 S0 的 10,565 个 mint、入样标记、哈希、`t3` 与入场储备逐一对账，再估计 15 条退出规则；只要有结果缺失，就不输出完整总体平均值，而先列缺失权重。本地 10,565 行模拟数据验收了对账、缺失传播和“全部亏损时无正利润集中度”的边界情况。模拟数据不进入项目结果。

## 执行闸门

先核 Dune 控制台的总剩余额度与本次 API 取回真实扣费，以及 Helius 控制台的实际方法计费。官方 `POST /api/v1/usage` 免费元数据端点已试过，但只返回 0.145 credits、与已知 45.5102 的 SQL 执行费不相符，不能用于判断总余额。余额核清后，先用 [一日冒烟版](sql/S1_SMOKE_20260601_固定退出基础回收_待验.sql)核结果形状、成本和当日缓存币，再跑开发期全窗并核 10 个跨日缓存币；单次 SQL 执行继续遵守用户此前设定的 **≤100 credits**。不触碰封存周。

验收要求：创建数、适用数、S0 纳入名单和哈希逐一相同；10 个既有 Helius 原始池状态再次对上；各延迟的入场代币量与 S0 相同；同一入场/退出池状态立即往返的损失与独立池公式相容；不存在未来事件作退出状态、重复计费、迁移前后储备混用。任何一项不符先修数据，不解释为策略结果。
