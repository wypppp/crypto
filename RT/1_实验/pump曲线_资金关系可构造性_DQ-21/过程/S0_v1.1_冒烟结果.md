## 3. 冒烟发现的输出缺陷

Dune 内部用 64 位 `mint_hash` 正确完成了 2% 抽样，但 API JSON 把超出 53 位精度的整数舍入：352 行中 349 行的输出哈希末位改变。本地从 mint 重算 xxhash64（大端解释、清符号位）后：

- 全部 `random_2pct` 行都满足 `hash mod 10000 < 200`；
- 导出的随机子队列数与精确计数 220 一致；
- 尾部普查数与精确计数 122 一致。

所以抽样没有错，**输出字段不可复算**。正式版必须把精确哈希以字符串或十六进制输出，本次结果不能直接使用 API 返回的十进制 `mint_hash`。

## 4. 对复核建议的裁决

1. **右尾过抽改成覆盖最晚 420 秒入场的超集：接受。**保留原 `t3+5s` 可执行 10× 结果字段；另以 `t3+5s` 至创建后 420 秒每个真实状态的“未来最高价格/本点价格 ≥8”定义抽样超集。它只决定全量入样，不算收益。
2. **全部适用币窄表：现在不做。**单日已有 11,068 个、两周约 15 万个。按现有输出规模，完整地址索引会显著占用取回预算。2% 子队列预计约 3,000 个对照，是否不足须由正式 S0 的功效计算回答。额度到期不是提前囤数据的理由。
3. **迁移映射完整性：接受。**正式版增加 `has_migration_event`、`amm_mapped` 及精确总数，不能再把未映射与普通方向池混为一类。
4. **哈希可复算性：新增必修。**输出 `mint_hash_exact` 字符串，本地必须逐行复算。

## 5. 判定

v1.1 冒烟对核心成交路径与时点语义**通过**，但暴露出哈希输出和映射验收字段不足。正式 v1.1 禁止运行；先出 v1.2，并对改变后的病例过抽数量和映射字段再做一次单日验收。
