# S0 v1.1 执行更正

> 冻结时间：2026-09-27；在任何 S0 Dune 查询产生 execution 之前。v1 文件保留作审计记录，但不得运行；v1.1 取代 v1。研究问题、A/B 总体、`t3`、病例队列抽样和结果权限均不变。

> **编译更正（09-27）**：第一次网页冒烟在编译阶段报 `COALESCE` 只有一个参数。三处表达式本来只是包住一个已有完整真假分支的 `IF`，现删除多余外壳；没有查询结果、没有改变任何计算口径。修正后重新冻结哈希。

> **Dune 兼容性更正（09-27）**：第二次网页冒烟在编译阶段报 Dune 不支持窗口函数上的 `FILTER`。七个精确计数字段机械改为 `sum(CASE WHEN 条件 THEN 1 ELSE 0 END) OVER (...)`；分组聚合中的 `FILTER` 保留。新增静态检查，禁止 `FILTER (...) OVER` 再进入运行版。没有查询结果，计数定义不变。

## 为什么更正

1. **PumpSwap 池方向**：v1 只接入“目标币为 base、wSOL 为 quote”的池。DQ-16 已实测 PumpSwap 还大量存在 `base=wSOL、目标币在 quote 侧` 的反向池。v1.1 同时接入两种方向，把储备、买卖方向和 SOL 金额统一成“`x=SOL`、`y=目标币`”。
2. **AMM 买入金额与交易后状态**：v1 重用了旧的 `quote_amount_in - protocol_fee - creator_fee` 回退量，且优先拿“下一笔交易的前储备”作当前交易后状态。前者与 H1 已核的池余额不符，后者会把两笔之间的加减流动性带入更早的交易。v1.1 的 AMM 买入金额和池增量改用已经本地原始交易对账的 `quote_amount_in_with_lp_fee`，交易后储备一律由本笔的前储备加本笔增量得到。
3. **同秒排序与区块时间**：v1 在 `slot` 前按 `venue` 排序；迁移附近同一秒内可能因此打乱曲线和 AMM 事件。v1.1 按 `slot → tx_index → outer_instruction → inner_instruction → venue` 排序，并用 slot 顺序的前缀最大 block time 作单调时钟，避免偶发的 block time 回退把未来事件塞进早期窗口。
4. **三档延迟的问题必须真正算到**：v1 只为 `t3+5s` 建仓，`+30s/+120s` 只报价格变化，不足以回答各延迟还剩多少可兑现空间。v1.1 为三档各自注入 0.5 SOL 模型仓位，分别输出 30 天最大模型回收；10/30 分钟、2/24 小时路径仍以 `+5s` 为主口径。
5. **结果取回也计费**：Dune SQL API 按返回 data points 计 credits。v1 的 5 MB 只是大小限制，不是费用限制。v1.1 要先读状态元数据并估算导出费用，再决定是否取回。
6. **R0 QA 不进主估计**：v1 的分析器会让恰好也进入尾部普查或固定子队列的 R0 币保留抽样权重，与“105 个已看币全部排除”的规则不一致。v1.1 在精确总体计数中保留它们，但从所有加权主估计的分子与分母中一律剔除。

## 没有改的内容

- 曲线阶段的估值公式保留。它先把我方仍持有的代币计入曲线状态，再按同一常数乘积不变量卖回；不是把当前未调整储备直接套卖出公式。
- 固定 0.5 SOL 模型仓位、`t3+5s` 主基准、30 天路径、全部 10× 尾部、固定哈希 2% 子队列和 105 个 R0 QA 币不变。
- 本段仍不读取 2026-06-15 起的封存 cohort，也不检验资金关系收益。

## 预算与停止

- 单日冒烟：执行上限 5 credits；只取对账所需列，取回上限 5 credits。
- A/B 正式查询：执行上限 115 credits。
- 正式结果取回：在下载前按账户当时的 data-points/credit 比率估算，硬上限 100 credits；超过就不下载，改用列裁剪或降低固定随机子队列比例的新版本，不能直接导出。
- S0 v1.1 总额上限 225 credits。额度到期或剩余额度不是运行理由；任何一步触顶即停。

## 验收新增项

- 报告映射到普通池与反向池的币数；若有反向池，在 R0 QA 或固定子队列中至少抽一笔与原始事件方向核对。
- 三档建仓状态不缺失；`max_sell_30d` / `_e30` / `_e120` 必须分别来自各自建仓的代币数，不得用价格比代替。
- v1.1 冒烟仍按 [既有对账基准](S0_smoke_既有对账基准.md) 核 2026-06-01 的 13 个币；若 `t3_s` 变化，须能由金额口径或 slot 顺序修正逐笔解释。
