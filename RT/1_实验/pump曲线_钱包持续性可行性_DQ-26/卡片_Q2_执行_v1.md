## 3. 定义（冻结）

| 项 | 内容 |
|---|---|
| 币 | **2026-08-17 00:00～08-30 24:00 UTC 创建**的 SOL 计价 pump 币（创建事件 `quote_mint` 为空或系统程序，同 S1） |
| 成交与池状态 | 曲线（`pump_evt_tradeevent`）与 PumpSwap（迁移池映射逐字取自 DQ-21 `WM_A.sql`，同第一步 `build_rank_sql.py`）的全部成交；只读 **08-17～09-06** 的分区，成交截至 **09-06 24:00 UTC**。每笔成交后的池状态为一个“状态”，按（slot, 交易序号, 外层指令, 内层指令, 场所）排序；时钟取到该状态为止的最大区块时间（秒），记创建后秒数 `dt` |
| 触发 | 每个（实体, 币）一次：该实体任一钱包在该币上的**第一笔买入**（事件 `user` 属于 146 个钱包；曲线或 PumpSwap）。其时钟为 `b_dt` |
| 实体卖出信号 | 该实体任一钱包在该币上、排在触发之后的**第一笔卖出**，时钟 `s_dt`；没有则无 |
| 持有上限 | `H = b_dt + 7 天`；数据截至 09-06 24:00，触发晚于 08-30 的，`H` 实际被数据截止截断（单列计数） |
| 入场（延迟 d） | 时钟 ≤ `b_dt + d` 的最后一个状态（S1 的同一约定：按该时刻可成交的池状态；区块时间只到秒，同一秒内的后续成交算在入场之前） |
| 跟随退出（延迟 d） | 时钟 ≤ min(`s_dt + d`, `H`) 的最后一个状态；没有卖出信号时为 `H` 前最后一个状态。卖出全部 |
| 估值 | S1 同一估值函数（DQ-21 `S1_*_双口径.sql` 的 `s9`/`s10`）：入场代币＝`y − x·y/(x + 0.5·(1 − fee))`（入场状态）；卖出口径 A（卖进不含我方仓位的状态，保守）与口径 B（我方仓位留在曲线里，乐观；PumpSwap 上两口径相同）；曲线卖出以 `xr + 0.5·(1 − 入场费率)` 封顶。PumpSwap 的费率取该笔成交的实际费用 ÷ 成交额（WM 管线不带费率字段）；反向池费用缺失时按 125 bps 计 |
| 全成本 | 网络费与小费按我方实测前的保守值，买、卖各 **0.002 SOL**：`R = (卖出所得 − 0.002) ÷ (0.5 + 0.002)`；截断 `Z = min(R, 3)` |

## 5. 统计量与读法（写死）

- **主统计量**：主格全部触发的平均 Z；按触发币的**创建日**（14 个区块）分块自助法 95% 区间（10,000 次，种子 20261001，按日有放回抽取，统计量为抽中各日全部触发的平均）。同法另报平均 R 的区间。
- **读法 1（支持）**：主格平均 Z 的区间下界 >1——外部跟随在检验期支持 E[R]>1（开发证据；进入确认前还须实测延迟与成交，02 §10.4）。
- **读法 2（关闭所测实现）**：主格平均 R 的区间上界 <1——关闭“跟随前 50 个全成本盈利实体（2 秒延迟、跟随其首卖退出）”这一实现。按 10-01 规则，关闭看 R 的上界，不看 Z。
- **读法 3（不定）**：其余情形。不在本窗口上加格或换参数。
- 次要格不改变读法。若某次要格下界 >1 而主格不是，只记为假设，须新卡、新数据检验。
- 命中率（R>1 的比例）只作解释；保本命中率 p_BE＝(1−R_L)÷(R_W−R_L)，R_W、R_L 为盈利、亏损触发的平均 R。

## 6. 描述（只描述，不改读法；读数前写定）

- 触发数、有触发的实体数；检验期没有触发的实体单列为“未参与”，不填 1。
- 按第一步的实体分组（`top50_profile.csv`）：同槽为主（同 slot 买入格 ≥90%，24 个）、可跟随（买入额中位持有 ≥30 秒且过半买入在 `t3+5 秒`之后，12 个）、其他（14 个）各自的触发数与平均 Z、平均 R。
- 按实体等权的平均 Z（先实体内平均，再平均）。
- 实体在我方入场前已发出卖出信号（`s_dt ≤ b_dt + d`）的触发占比；入场与退出落在同一状态的占比。
- 集中度：主格净额（Σ(R−1)）中最大 10 个币、最大 1 个创建日的占比。
- 触发距创建的时差、是否与创建同 slot；`H` 被数据截止截断的触发数；口径 B 无定义（曲线上代币不足）的格数。
