## 1. 只回答一个问题

**在加密市场里，是否存在一个具体的“信息来源—我方位置—可观察时刻—同一资产的交易动作”，并能拿出带时间戳的历史实例和失败对照？**

- 找到：交一份材料，供 10-16 治理复核决定是否批准写**一项**有限提案。
- 找不到：交“无合格来源”，并写清查过什么、为什么不合格。**不靠增加术语或数据接口凑提案。**
- 本卡不证明任何优势。材料里的实例只用来说明机制，不作收益证据。

## 2. 我方位置的三种类型

每个候选必须先回答：**凭什么是我们？**也就是我方哪一项实际能力，能让我们比边际交易者更早、更深或更全地读懂这类信息。说不出来的候选直接淘汰。

| 类型 | 含义 | 我方可能的依据（背景.md，需逐项证明） |
|---|---|---|
| **更早** | 在价格反映之前收到信息，而且比同样看到这条信息的最快对手慢得不多（09-23 用户补充的两条判据：机会是否排他；所需速度由最快的同信号对手决定） | 秒级延迟（硅谷服务器，未实测）；中文信息渠道 |
| **更深** | 信息公开，但读懂它的含义需要专业知识或大量处理，例如协议代码、规则变化、代币经济条款、链上结构；**也包括对我方已有数据的深挖**，从中发现之前没发现的结构 | 大模型处理长文本、代码和多源材料的能力；已建好的 pump 链上数据管线（DQ-1 至 DQ-16） |
| **更全** | 单条信息人人可见，但它们分散在不同语言、平台、链上和链下，很少有人把它们合在一起看 | 中英文双语；大模型的多源整合能力 |

**深挖已有数据的护栏**：在已打开的数据上可以广泛探索，但挖出的模式要算数，须满足三条：①说得出机制，也就是谁在为它付钱；②不是 F83、F93、F88、H1 这些已失败特征族换个名字；③之后要用没打开的数据检验，检验另写提案。DQ-16 §7 的关联线索按其中列出的四个前提处理。

## 3. 材料格式（每个候选）

| 字段 | 要求 |
|---|---|
| 信息由谁产生 | 具体的发布者或链上事件 |
| 我方位置 | 更早、更深或更全，以及“凭什么是我们” |
| 可观察时刻 | 分开写：信息发布、我方能收到、最早可成交 |
| 为什么价格可能还没反映 | 一个可以失败的机制说明 |
| 交易动作 | 同一资产，写明场所、方向、成本和大致容量 |
| 带时间戳的历史实例 | 至少 1 个成功例、1 个失败对照，价格路径可复查 |
| 与已失败路线的差别 | 对照 F83、F93、F88、H1（F105）、F106、DQ-2 |
| 数据需求 | 需要付费数据时写明：用途、平台费用上限、结果会改变什么判断，**经用户同意才用** |
