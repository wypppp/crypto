# DQ-1 卡 · pump curve 阶段：生命周期与数据可得性探针（≤2h）

> 2026-09-15 冻结，写于运行任何 Dune 查询之前。本探针**不测收益**，也不读取任何代币的倍数结果。

## 决策

**只回答一个问题**：现有数据能否支持一次 curve 阶段的右尾测量，并满足三个条件：包含失败对象（不毕业、无成交的币）、覆盖跨迁移退出、口径可解释。

- **if_A（可行）**：四项交付都有可用路径，缺口可以用有限成本补齐 → 用剩余预算（原 8h 中不超过 6h）另写测量卡，先测一个有限切片。**不自动启动批量测量。**
- **if_B（不可行或代价过高）**：分母、单位或迁移映射中任一项无法取得，且没有低成本替代 → 写明缺口与最便宜的补法，DQ-1 暂停。

**对百万目标的贡献**：curve 阶段是 #10 从未测过的区段（F02），链上发射台是母体发现候选中最集中的一类。本探针只决定这件事能不能测。

## 四项交付

1. **储备字段**：`pump_evt_tradeevent` 中新旧储备字段各自的时间覆盖、单位、空值含义，以及与程序版本、官方文档变更的对应关系（F27）。
2. **分母**：能否枚举全部发行，包括不毕业、没有成交的币。创建事件与成交事件的对账。
3. **迁移映射**：curve 完成 → 迁移 → 后继池的映射能否取得；迁移后退出所需的池状态能否取得（历史上迁往 Raydium、后来迁往 PumpSwap 的分支都要看）。
4. **结论**：能测什么、还缺什么、下一步最低成本。

## 取证顺序与上限

1. **信息搜索**：官方 docs 与 IDL 及其提交历史；已有研究。
2. **工具搜索**：Dune 数据集目录的表结构（目录搜索，不执行 SQL）；本项目已有 SQL 与数据。
3. **实证**：Dune SQL，**最多 6 条**，每条只扫描指定的单日分区（`evt_block_date = DATE …`），抽样日期事先列出：2024-03-01、2024-09-01、2025-03-01、2025-09-01、2026-03-01、2026-09-01。运行中若需增加日期，写明原因后再加。
   - 不做全表扫描；
   - 不查询任何代币在决策时点之后的价格或倍数。

## 输出

- `dq1/raw/`：目录搜索结果、每条 SQL 与返回的 CSV；
- `dq1/DQ1_结果.md`：四项交付，每项写明证据、适用范围、不能推出什么。

## 不能推出

- 任何收益、命中率或容量；
- 抽样日以外的完整覆盖（抽样只能发现缺口，不能证明完整）；
- 其他发射台的数据可得性。

## 预算

主动工时 ≤2h。Dune 额度以上述 6 条单日查询为限。
