## 3. 判断

1. **它的币安部分不是我们的样本外**。按定义推断（未逐条核对），470 个事件几乎包含我们开发期看过的全部 206 条（206 条都有 USDT 交易对，F26；窄类 145 条在其中），也包含 55 条留出。在同一批事件上换口径重算，只能说明“上市后下跌”对口径不敏感，不是独立证据。
2. **Bybit、Coinbase 部分是不同的事件，但不检验我们的策略**。
   - 它们只量现货价格的中位变化。做空窄类要的是**空单盈亏的均值**，包括资金费和爆仓路径。
   - 我们自己的 F124 已经说明两者会分开：币安只上永续的 199 个新币，价格多数下跌，同一做空规则仍是 −3.3%、爆仓 25.4%。少数暴涨的币决定均值。
   - Bybit 样本只含存活的币，中位跌幅可能被低估，这一点对做空有利。但它不能替代对均值和爆仓率的测量。
3. **结论：可作为“上市后下跌在其他交易所也存在”的外部旁证（T3），提高宽类现象的先验；不能作为窄类的样本外证据，也不能据此缩短前向 T1 窗口。**缩短一个已冻结的 T1 窗口本来也要你裁决，并先过门 1。
4. **可复用的部分**：
   - **首日成交额分组**（成交额越高，首周跌得越多：从 −0.6% 到 −23.5%）可作窄类的条件变量。但 v3 卡已冻结，只能在门 1 时作为“事先登记的描述分组”提出，不改读法。
   - 仓库里有 `short_pnl_check.csv`、`funding_sweep.csv` 两个文件，看文件名，作者对做空盈亏和资金费做过检查。它们正是我们关心的量，但内容未读（见 §4）。

## 4. 为什么没有做逐事件复跑（设计第 6 节要求“复跑管线”）

- 它的逐事件文件（如 `listing_events_enriched.csv`，含逐币前向收益列）**包含我们 55 条留出事件的结果**。规则是“留出文件不下载、最多只能打开一次”（F25），留出按 sha256(baseAsset) 首字节 mod 5 == 0 判定。
- 若要复跑，可行做法是：下载时在内存里先按同一哈希规则丢弃命中行，再落盘和显示。这样留出行不进入我们的数据，但下载时这些行仍会经过内存。这是对留出规则的一次解释，不可撤回，所以先请你决定，再做。
- 已经发生的接触：作者 README 的汇总数含留出事件（约占 470 条的 12%），我们和总控都已读过。这是对留出的间接、汇总层面的暴露，以后用这 55 条做确认时要注明。检索子代理列文件树时，看到过缓存目录里若干按币命名的文件名，没有任何数值；执行模型没有看到这些名字。

## 5. 顺带：“公告前 3 天在其他交易所中位 +24.4%”

只描述，不当策略。它需要逐事件的公告时刻与其他交易所价格，与 §4 同样受留出限制，本次没有做。机制上，“公告前买入”要么依赖提前预测上币，要么接近内幕信息（外部研究称约四分之一的 Coinbase 新币有可疑的上市前买入）；按项目范围，只研究公开可见的链上积累，不研究内幕信息。
