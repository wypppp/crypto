## 1. 为什么现在就录

- 链上**成交**以后都能从 Dune 补取。但“我们当时什么时候收到、看到了什么、哪些请求没成功、哪些接口在限流”补不了（GPT G01）。
- 链外的榜单、推广、热搜、帖子，大多数接口只给“当前”的状态，不给历史。今天不录，今天的数据就永远没有了。
- 这些数据是 F（注意力分配）、H（热点时间差）、K（影子机器人）的来源，也是以后任何用到它们的规则做前向检验的数据。
- 代价是时间：晚开一天，就永久少一天样本。

### 2.1 中文热榜

GPT 第二批资料准备的结论（10-12）：
- 微博：服务协议把未经同意的自动化抓取列为受限行为。不直接抓。
- 抖音：官方开放平台有热点词与上升词接口，约两小时刷新，需要申请权限。
- 百度、知乎：没有核到合适的官方接口与条款。
- 第三方聚合：天行的微博热搜“每半小时更新”、抖音热搜“每 3 分钟更新”，按会员档计调用次数；UApiPro 按次付费。上游授权、历史完整性都没核清。

**可选做法**（交用户定，§8）：
1. 只拉 GitHub 微博热搜存档，改为每 5 分钟拉一次，记下每次新提交到达的时刻。免费；存档本身仍晚 2～6 小时（F138）。
2. 加一个付费聚合源（30 分钟或 3 分钟粒度）。条款与上游授权先核。
3. 申请抖音官方接口（约两小时粒度）。
4. 用户自己的观察记录（H 第三段）。

### 2.2 链上事件到达时刻（新增）

- **做什么**：订阅公开的链上事件流（例如对 pump 曲线程序与 PumpSwap 程序的日志订阅），每收到一个事件，记下交易签名、slot、我们收到的时刻（本机单调时钟加 UTC）、来源端点。另记断线、重连、限流、错误。
- **为什么**：Dune 只能给出块时间，给不出我们当时什么时候能看到。没有它，任何“按事件进场”的结论都默认我们和最快的人同时看到。
- **边界**：只收不发，不构造、不发送任何交易，不付费买加速服务。费用与限速由执行端核（公共端点通常有限速；付费流服务另议）。
- 以后的 K（影子机器人）在这一路的基础上加“判断与模拟交易”的时刻，单独写卡。

### 2.3 用户自己的热点观察记录（用户 10-13 启用）

用户说在中文热点上“我有位置”。没有合规的分钟级中文热榜来源时，这是测它最直接的办法（H 第三段）。

**每条记录的字段**：

| 字段 | 说明 |
|---|---|
| 记录时刻 | 工具自动写入，UTC 与北京时间各一列；不手填 |
| 在哪看到 | 平台、群、账号或链接 |
| 看到了什么 | 一句话 |
| 会不会出币 | 是、否、不确定 |
| 预计的币名或关键词 | 可以写几个 |
| 预计在哪 | 链与平台，例如 pump.fun、four.meme；不确定就写“不确定” |
| 把握 | 1～5 |
| 来源方式 | “直接记录”或“转录”；转录的另记原始时刻与原始载体 |
| 备注 | 可空 |

**规则**：
1. **先记再查**：看到热点就记，在查任何币、价格或链上数据之前记。
2. **只追加，不修改**：记错了就新加一行更正，不改旧行。工具给每行加上前一行的哈希，改动可被发现。
3. **手机上**：先发给自己一条消息（用服务器记时刻的应用），当天转录进记录，标“转录”并写原始时刻。
4. **不进公开仓库**：记录存在本机被 `.gitignore` 排除的目录里；每周只把清单与哈希提交进仓库。
5. **存而不读**：记录与链上同名币的对照，属于前向批次数据的读取，按 §6 在 H 第三段的卡冻结并登记之后才做。用户自己当然可以翻看自己的记录；不能做的是在卡冻结前拿它去对链上结果。

**执行端要做的**：一个只追加的小工具（命令行一条命令记一条，自动时刻、哈希链）、记录格式说明、每周清单。

## 3. 存而不读

- **地位**：G 录到的数据都产生于 2026-10-05 之后，属于 DQ-37 前向批次的“未读盲留出”，受前向批次预登记第 2、3、6～12 条约束。
- **每次请求记**（GPT G02）：请求发出与收到的时刻；来源自带的时间字段；条目的稳定标识；缓存与分页信息；接口与字段结构的版本；原始返回；错误与 HTTP 状态。成功的 HTTP 也可能漏条目，所以“首次出现”只代表“这个来源、在这个频率下的首次出现”，不代表市场里第一次发生。
- **删改留痕**（GPT G06）：来源删除或修改了条目，新增一行墓碑记录，不覆盖旧行。首次收录、补录、估值字段分别标记。
- **怎么存**：按日写只追加的压缩 JSONL，写完不改；每天生成清单（文件名、行数、sha256）。
- **仓库是公开的**：原始数据不进仓库，只提交清单与哈希。社交帖子只存必要字段。
- **健康检查的输出白名单**（GPT G06）：只输出计数、成功率、缺口时长、字段结构摘要、通过或失败。不输出标题、币的标识、价格或任何正文。排错用构造的样例；真实异常明细一旦用于改代码，按前向批次预登记第 10 条登记暴露。
- **心跳**：每分钟一次。休眠、断网造成的缺口照实记录，不补造。

## 4. 在哪台机器跑

- **用户的电脑**：今天就能开始；休眠或关机时断档。
- **小云服务器**：不断档，每月花费不高。

默认先在用户的电脑上录，一两周后看断档情况再定（§8）。

## 5. 合规

- 只用公开接口或官方开放接口，遵守条款、robots 与文档限速，请求头写明用途。
- 不登录抓取需要登录的内容，不绕过反爬，不超用免费额度。
- 来源条款不明时先不录，记进来源决定表，交 GPT 核。robots 只说明抓取规则，不等于数据许可；供应商出售接口也不单独证明上游授权。

## 6. 读取规则：按现行前向批次规则滚动登记

v1 曾建议按日期哈希把录制日分成开发日与确认日。**撤回**（GPT G03）：同一个币、同一个题材、七天标签都跨日，开发日会读到确认日之后的信息，确认日也就不干净了。

改为按时间滚动（GPT G04、G05），这与前向批次预登记第 3、7、9 条一致，**不需要改冻结规则**：
1. 任何读取都先登记：读哪一段、用于哪张卡、卡的冻结时间。
2. 描述性的卡（F、H 第二段、K）可以在自己冻结之后，读一段**连续的早期录制**作开发数据。读过的那一段，连同同期的链上数据，对之后所有卡都降为开发数据。
3. 任何规则的确认，都用**该规则冻结之后**才开始的连续批次；确认结果成熟之前只看健康信息。
4. 跨边界按信息与结果窗清除：开发标签的结果窗伸进确认起点的，要么截掉标签，要么推迟确认起点；同一事件的副本不在两边同时出现。
5. 同一个确认批次可以由预先登记在同一试验族里的几张卡共用，多重比较一起控制。

**代价要说清楚**：读早期录制做描述，会让那一段的链上数据也变成开发数据，最早的干净确认批次相应后移。读多长一段，在 F 或 H 冻结时定。

## 7. 步骤

1. **来源决定表**：执行端逐个来源核条款、robots、限速、密钥，写成表：录、不录、待核，各附理由。
2. **写录制程序**：用构造的返回内容测过断网重试、限速退避、日切换、清单与哈希、墓碑记录、健康白名单。
3. **开录**：“录”的来源与 §2.2 的链上到达时刻今天就开始。
4. **每天**：健康检查（只出白名单内的内容）。**每周**：把清单与哈希提交进仓库。
5. **GPT 门 1 与开录并行**：录制不是分析，不必等审；审出问题从那天起改，之前录的照常保留。

## 8. 用户要定的事

1. 是否换到常开的服务器（每月有少量费用）。默认先用你的电脑。
2. 是否为 X 官方接口付费（粗算每月约 150 美元，规模可调）。默认不录 X。
3. 中文热榜选 §2.1 的哪几种做法。默认只拉 GitHub 存档。（你自己的热点观察记录已于 10-13 启用，见 §2.3。）

## 9. 不做什么

- 不读录到的内容，不做任何分析、回测或交易。
- 不录需要登录或违反条款的来源；不发送任何交易。
- 原始数据不进公开仓库。
