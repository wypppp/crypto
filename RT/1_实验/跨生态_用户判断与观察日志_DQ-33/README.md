## 2. 观察日志（现在就能用）

- **文件**：`观察/YYYY-Www.md`，每周一个（ISO 周），已建好 [2026-W40](观察/2026-W40.md)。每条一行，字段（10-03 起，取自[中文信息源地图](../../5_参考/检索记录/中文信息源地图_GPT_v1_1002.md) §10“一条线索的最小记录”）：

  | 字段 | 写什么 |
  |---|---|
  | 主题与具体事件 | “某市场新增”“某规则变更”“某梗首次关联合约”，不只写币名 |
  | 原始来源 | 链接、发布者、消息或帖子编号；截图须有时间与作者 |
  | 三个时间 | 原发时间、该渠道发帖时间、你实际收到时间；统一北京时间，保留原时区 |
  | 链与准确合约或市场 | 不只写同名代号；股票配对写两侧资产 |
  | 事实与推断 | 原文明确说了什么；传播者加了什么解释；你的假设 |
  | 商业关系 | 官方、项目持有人或顾问披露、合作标识、工具返佣链接、付费推广、未知 |
  | 首次传播时的市场状态 | 是否已可交易、流动性、当时涨幅（大致即可；要用价格时由执行模型按规格补取） |
  | 独立性 | 新的原始证据、同源转载、翻译、纯观点 |
  | 后续 | 改规则、更正、删除；失败和没兑现的也保留 |

  “预测”一列在题库冻结之前留空。合约地址是项目的公开信息，可以写；自己的钱包与持仓照旧不写（见下面“隐私”）。
- **标签**（初版；以后可以加，不改旧的）：上币与空投规则、项目方动作、社群与 KOL 热度、链上异动、交易所公告、股票代币与规则窗口、其他。
- **来源**：写链接；群聊或私聊写“平台＋群类型”，不写能识别个人的信息。
- **推送**：写完当天推送。git 提交时间是本地写的、可以改，**以 GitHub 记录的推送时间为准**；执行模型每周存一次推送记录，记录里带提交哈希，用来绑定内容。
- **隐私**（仓库是公开的）：不写钱包地址、交易号、账户和金额，**不写自己的持仓和打算做的交易**（总控 10-02 第四轮），不写能识别你身份的信息。参与账本的明细放在仓库外。
- **答题题库冻结之前，只写观察**，不写预测（总控 10-02 第四轮）。~~第一个题库随四周试攻（股票上链，DQ-34）的卡片一起冻结。~~ 10-03 改：DQ-34 转为被动（用户裁决第 3 条），第一个题库随 DQ-38（公开发行与 TGE）的卡片一起冻结。

## 3. 评分部分（四周试攻目标定下后写卡冻结）

| 项 | 设计 |
|---|---|
| 题库 | 按事先公开的规则产生（例如目标生态里每个新上币、每个毕业的币）。题量超过你能答的时候随机抽题，种子取规则指定的、之后才出现的区块哈希；抽中必答 |
| 截止 | 人和机器用同一个决策截止时点评分；截止前没答的，按冻结的默认规则记分 |
| 成交与对照 | 仓位按池子状态模拟能否成交；对照匹配信息截止、仓位和持有期 |
| 机器基线 | 在开发期的几个简单候选中比较后选出，然后锁定 |
| 评分 | 概率题用 Brier 分对基础比率；交易题按该类冻结交易规则扣成本后，对两条基线（全体、机器基线）的配对超额 |
| 统计 | 按币和叙事聚类的自助法（叙事标签由冻结规则产生，不由人临时判）；每 4 周一次的重复评分，事先登记校正方法 |
| 规则窗口的开窗条件（用户 10-02） | 该类冻结交易规则扣成本后，对两条基线的配对超额：单侧 80% 下界 >0，且点估计超过事先定的经济门槛；第一个窗口 ≤3,000 元；动用真钱按 02 §10.8 过门 2 |
| 时间 | 12 周后第一次评分；第一次评分只能筛出很强的判断力，不作停止依据 |

## 4. 公开写攻略（总控第三轮）

攻略不能代替日志。底线：披露持仓；写完后若干天内不卖出写到的币；不接受按读者交易额分成的激励；笔名不与公开仓库、钱包关联。
