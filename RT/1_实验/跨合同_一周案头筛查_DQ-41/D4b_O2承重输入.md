## 1. 结论

**两份合同都卡在同一个便宜的缺口上：v1 没有“币→曲线创建时刻”这一列，检验周与封存周无法在入口过滤。**补这张名单约 30～80 credits（一条 Dune 查询，含导出费）。补上之前，v1 一行都不能读。

补上之后：

- **O2b（DQ-40）**：冲刺集中度与 60 秒入场有偏差上界；退出须改到小时桶边界；随机删除对照还缺 mayhem 名单。→ **未识别**，补证项同上，另加 mayhem 名单（小查询，可并入同一条）。

两份合同都还缺账户重放器（DQ-37 待办第 6 项）。它是代码，不花 credits，但写完之前不能做资金竞争与账户读法。

## 2. v1 的事实（核自 SQL 与评估）

| 项 | 内容 |
|---|---|
| 分桶 | 建池后 [0, 300) 秒按 5 秒（S）；[300 秒, 7 天) 按 floor(建池后秒数／3600)（H，第 0 桶是 300～3,600 秒）；[7, 180) 天按日（D） |
| 桶首储备 | `q0_open`、`b0_open`＝桶内第一笔成交的**成交前**储备，取自成交事件本身记录的值；不受 LP 费少算的影响，含之前全部 boost 与加撤池的效果 |
| 桶末储备 | `q1_close`、`b1_close`＝最后一笔成交后的储备，由公式算出；买入时少算 LP 费（价格误差最大 0.184%），停在之后的 boost 与加撤池之前 |
| 排序 | 没有外层指令序号，同一交易里多笔成交时首末不唯一 |
| 缺的列 | 曲线创建时刻、mayhem 标志、费用、交易号、事件键 |
| vq | 07-15 18:07:32 之后建的池缺 vq；07-15～09-14 可由 InitBoost 扫描按池加回（本地已有 `raw/dune/SCAN23_BOOST_*`）；09-15～09-30 要 d 段补扫（约 40 credits） |
| 母体缺口 | 晚毕业（曲线创建后 90 天以上）1.75% 不在 v1；封存口径误挡 298 个池 |

“以桶首成交前储备作为某时刻的可成交状态”是本文的做法：o 秒发出的单子，最早面对的是 o 秒之后第一笔成交前的状态（DQ-35 快照契约的 `b{o}`）。v1 能给出桶边界上的 `b{o}`，桶内任意时刻给不出。
