## 2. EDGE 标定与原外推更正

同一对的 W 七个创建日共用一个截点。
建边窗为 [W 起前七天, W+1 周一)。
因此每对是 14 天，一共 42 天窗口。
SQL 接受七日母体，驱动没有逐创建日循环。
旧执行费倍数 7×14×3 重复计了创建日。
旧 1,233～1,377 执行费估计已撤回。

“一条查询”仍不等于“一次物理扫描”。
新 SQL 的转账表逻辑展开五次。
其中 SOL 建边四天，代币边仅创建后一天。
全量的种子成交与代币边会覆盖 W 的七天。
标定的 cost/4 是平均窗口日费用。
它不是纯转账表每个物理分区的报价。
[静态依赖核对](runs/a8_s3_static_diagnosis.json)。

新 SQL 的金额全部用原始整数。
SOL 的阈值为 50,000,000 lamports。
代币金额是对应币的原始单位，不称 lamports。
扇出改精确不同接收方数，准确执行 >200 规则。
完整行与四列输出都用十六进制校验和。
它避免 API 数字类型再次丢失校验和低位。
[Dune 转账表字段](https://docs.dune.com/data-catalog/curated/token-transfers/solana/solana-token-transfers)。

首次标定已完成，执行费为 13.040147059。
平均窗口日为 3.260037，未越过 14.95 上限。
平台终态出现时已超过 85% 提前撤单点。
它说明两秒轮询仍可能跨过触发点后直接完成。
第二次也完成，执行费为 7.273088236。
双跑全部结构字段与两个校验和相同。
结果 1,126 行：S 185、G 912、T 29。
缺端点、缺扇出、重复键和前缀碰撞均为零。
平均窗口日费为 1.818272～3.260037。
高价比低价约高79%。
不能只拿低价作稳定单价。
[平台证据](runs/a8_measurement_manifest.json)。

实际身份继续保留完整钱包地址。
四列为 kind、a、b、x。
前缀只估体积、检查窗口内碰撞。
即使窗口碰撞为零，也不覆盖孤立钱包或跨对。
直接用前缀算实体哈希会改变真并列排序。

## 3. 统计量 SQL 昂贵的原因

明细与统计量 SQL 都含 185 行 emap VALUES。
文本分别为 48,898 和 49,605 bytes。
VALUES 大小接近，不足以解释 17 倍费用差。

从最终 out 逐层展开，成交分支引用 81 次。
池、PumpSwap 买入也各 81 次，毕业为 82 次。
明细版各为一次，创建表引用为六次。
这些是语法上的逻辑展开数，不是实际扫描数。
没有付费执行计划，不能给每项归因百分比。
[结构原件](runs/a8_s3_static_diagnosis.json)。

重复路径主要是 sr 同时流向 ss、rx 与多个 N。
分箱 bd 又反复引用 lb，放大上游状态计算。
wq 的全局排序与 count(*) OVER () 需要汇合。
它们是定义所需的分位数，不能直接分区改算法。
[Trino CTE 内联规则](https://trino.io/docs/current/sql/select.html#with-clause)。

原统计量 SQL 按要求保持原样。
本轮没有执行它，也没有把取消费用当完成价。

## 4. 本机冻结参照路线草稿

推荐把标签、实体首笔、分箱和统计放回本机。
SQL 只出 B、A、E、K 四类行。
B 是曲线钱包×币的首笔成熟买入及状态。
A 是 PumpSwap 同粒度的首笔成熟买入。
E 保留所有允许域内的毕业事件。
K 保留母体币及创建时点，包括零事件币。

状态仍需要全部曲线买卖的净额窗口。
因此不能只扫描“被导出的那一笔”。
成熟先过滤，再按完整链上键取钱包首笔。
实体归并后，再调用冻结 label/collapse。
两个阶段合并选择实体×币的首笔。
保留完整交易号，准确执行同交易自身排除。
[草稿 SQL](sql/A8DRAFT_S3_FIRST_0811_p002.sql)、[生成器](s3_first_extract.py)、[本机实现](s3_first_local.py)。

首笔压缩的语义需要验证，统计内核可减少重复审阅。
十二组随机数据与手算用例均逐项相等。
真实样本由 16,145 行压为 4,540 行。
其中 B 3,483、A 903、E 3、K 151。
N/C/G 与完整明细参照相同，删除 W+1 不改选集。
真实 C/G 仍为空，新 SQL 也未在 Dune 执行。
[本机证据](runs/a8_first_local_check.json)。

旧样本只有交易号前 16 位。
该样本压缩 CSV 为 0.752 MB，gzip 为 0.331 MB。
换完整交易号后，CSV 上沿为 1.068 MB。
这里只按每个交易号最多增加 72 字节估计。

## 5. 下载最少路线与热点

EDGE 还能删掉必被参照跳过的高扇出 G。
四列重复 T 也可去重，完整 S/T 对手仍保留。
因此服务节点的度数判断保持原样。
已付 A7-03 样本从 815 行变为 237 行。
CSV 从 0.116 MB 变为 0.022536 MB。
实体映射完全相同；新 SQL 未执行。
[压缩草稿](edge_sgt_min_download.py)。

若导出确实收费，下载量最小的候选路线为：
EDGE 的有效四列，加 S3 的 C/G/N 统计量。
它仍需要实体映射上传和统计 SQL 的性能重构。
现统计 SQL 无完成价，这条路线暂不能诚实报价。
只给总价公式，不冒充已有标定。

恢复下载代码已支持每页原子保存。
它绑定 execution、SQL 哈希、列、行数与页哈希。
网络中断直接退出，再批准后只取缺页。
服务端缩小页面时按 next_offset 推进。
每页默认 1,000 行；全程不重新执行 SQL。
[实现](dune_get_resume.py)、[离线测试](test_dune_get_resume.py)。
[Dune 分页说明](https://docs.dune.com/api-reference/executions/pagination)。

CSV gzip 只减少本地占用，不能当作网络量。
当前 API 用 JSON 拉取，字段名也占流量。
报价中的 CSV MB 是模型基准，网络量会更大。
不承诺在热点上几分钟完成数 GB 下载。
只下有效 EDGE 与统计量更适合热点。
首笔路线应分对下载，按页恢复、按对计算。
完整规模的本机内存与吞吐尚未验证。
