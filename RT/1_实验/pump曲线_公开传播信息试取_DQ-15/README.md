# pump 曲线：公开传播信息试取（DQ-15）

> **状态：进行中（第一步，用户 09-22 批准）**｜2026-09-22｜来源：主审 09-22"有边界的新信息发现"方案，执行方批判性吸收后补充 4 点（见 §6）｜现状以 [总入口](../../00_总入口.md) 为准

## 1. 这一轮只回答一个问题

**是否存在可研究的公开传播信息？**不判断有没有优势。

下一轮研究的主问题是：在交易者实际收到信息之后，能否区分"仍有可参与价值的需求增长"和"价格已经兑现、后来者承担损失"。本卡只做第一步，确认这类信息拿不拿得到、够不够研究。不要求消息早于起涨或点火，也不把"预测到买家增加"当成盈利证据。

## 2. 总入口 §6 第 5 条要求的四项

## 4. 第一步：来源试取

### 4.1 候选平台（先做可得性检查，再选 ≤3 个做完整取数）

| 平台 | 为什么列入 | 已知风险 |
|---|---|---|
| Telegram 公开频道（人工喊单/研究类） | 目前最常见的 meme 传播渠道之一；`t.me/s` 可随机访问历史（F100） | 便利样本多为机器人或已停更；要换一种发现方法，不能重复 F100 的 4 个频道 |
| 4chan /biz/ 第三方档案 | 连续档案，帖子不可编辑，原始时间戳，失败帖同样保留 | 信噪比低；档案站可能不全 |
| Reddit（Arctic Shift 档案等） | 按版块、时间窗连续取帖和评论，带编辑标记 | 版块审核会删帖；pump 币提及量未知 |
| Farcaster | 协议级公开历史，帖子带时间戳 | 用户量小 |
| Bluesky 公开搜索 | 公开接口可按时间搜索 | 加密圈规模小 |
| X / Twitter | 最主要的 KOL 渠道 | **没有免费历史接口，本卡不覆盖**。这是覆盖上的最大缺口，结论须注明 |

### 4.2 每个入选来源的合格条件（四条全满足）

1. **mint 映射明确**：消息里有合约地址，或能唯一对应到某个 mint；同名币不能靠名称合并。
2. **时间可区分**：发布时间有原始时间戳；可判断是否被编辑；前向留存时另记实际取得时间。
3. **连续完整**：取完整连续窗口，保留全部相关消息（包括提到后来失败的币），能估计删帖或漏收。
4. **有新增内容**：内容不只是重述价格、成交量、持币数。自动行情播报另列一类，不算作满足本条。

### 4.3 事件分母与盲化

- A 周（06-01～07 创建）全部 191,192 个发行币的 mint 清单，用于统计"来源提到了多少 A 周币"。
- H1 的 308 个触发（mint 与触发时刻），用于统计覆盖率，以及消息相对链上触发的先后。
- 检索方只拿到 mint 清单和触发时刻，**不拿任何收益或赢家标签**。收益只在第二步、内容分类冻结之后才连接。

### 4.4 交付

每个来源一份原始记录（可复查的原始页面/接口返回），加一张表：窗口、消息数、ID/编号缺口、提到的 pump 合约数、落在 A 周的币数、H1 触发覆盖数、消息相对触发的时间分布，以及内容类型的盲分类样本。最后写一页结论：哪个来源合格、哪个不合格、为什么。

## 5. 之后的步骤（本卡不批准，须各自再定）

- **第二步**：从消息内容形成至多两个假说。每个写清：谁会因此改变行为；为什么这种变化还没完全反映在可成交价格里；什么观察能否定它。拿不出具体区别，就不做特征工程。
- **第三步**：只为有依据的假说检验简单参与规则。恢复完整事件分母（失败、无法成交、重复宣传、同一事件涉及多个币），按实际可获知时刻加现实延迟计算新仓位收益。检查三件事：相对同时点简单基准的增量；扣成本后的经济空间与尾部集中；按频率、并发、单币容量和周转估计账户能部署多少资金。财富路径从这里开始算。
- **第四步**：满足条件才冻结并使用确认样本。门槛按候选的频率、尾部集中、成本和资金需求制定，不搬用旧的 1.03。**若历史来源覆盖到 7 月，4 个封存周（06-15～07-12）可直接作确认样本**；否则用前向数据。
