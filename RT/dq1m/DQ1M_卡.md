## 决策

**只回答一个问题**：在 pump curve 阶段用固定金额买入、按一条冻结规则退出，右尾（≥10 倍的可退出结果）在一个**完整发行分母**里是否存在、且数量不止一两个？

| 分支 | 条件 | 下一步 |
|---|---|---|
| **继续** | 见下方"判据·继续" | 写选择假设卡（事前特征），对象限本切片 |
| **暂停** | 见下方"判据·暂停" | DQ-1 线路暂停，转其他母体；已花额度记账 |

**对百万目标的贡献**：先确认这条路上有没有可兑现的右尾。**本轮不回答"能不能事前选中"**，选择问题留给下一张卡。

## 一、样本（分母不按结局筛选）

- **发行定义**：`pump_evt_createevent` 中，创建日期在 **2026-06-01 至 2026-06-07**（7 天）的全部 mint。
- **计价**：只保留 SOL 计价（`quote_mint` 为空，或等于系统默认地址 `11111111111111111111111111111111`）。USDC 计价单列计数后排除。
- **必须包含**：不毕业的、没有成交的、只有创建者买入的币。**禁止**按"后来毕业"或"后来迁往 PumpSwap"反向筛选样本。
- **毕业的币**：继续追踪 PumpSwap 分支（`pump_call_migrate*` 或 `pump_evt_completepumpammmigrationevent` 给出池地址，再用 `pump_amm_evt_buyevent` / `sellevent` 的池储备计价）。
- **窗口**：每个 mint 自创建起 **60 天**。最后一个 cohort 日为 06-07，故行情扫描范围是 **2026-06-01 至 2026-08-06**（67 天）。

**（v1.1 新增）对照组**：在完整分母之外，另单列"后来毕业"的子集，用同样的规则计算，以便与 2026-05～07 毕业币基线（F54：5 分钟入场后 ≥10× 占 6.74%，其中容量 ≥$1,400 的仅 0.12%）直接比较。**这只是对照，不得用它替换完整分母。**

> 分母口径写进结果时必须给出：总发行数、无成交数、无法入场数、毕业数、USDC 排除数、异常排除数。这几个数相加应等于总发行数。

## 二、金额、入场、退出（全部冻结）

| 项 | 规则 |
|---|---|
| **金额** | 固定 Q = **0.5 SOL**，每个可入场的 mint 各投一次，互不复投 |
| **入场时点** | 创建后 **30 分钟**（与 DQ-2 的 a30 一致）。取该时点前最后一笔成交后的储备状态计价 |
| **无法入场** | 该时点前没有任何成交 → 记"无法入场"，**留在分母里**，不计入倍数分布 |
| **买入数量** | 按当时虚拟储备的恒定乘积算 Q 买入所得代币数，扣当时事件中的费率字段；费率字段缺失的时期记为未知并按 0 费计算，结果里单独标注 |
| **退出规则（冻结一条）** | **T50**：逐日取当日最后一笔成交价，跌破"入场价与此后各日最高价中较高者"的 50% 时，按次日首笔成交的储备状态卖出全部持仓；60 天内未触发则按窗口末最后一笔成交卖出 |
| **卖出计价** | 同样按当时储备算卖出所得 SOL，扣费。迁移后用 PumpSwap 池储备 |
| **多口径报告（v1.1 新增）** | 同一次扫描内，对每个 mint 另报 **2 小时、24 小时、7 天、30 天、60 天** 五个口径的 M\* 与 Mπ。这是零边际成本的增列，用来**检验**"短期涨得多的后续也涨得多"，而不是假定它成立。须报告短口径与长口径的秩相关，以及"2 小时内 ≥2× 者"在 60 天口径下的结果分布 |
| **产出三个数** | **Mπ_T50**＝固定金额按 T50 退出的所得 ÷ Q（可退出倍数）；**Mπ60**＝持有到窗口末；**M\***＝窗口内最高成交价 ÷ 入场价（**零规模事后代理，不是收益**） |

**M\* 与 Mπ 必须分列。**结论只能建立在 Mπ 上，M\* 只用来显示"事后最高点与可兑现之间的差距"。

## 三、未知值与异常（不得裁剪）

| 情况 | 处理 |
|---|---|
| 虚拟 SOL 储备 > 120 SOL。**校准显示这占 2026-06-15 全天成交的 3.45%，当日最大 2,052 SOL（F55），不是个别现象** | **标记为 anomaly，按 `mayhem_mode` 字段分组单列统计**。不裁到 115 SOL，也不当作暴涨证据。若与 `mayhem_mode` 一一对应，则作为独立一类报告；否则取 2–3 个样本 mint 的原始事件核实后再定 |
| 虚拟储备为 0 或代币储备为 0 | 标 anomaly，同上 |
| 毕业但找不到 PumpSwap 池，或池已被撤走 | 记"退出不可行"，单列计数，不按 0 计 |
| 迁移事件缺失但有建池事件 | 用建池事件的池地址，并标注来源不同 |
| 计价币非 SOL | 排除并计数 |
| 窗口内行情提前终止 | 按最后一笔成交退出，标注"行情终止" |

**任何一类的占比超过 30%，直接判为口径不可解释，进入"暂停"。**

## 四、判据（冻结）

**继续**，须同时满足：

1. Mπ_T50 ≥ 10 的 mint **至少 5 个**，且其中不含被标记为 anomaly 的币；
2. 这 5 个及以上的币不集中在同一天创建（至少来自 2 个不同的创建日）；
3. "无法入场"+"退出不可行"+anomaly 合计 ≤ 30%。

**暂停**，满足任一：

1. Mπ_T50 ≥ 10 的为 0，或只有 1–2 个；
2. 上述合计比例 > 30%；
3. 实际额度消耗超过 600 credits 且仍未拿到完整窗口结果。

## 五、必须同时报告的两件事

- **容量代理**：每个进入 Mπ 分布的币，记录入场时点的虚拟 SOL 储备，以及 Q ÷ 该储备的比值。退出日同样记录。这决定 Q 能不能放大。
- **全买策略的资金需求**：cohort 天数 × 当日发行数 × Q。按 2026 年每日约 3 万个发行估算，一天就需要约 15,000 SOL，**远超 11 万元的资金上限**。所以本轮即使"继续"，也只支持去做选择假设，不支持机械全买。这句话必须写进结果。

## 六、额度预算

**已知成本**（实测，来自账户用量导出，F52）：

- credits ≈ **CPU 秒 × 0.01177**，与返回行数几乎无关；每次执行另有约 0.2 credits 的下限；
- curve 成交表单日分区：约 **1.69 GB、0.77 credits**；
- CSV 下载：约 1.7e-5 credits/数据点，可忽略；
- 已用 8.061 / 2,500，余额约 **2,492**。

**尚不可靠的部分**：PumpSwap 买卖事件的单日扫描成本、按 mint 分组做窗口函数带来的 CPU 增量。两者都没测过。

**预算安排**：

| 步骤 | 内容 | 预算 |
|---|---|---|
| 0 | 校准查询 C1、C2（各一个单日分区） | **已完成，实耗 0.7885 credits** |
| 1 | 按校准结果重估总成本 | **已完成：67 天双表约 53 credits** |
| 2 | 正式测量 | ≤400 credits（估计 53–150，留出重跑与分批余量） |
| — | 硬上限 | 合计 600 credits，超出即停并记账 |

**预算不足时的收缩顺序**（禁止缩短观察窗口到 45 天以下）：

1. cohort 由 7 天缩到 3 天（06-01、06-04、06-07）；
2. 对 mint 按哈希预抽样 20%，抽样规则写死并留档；
3. 窗口由 60 天缩到 45 天；
4. 仍不够则停止，不再收缩。
