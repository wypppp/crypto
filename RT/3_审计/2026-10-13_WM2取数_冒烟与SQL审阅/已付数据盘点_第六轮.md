# 已付数据盘点：本机已存的取数结果能否用于 WM2（总控第六轮第三节）

> 执行模型，2026-10-14。0 credits。只读了文件头（列名）、Dune 状态文件里的行数、各实验的 SQL 日期围栏与 README；**没有读任何数据行，没有看任何盈亏。**
> 清单原件：本机 `raw/` 下共 361 个结果文件（pump 相关实验）；按列名筛出带钱包字段的 75 个，其余都是币级、池级或桶级汇总。

## 1. 结论先行

1. **本机没有一份数据能直接算 S3。**S3 要的是：六个窗口周里每个钱包在每个币上的首笔买入（顺序键、时刻、买入当时的曲线进度、前 60 秒净买入、本笔大小），加上每个币的毕业事件，以及事前的实体关系。已存数据要么没有钱包字段，要么只覆盖部分钱包、部分币，而且都没有买入当时的状态。
2. **与 WM2 窗口重合的只有三处，都不完整**：
   - 第二对的 W+1 周（08-03～08-09）：DQ-26 的排名数据。全部币有币级汇总，钱包级只有 3,817 个选定钱包；成交只到 08-16。
   - 同一周的 08-04、08-05：DQ-28 的同槽买家数据，只含与创建同一 slot 买入的钱包。
   - 第一对的 W+1 周（06-01～06-07）：DQ-21 的 WM 与 S0、S1，都是币级或“币 × 群体”汇总。
3. **第一对的 W（05-25）、第二对的 W（07-27）、第三对的两周（08-10、08-17）没有任何钱包级数据。**
4. **毕业时刻**：DQ-35 v1 的 GRADPRE 有 2025-03～2026-09 全部毕业币的完成时刻，但没有毕业交易号与触发者；它的提取 SQL 未审，且有“代号窗口截短母体”的已知缺陷（DQ-35 README §1a 第 1 条）。
5. 所以 S3 仍要取数。§4 列出只为 S3 取数的最小清单与费用估计，供定方案。

## 3. S3 要什么，已有数据缺什么

| S3 要的 | 来源 | 已有数据 |
|---|---|---|
| 每个“实体 × 币”的首笔成熟买入（顺序键、时刻） | 全部钱包、W 与 W+1 的全部抽样币 | 只有 DQ-26 选定钱包在一周的首买时差，没有顺序键 |
| 买入当时的状态分箱：曲线进度、前 60 秒净买入、本笔大小、UTC 小时 | 逐笔成交 | 没有 |
| 毕业事件：时刻、交易号、触发者（命中与自身触发） | 毕业事件表 | DQ-35 v1 只有完成时刻 |

| 六个窗口周的全覆盖 | — | 没有一周完整 |

## 4. 只为 S3 取数的最小清单（估计，没有执行）

S3 不需要成本，也不需要现金合计，只要首笔买入、毕业事件与事前关系。可以把汇总版再收窄：

| 层 | 内容 | 估计（冒烟实测外推） |
|---|---|---|
| COIN | 抽样币与毕业事件的键、交易号、触发者 | 6 条，每条约 3～10 |
| CYCC 只出首笔买入 | 钱包 × 币：首买的键、时刻、现金、K、进度、前 60 秒净买入、是否在毕业交易里 | 6 周 × 约 77 万行 × 约 120 字节，约 1,300 |
| CYCA 只出首笔买入 | 同上（PumpSwap 阶段；不可能命中毕业，只用于“合格”计数与分层） | 约 1,000 |
| EDGE 事前图 | v3 的 S、G、C、T，三对各一次 | 未实测；等 1% 试跑 |

合计约 2,500～3,000。本账号本期剩 1,031。按新规则，每层先在 1% 以内的范围试跑一次，按实耗外推，报批后才放大。
