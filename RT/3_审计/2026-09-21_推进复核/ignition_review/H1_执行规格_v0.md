# H1 首版执行规格：从事件枚举到经济判断

2026-09-21，主审给执行方的具体方案。A/B 都是已打开开发数据；本规格在已知六例之后提出，只限制接下来继续搜索的自由度，不是独立预注册证据。当前未运行 Dune 查询，也未占用确认样本。

## 1. 首版只测一个明确规则

**买入突然放大规则**：在币龄 `[30 分钟, 24.5 小时)`，首次出现买入净注入场所 ≥4 SOL，且此前 30 分钟买入净注入合计 <4 SOL 的合格交易。每币最多一个事件、一笔模拟仓位。失败或不交易后不向未来寻找该币下一次更好的触发。

- 4 SOL 沿用已有案例示意阈值；新增的低活跃定义是“当前买入超过前半小时全部买入”，用同一尺度表达突然放大，不再增加任意笔数/涨幅条件。它并未证明优于别的阈值。
- 前窗口为 `[t−1800s, t)`，同秒但在当前交易之前的交易按链上顺序纳入；同秒之后的交易排除。严格说这是按 `(block_time, slot, tx_index)` 排列的半开事件窗口，不是用全秒聚合提前看到整秒。
- 当前交易的全部指令执行完才能知道信号；入场不得使用该交易中间状态。多笔买入在同一交易里按同一 mint 合计，含卖出或流动性增减/迁移的混合交易单列为不适用，不混成一笔普通买入。枚举时保留排除原因与数量。
- 本地 `trades.csv.sol` 是交易级场所余额净变化，只用作六例实现对照。生产查询须从解码 swap 重建同义的净流入；不得把用户含费付款、池净流入、LP 加仓混用。三例的首次触发已从原始日志确认含买入指令；这不等于其余交易都已解码验证。
- 这一版的 BUvu 触发在原入场后 **0.638h**，不回填成叙事中的 3.12h。GDP 为 3.648h，B1C2 为 7.549h。三个失败对照未触发。三名赢家是规则开发来源，不能用其命中率证明选择有效。

**人群**：A 周创建的 SOL 计价币，监测各币上述币龄窗口；不能直接拿 F2 的约 1.4 万活跃币当所有发行币。F2 在创建后 30 分钟筛掉的对象可能之后才启动。非 SOL 或执行模型不支持的对象显式列出，不能按未来是否存活、有赢家标签或路径完整与否筛人群。

## 2. 先做事件枚举，不把全套收益塞进第一条 SQL

S0 仅取创建时间、场所映射和必要事件，输出每币首个合格事件与质检计数。最低字段：mint、created_at、signal_time、slot、tx_index、signature、场所、净流入、前 30 分钟买入合计、主体地址、排除/缺失原因。额外输出发行数、可监测数、触发数、不可判定数；不接收益标签。触发前后储备留给 S1。单日草稿与运行说明在 [SQL 目录](../../../1_实验/pump曲线_案例时序与点火跟随_H1/sql/README.md)，未在 Dune 执行。

先用同一实现核对六例，再以 **6 月 1 日创建队列、仅其信号监测窗口**作为成本冒烟。它是开发数据，不具有额外验证身份。确认实耗、行数与映射后分日扩大 A 周；不能因为 LIMIT 输出少就假定扫描成本低。B 不在首条查询里。

S1 才为触发名单取所需状态路径并计算收益。尽量复用可验证的路径构造；不复制 F2 的旧排序、旧 +30 分钟筛选和原仓位回收。少量本地原始交易用于核入场/止损附近状态，至少包含下跌、连续同秒交易和迁移边界。程序失败、缺失和不可成交对象都保留在触发分母中。

## 3. 经济口径固定

| 项 | 首版口径 |
|---|---|
| 主延迟 | **120 秒**，从触发交易完成的历史时刻起计；这是待部署核实的研究假设，不声称已测得端到端延迟 |
| 敏感性 | 30 秒、300 秒，全部报告。不能事后挑三档中最好的一档作为预先指定主结果；若只有 30 秒可行，须先证明该时延及其成本可实现 |
| 仓位 | 新买入 0.5 SOL，按实际延迟后的状态重新算得到的 token；不按原仓位收益除以涨幅折算 |
| 退出 | 新入场后的 50% 移动止损；峰值从新持仓开始，24 小时沉寂退出；最长新入场后 30 天。窗口不足列为删失，不把旧入场+24h当统一持有期 |
| 执行 | 明示信号可见与成交状态的时间假设；止损触发后按固定执行延迟取对应状态，不能只取未来第一笔而忽略同一延迟内其余交易；同秒/同交易顺序单独验证 |
| 成本 | 报协议费、仓位冲击、旧模型固定扣减 0.004 后的回收；0.004 不宣称覆盖本候选全部优先费/失败/MEV。另报剩余成本容忍空间，只对能翻转判断的费用做定点校准 |
| 基准 | 不交易保留现金，回收=1；另可描述与当时状态相似机会的差异，不能用“比负收益基准少亏”代替绝对正收益 |

解码层必须明示费用、储备与收益的单位。交易排序使用真实链上顺序；场所名称不能作为改变同秒先后关系的排序键。以上是执行要求，当前没有声称完整收益 SQL 已通过核验。

## 4. 首轮结果包与决定

同时交付事件数量、不同币/创建者/日期的数量、收益分布、失败点火、缺失/不成交数量、最大若干事件贡献、持有期和仓位重叠。已有三名种子赢家的贡献单列；剔除它们的结果也展示，用于辨认结果是否只是重述种子。移除最大贡献后变负不是自动否决右尾策略，但必须展示这种脆弱性与确认可行性。

**负结果**：可信执行下经济空间不足、且没有具体可负担的翻转证据，停止这版 H1 投入。不是因单次试验而宣告所有大单信息永远无效；也不因此默认启动阈值网格、H2 或新案例搜索。

**正结果**：开发均值 >1 只是进入候选评估。核查是否依赖事后选择、单一事件群、不可实现延迟、未计成本或超出本金的并发仓位；按事件频率、仓位与持有期估计对既定资金目标的经济意义，再决定是否值得占用现有一个候选名额。A/B 不能变回确认数据。

**不确定结果**：说明是哪一项误差或样本稀缺妨碍决定，只允许能翻转当前判断的定点补证；无此补证则以资源判断暂停，不无限延长开发。

## 5. 成本控制与并行工作

Dune 官方提供平台级单次查询 cost cap；本轮未验证项目账户的设置与实际生效。SQL 分区限制、小规模冒烟和取消请求都不能替代该设置，取消也不会退回已消耗计算。见[官方资料核验](dune_cost_note.md)。运行前记录使用的 engine、平台 cap、查询版本、窗口；运行后记 execution ID 与实耗。不能在 SQL 注释写“≤X credits”就宣称已有硬保护。

H1 是当前主线。H2、公开传播 B 保留为待用解释，当前不并行扩大采集；只有结果出现具体、当时可知的主体差异或传播证据，才评估其增量。H2 的钱包关系必须使用信号时点之前的图，不能使用点火后分币建立的连通分量。没有证据触发时，就不因“备选还没测”自动续开路线。
