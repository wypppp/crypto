## 1. 新的盈利集中度：算术对，分母与 F99 的排序描述需改

独立复算采用 A=`F2_dev.csv:b50`，B=`F1_val.csv:x50_24h`，剔除 `__SUMMARY__`，回收扣 0.004。

| 指标 | A | B |
|---|---:|---:|
| 币数 | 14,120 | 14,918 |
| 正盈利币数 | 788 | 816 |
| 前 5 占正盈利总额 | 26.7411% | 14.7481% |
| 前 50 占正盈利总额 | 59.0252% | 45.9537% |
| 全池平均回收 | 0.9719405 | 0.9475542 |

这些份额来自**等额仓位**的 `sum(max(R-1,0))`，不是全池净利润，也不是 F99① 新写的“容量×净收益”口径。亏损币没有进入该正盈利分母。它支持收益集中，不能据此认定事前一定可识别这些币。

容量加权口径的前 5 份额为 A 32.12% / B 10.13%，前 50 为 63.07% / 46.37%。见 [f99_checks.py](f99_checks.py) 与 [f99_checks.json](f99_checks.json)。

## 2. 六格预言机数字可复现，但解释不成立

未找到对方新计算的原脚本；[check_claims.py](check_claims.py) 用以下公式复现了全部六格及币数，输入哈希与结果见 [claims_results.json](claims_results.json)：

1. 容量人民币 `C = 0.025 × entry_x_sol × 69.76 × 7.1`。
2. 每币金额盈利 `P = C × (R_0.5SOL - 0.004 - 1)`。
3. 按 P 从高到低排序，整笔累加容量；超过本金时停止。

| 本金 | A 币数 / 估算盈利（元） | B 币数 / 估算盈利（元） |
|---|---:|---:|
| 10,000 | 7 / 314,050 | 10 / 101,918 |
| 30,000 | 21 / 437,589 | 21 / 170,522 |
| 1,000,000 | 788 / 864,945 | 816 / 587,271 |

限制直接影响结论：

- 原 SQL 买入量和卖出价值按 0.5 SOL 计算（如 `RT/dq7/sql/F2_dev.sql` 的 s4/s5）；放大至 C 后继续使用同一收益倍数，没有重算更大仓位的入场与退出冲击。容量是入场侧近似，不是完整执行认证。
- 此排序不是严格最优上界。同一静态线性模型允许部分投入、按单位资金收益排序时，1 万元可得到 A 336,601 / B 123,243 元，高于表内结果。这里也只是模型内比较。
- 容量在小本金下已经影响最优分配；“仍可能有足够经济空间”不等于“容量不构成约束”。预知赢家后跳过所有亏损交易，无法证明现实筛选中的摩擦不重要。
- 表内是某个发行周币群的后续收益；并非均在一周内到账。例如 A 的 3 万元组合含持有 17.50 天的币。没有多周并发现金账、资金增长、复利或制度稳定性的模拟。
- “三年 9,000 万—1.3 亿元”精确对应 **100 万元本金行 × 156 周**：B 91,614,241 / A 134,931,452 元。不能用来证明从 1 万元起步只需捕获约 1%。
- 即使上界严格成立，“捕获上界百分之几”也不是预测器难度、命中率或三年达标概率。

此外，`RT/dq1m/DQ1M_结果_v2.md` §4 在 09-16 已写“18 个赢家全部选中，投入 $1,423，毛利 $56,708”，并另列单币容量小。多币总机会可大于单币容量限制，不是本轮才出现的新发现。

可接受的更正是：**单币容量小不足以单独判定项目不可行；现实策略的容量、摩擦、误选与资金占用仍需联合评估。**不接受“只剩信息一个解释”。

## 3. DQ-14 的前提和冻结判据

8.50/11.83 小时、买家数 228/75 已按金额盈利排序前 20 复现。另一个语义问题：`pre_peak_pm` 是入场前最高价格相对入场价的倍数，不是从创建到入场的涨幅；原文的“入场前已涨 1.36×/1.15×”不能由该列得到。

A 周 F3 的 −0.0856037/+0.0839905 也已重建：按同币现有行顺序取相邻前后价格比，缺失的无成交区间被跨过，观测时间不等距。原 CSV 是区间末状态，`iv=11` 为 (7d,30d]。数值可复现不等于其机制解释或整类停止判据成立。

| 当前写法 | 审查结论 / 应采用的表述 |
|---|---|
| 峰值晚、起涨后仍有事后最高倍数，因此慢信息时间窗通过 | 支持挑选案例去检查。公开信息在何时出现、能否识别、实际参与后如何兑现仍未知；不应标为慢信息必要条件已通过 |
| 滞后 4/5 档有剩余倍数 | 检查点不等距，必须报告实际时间、各档样本数、样本如何变化、剩余量是未来最高价还是可执行策略收益；不能作为任意传播事件的收益折算表 |
| 新买家与未来价格负相关，所以链上代理无用 | 负相关可能包含反向选择或退出的信息，也可能受时间、活跃度、样本构造影响；本身既不能认定可交易，也不能认定无用 |
| 外部事件必须早于价格的实质变动 | 过强。价格已从 1 涨到 2，公开信号后仍可能走到 4，也可能提示回撤。应检验“实际观察时点之后的增量净收益”，同时控制当时已知状态 |
| 仅查 151 个事后赢家；覆盖 ≥30%/10% 决定是否可研究 | 阈值没有连接经济目标、事件频率、成本或确认样本量。低覆盖可能对应稀少但高价值事件，高覆盖也可能全是事后提及；先以相同检索强度查赢家与失败者 |
| 同一事件的多个币只计一份 | 以事件作为相关性分组是对的。必须保留其全部候选币及损益，冻结具体选币规则；不能每事件只保留事后最佳币 |
| 第四个角度为负，关闭整个信息类 | F82/F83 与 F99 大量共用开发数据，PF3 是另一窄场景；角度数不是独立证据数。允许预算结束后停止 B 路线投入，不将其包装成所有传播信息无效 |

**B 周已经是开发数据。**只在 A 周形成案例假说、再查 B，有助于发现不一致，但不能恢复 B 的独立验证资格。最终确认仍需未使用的数据或前向观测。

“只改 V 一律不做”也不能从旧特征的失败推出；“每项工作开工前必须报改善多少”会阻止尚未形成假说的探索。探索交付一个有证据来源、可被后续否定的候选或明确数据缺口；验证阶段再冻结量化判据。

PF3 原文是 [Money Leaves Clues 的 newsletter](https://moneyleavesclues.substack.com/p/inside-the-economics-of-pumpfun-call)，不是论文。其 Telegram 导出覆盖 2025-01-22 至 03-09；770 个 calls 仅 375 个有可用收益曲线，报告为未完整计入成本的毛收益。文中确实写 call 后 30 秒进入、5 分钟时中位亏损 27.6%，但不能据此否定全部跟随方式，更不能只凭负中位数否定右尾策略的期望收益。原文抓取记录见 `pf3_source.txt`。

## 4. 有限探索的具体推进

首批只用已打开 A 周，选三组事后高收益币及相似失败币作数据试取，避免一开始铺开 151 个赢家。失败对照只用入场已知状态作匹配；检索人员不接收组别与未来收益。这个极小样本只回答数据能否取得，不估计覆盖率或收益规律。

每个对象只记录：

1. mint 身份及原始证据；今天查到的名字、社交链接仅作导航。
2. 外部消息原文链接、公开时间、时区、是否编辑/转述，消息当时如何映射到该 mint。
3. 在同样检索强度下是否找到来源。未找到记“在本通道未检出”，不记“没有传播”。
4. 可回放价格在消息出现前后的位置；收益从消息可观察并加上实际参与延迟后计算。

首批之后按证据选择：

- 可同时还原成功与失败对象的当时事件：形成至多 1–2 条具体预测，再决定有分母的开发比较；不为了凑数生成候选。
- 只能查到今天的网页或事后热度：评价一个具体前向采集通道的成本与预计事件量；不继续无限历史考据。
- 没有具体、可负担的补救通道：停止本轮来源投入。

候选形成后，以可部署仓位、误选成本、剩余收益、机会频率和执行成本共同判断是否值得确认；只有关键经济判断依赖摩擦或容量时，才做对应校准。若本轮候选在构造正确后失败，且无一个有依据、足以翻转决定、在剩余预算内的补救，就停止本轮 B 路线，不自动给新解释、新名字追加预算。是否重启须有新的外部证据或资源条件。

这既保留发现环节，也提供有限的停止机制，不要求科学上穷尽一个无限的信息类别。

## 5. 首批公开来源试取已完成

低成本检索模型未接收收益/组别，对六个地址采用相同检索步骤；对应 [名单及配对](case_seed.csv)、[复现名单脚本](make_case_seed.py)、[检索结果](public_event_pilot.json)。本轮没有 Dune/Helius 请求，没有打开确认 cohort。

- 六个地址中，两个检出当前名称导航：GDP、Son Goku/GOKU。GDP 的地址映射见 [Coinbase 页面](https://www.coinbase.com/en-de/price/gdp-solana-d54653c5)，不回填为历史身份。
- GOKU 检出带本币地址的风险提示副本，页面显示 06-09；尚缺原始消息时区、原文版本/编辑证据与可回放的实际观察时点，不能视为已经找到可交易的早期事件。
- 主审核对 [BitMart 页面](https://www.bitmart.com/uk-UA/price/goku) 发现：同页 06-25 消息对应另一个 GOKU mint。检索员最初把两日都记成本币传播日期，已要求剔除。**按名称/符号合并会造成身份错误，须逐条按 mint 核实。**
- 其余四个在本轮精确检索中未检出，统一 Dexscreener 无密钥端点返回 `pairs:null`；不能把这解释为历史上没有传播。

这一极小样本不估计覆盖率，更不判断 B 成败。它改变了下一步的数据获取选择：**不扩成 151 个赢家的搜索引擎考据；优先判断一个固定消息源能否提供带原始时间与地址的连续档案，同时保留失败对象。**若没有可用历史档案，比较一个有限前向留存通道的成本与可验证事件量；不继续用今天的搜索可见性代替当时的信息。

选择消息源仍是开发阶段选择，必须记录搜索范围。确认阶段固定来源、采集规则、mint 映射和参与规则，不能只保存后来涨过的消息。该试取没有证明社会传播具有或不具有收益增量。
