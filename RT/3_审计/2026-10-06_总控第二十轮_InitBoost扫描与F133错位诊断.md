### C4. 第四节：F133 错位的结构

**结论：错位是确定的位置映射，不是随机打乱，也不是来自时间相邻的币。**（[诊断](../1_实验/pump毕业后_SOLMEMES复现_DQ-39/S0b_错位诊断.md)，只用元数据与时刻）

1. **每行的元数据属于谁**：7,575 行能唯一认领到本数据集的某个 token（其中认领到自己的 10 行）；1,040 行同名同代号有多个；345 行在本数据集里找不到。
2. **时间差**：所属 token 与本行 token 的创建时间差，绝对值中位 221 小时，与全体随机配对（226 小时）几乎一样，远大于同周随机配对（44 小时）。
3. **固定偏移**：按任何时间排序都没有固定偏移；按数据行序，所属位置与本行位置的相关达 0.94。查下去，规律是：按 token 首次出现的顺序编号，第 u 个 token 拿到第 10·⌊u/20⌋＋(u mod 10) 个 token 的元数据。8,960 行里 7,613 行符合；不符合的主要是重复 token 多出的 998 行。这像是按每页 10 条取元数据时，每页都重复了一次。

对论文的含义：所属 token 都在列表前一半，创建时刻与本行 token 几乎不相关，所以文本既不带本币信息，也几乎不带时间信息。论文的样本外测试（04-14～04-19 毕业）拿到的文本全部来自 04-10 之前创建的币。论文作者所用的数据是否同样错位，推不出。

另外，名称、代号、描述、图片一起错位；`token_uri` 与价格列跟着本行 token。所以 S1 的“正确文本”可以按 `token_uri` 去 IPFS 取。
