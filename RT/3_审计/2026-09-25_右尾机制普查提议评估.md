# 外部提议“右尾机制普查（RT-M0）”的评估

> 2026-09-25｜**讨论材料，不是项目决定**｜本页任何“下一步”都不是指令；只有经用户裁决并记入 [总入口](../00_总入口.md) §3.1 的才算数｜提议来自用户转来的外部模型意见（09-25），原文在用户消息中，§1 保留全部论点

## 1. 提议要点

- **问题重构**：不找“百倍币的共同特征”，而是找能产生巨大、可兑现右尾的**状态转变**，并分三问：
  - 科学：什么转变能产生右尾；
  - 预测：哪些转变在主要重估前留下痕迹；
  - 交易：这些痕迹能否在扣掉误选、成本、容量后改善三年财富路径。
- **基本事实**：
  - 价格是边际成交决定的；
  - 价格曾到 100 倍不等于能赚到 100 倍，研究单位应是“币 × 入场时点 × 仓位 × 退出规则”；
  - 极端右尾必然伴随状态变化，应看变化量和变化速度，不看静态水平；
  - 低基率下“能预测赢家”不等于“能赚钱”；
  - 信号必须在决策时刻可得；
  - 右尾很可能由多种机制产生，不存在统一特征。
- **机制族**：
  - M1 买家人数爆发；M2 购买力变化；M3 有效卖盘收缩；M4 可访问性扩张（如上所）；
  - M5 传播与反身性进入超临界；M6 协调资本或控制；M7 真实使用突变；M8 未知。
  - 现有数据源都重新定位为某些机制的“传感器”：钱包对应 M2/M6，注意力对应 M1/M5，MELT 对应 M6，交易所事件对应 M4，持仓集中度对应 M3/M6。
- **诊断**：项目的“候选 → 预登记 → 数据 → 经济检验 → 审计”很强，缺的是“观察到的右尾 → 机制 → 候选”这一层发现层，所以候选靠模型想象，一个接一个失败。
- **提议**：
  - **做法**：暂停新的交易策略卡，批准一次有限的 RT-M0。对象是已打开的 A/B 周里、+30 分钟入场后路径曾达约 100 倍的全部 27 个事件（11 + 16），每个配匹配的失败对照。
  - **步骤**：先定位“第一次与失败对照分叉”的时刻，再查这段时间发生了什么；每个机制都要列竞争解释；必须同时看 P(100×|M) 和 E[R|M]；不求统一特征。
  - **产物**：一张机制普查表（分叉时刻、机制、证据、竞争解释、观测量及其可得时间、领先时间、剩余右尾、同机制的失败案例、证据等级）。
- **自带的失败条件**（任一大规模出现即考虑停止 pump 百倍选择路线）：
  1. 机制极度异质，压缩不成少数几类；
  2. 可观测的状态变化多数不早于主要重估；
  3. 即使领先，剩余的可兑现右尾也不够覆盖误选、摩擦、容量和失败率。

## 3. 上位模型的评估

### 3.1 值得吸收的

1. **P(M|100×)、P(100×|M)、E[R|M] 三者分开**，以及“研究单位 = 币 × 时点 × 仓位 × 退出”。这是项目已付出代价学到的，提议表述得更清楚。
2. **把数据源当传感器、按机制组织**。以后评价一个数据源，先问它能感知哪个机制、能否历史回放、多少钱，而不是在数据源之间横向比较。
3. **三条失败条件**比“再测十个特征都失败”更接近真正的停止依据。尤其第 2、3 条（观测量不领先、领先后剩余右尾不够），可以把 10-16 的结束理由从“资源决定”加强为“结构性结论”。
4. **机制表必须有 UNKNOWN、必须有竞争解释**，防止为了填表编故事。

### 3.2 不同意或须修正的

1. **新意被高估**。“右尾 → 机制 → 观测量 → 完整分母检验”已经在 H1 跑过一次，而且恰好失败在提议自己的第 2、3 条：观测量（点火买入）与重估同时发生，延迟 120 秒跟进时剩余右尾已不够（0.911）。RT-M0 是把 H1 的 3 + 3 扩成 27 + 对照、并系统编码机制，不是项目第一次有发现层。
2. **可测性会污染“机制”结论**。27 个事件从入场到峰值通常只有数小时到数天（F99③：按容量 × 回收排序的前 20 个，峰值距入场中位 8.5/11.8 小时）。要领先这么快的重估，观测量只能来自链上或实时社媒。但链外档案大多不能按分钟回放（F85、F100、F106；X 未覆盖）。所以 M1/M4/M5（传播、可访问性）在历史上基本测不到，会被系统地归为 UNKNOWN 或误归为链上可见的 M6。
   - 须事先写明：“UNKNOWN 多”若来自测不到，是**不可判定**，不是“机制异质”；
   - 须事先写明：只在链上可测的机制内得出的结论，不能外推到整个右尾。
3. **27 个事件、8 类机制、几十个候选观测量**，在已被 DQ-1F、DQ-7、DQ-8、F93–F96、H1 反复看过的两周上，找出“领先”的东西几乎必然成功，也必然过拟合。
   - 机制编码规则要先写定，由两个模型独立编码并报告一致性；
   - 任何候选观测量要回到**完整分母**（A/B 周约 36 万个币）计 P(100×|O) 和 E[R|O]，再用封存周确认；
   - 完整分母要花钱：Dune 只剩约 356 且约 09-29 过期，之后要重新定额度。
4. **“先找机制、不先找信息源”这个顺序过于绝对**。对我们来说，瓶颈常常不是不知道机制，而是这个机制的传感器不能历史回放。应当两者联合：只研究有可回放传感器的机制；没有的，要么记“测不到”，要么改为**前向采集**（从现在开始记录，数月后才有样本）。后者是另一种项目，时间尺度不同。
5. **“暂停策略卡，批准 RT-M0”须按规则走**：它是新路线，要写进 `2_提案/`，经用户裁决并记入总入口 §3.1。它也不是 10-16 分支①要求的“DQ-17 合格材料”；若做，应作为用户对 10-16 选项的调整来裁定。

### 3.3 成功概率与成本（上位判断）

- **成功概率低**。已知证据指向：
  - 链上唯一清楚的分叉信号（点火）与重估同时发生（F101、F105）；
  - +30 分钟和各检查点的链上状态特征都没有转成收益（F83、F87、F93）；
  - 入场时控盘在失败币中反而更常见（F101⑥）；
  - 剩下可能领先的是点火前的资金准备（关联钱包在点火前收 SOL 等，M6），领先时间可能只有分钟级，而且本质是跟随协调拉盘。
  - 我的估计：27 个事件里，能在重估前数十分钟以上看到、且在完整分母中 P(100×|O) 显著富集的观测量，多半找不到或只有个位数事件支撑。
- **成本不高**：
  - 链上逐笔时序用 Helius（F101 为 6 个币约 1,820 credits，27 个事件 + 约 80 个对照约 3.5 万 credits，远低于剩余额度）；
  - 本地分析为主；Dune 只在完整分母那一步需要。
  - 主要成本是时间，约 2–3 周。
- **决策价值**：结果无论正负，都比“资源止损”更有信息量：
  - 如果多数事件落在失败条件 2、3，10-16 的结束理由就有了结构性依据；
  - 如果出现 1–2 个有领先时间和剩余右尾的机制，就产生一个有数据来源的候选，而不是模型想出来的。

### 3.4 若用户要做，最小可行版本（建议写进提案）

1. **第 0 步，零成本预检**：用已有的 A/B 价格面板（`dq8/raw/F3_devA.csv`、`F3_devB.csv` 等；先确认时间分辨率够用，不够就只做 A 周能做的部分），对 27 个事件量出“价格首次到入场价 2×、3× 的时刻”与“此后 `b50` 可兑现的剩余倍数”。如果重估一开始剩余的可兑现倍数就普遍不够，不管领先观测量是什么都救不回来，RT-M0 直接按失败条件 3 结束。
2. **范围**：
   - 只用 A/B 周，不开封存周；
   - 只用可回放的传感器（链上逐笔、资金往来；Telegram 公开频道按 F100② 可回放，可作补充）；
   - 测不到的机制记“不可判定”。
3. **事先写定**：分叉时刻的定义（相对匹配对照的规则）、机制编码表、两模型独立编码、竞争解释、停止条件（提议的三条，加“测不到占多数 → 不可判定 → 按原计划走分支③”）。
4. **交付**：机制普查表，以及三问的答案。答案是“没有”，就结束 pump 百倍选择路线；有 1–2 个，才另写候选卡，并在完整分母和封存周上检验。
5. **额度与时限**：Helius ≤5 万 credits；Dune 0（完整分母那一步另提需求）；≤2 周；10-16 前交。

### 3.5 对 10-16 的影响

维持原建议：**默认走分支③，理由写成资源裁定**。

如果用户在结束前还想做一次有限尝试，RT-M0 的最小版本是目前见过最合适的一项。原因有三：
- 它不依赖新的信息源；
- 它用的是已打开的数据；
- 它自带能把项目收住的失败条件。

它的优先级高于重开任何单一特征或数据源卡。先做第 0 步零成本预检，再决定是否花 Helius。
