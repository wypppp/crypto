# DQ-21 与旧 pump 回测：曲线卖出方向错误

2026-09-28。**这是估值缺陷，不是新策略结果。** 在 S1 一日冒烟后、两周固定退出和 DQ-21 关系收益检验之前发现。发现后已通知用户暂停旧 S1 样本过滤查询；用户先前收到的异步执行请求已在此期间完成（query 8848627，用户报 9.7502 credits），只作为计算成本样例，不使用其收益。

## 可独立复核的错误

设某时点曲线虚拟 SOL 储备为 `x`、虚拟代币储备为 `y`，卖回 `q` 个代币。按恒定乘积关系，卖出让代币储备**增加**，可得的手续费前 SOL 为 `x - x*y/(y+q)`。旧 SQL 的曲线分支使用 `x*y/(y-q)-x`，该式求的是从曲线**买到** `q` 个代币所需 SOL，方向相反。Pump [官方合约文档](https://github.com/pump-fun/pump-public-docs/blob/main/docs/PUMP_PROGRAM_README.md)明示卖出时虚拟 SOL 储备减少、虚拟代币储备增加。PumpSwap AMM 分支已用 `y+q`，本错误只在 `venue=0` 的曲线卖出分支。

用旧 S1 结果中 21 个入场后至 30 秒退出目标都没有新成交的曲线币独立检验：其退出状态与入场状态相同，旧 SQL 的回收与旧式子完全吻合；用正确式子重算，旧值高出回收比率中位 **0.03090**（约 3.09 个百分点，范围 2.34～3.13 个百分点）。在一日 669 个适用曲线币的同池立即卖回反事实中，旧式子多算的回收比率中位 **0.02460**，第 95 分位 **0.05661**，最大 **0.12664**。这些是同池对照的**公式误差**，不是全路径策略均值的修正额。复算见 [audit_curve_sell_direction.py](../1_实验/pump曲线_资金关系可构造性_DQ-21/audit_curve_sell_direction.py)与 `raw/s1/S1_curve_sell_direction_audit.json`。

又用本地既有 Helius 原件的 1,000 笔已落地曲线卖出作独立方向核对：从事件的交易后储备反推交易前 `x/y` 后，整数式 `floor(x*q/(y+q))` 对事件 `sol_amount` **1,000/1,000 精确到 lamport**；旧方向只在 147 笔小额/取整情形偶然相等，绝对误差中位 18,691,503 lamports。这一步未新增 Helius 调用，也不证明浮点 SQL 已复现链上所有取整与费用细节，但排除了把修正方向再写反。

## 已知影响范围

- DQ-21 S0/S1：创建币 371,312、适用币 137,181、`t3` 时刻、哈希和入场池储备的核验仍成立。S0 的 1,782 个“整笔卖出 ≥10 倍”、最佳退出 1.90/1.59/1.33、任何依赖 `sell_multiple` 的收益与崩盘标签**暂不引用**。价格路径定义的 7,848 个 420 秒病例超集不使用卖出公式，仍可作抽样框；旧 1,782 个标签全部包含在该超集，旧样本名单不会因为删除旧标签而少一行。修正后 10 倍币的数量与全路径回收仍未知。
- 仓库静态搜索发现同一 `y-q` 曲线卖出式出现在 DQ-1F、DQ-1M、DQ-7、DQ-8A、H1 的 SQL 或生成器，以及后继 DQ-19 等沿用 F3 面板的分析。它们的曲线卖出回收、胜者标签和相关经济判定须逐路线复核。**不能**仅凭公式对单笔卖出偏乐观就断言所有旧负结论仍成立：缺失值、样本纳入和阈值判定也可能变化。DQ-18 的毕业后 AMM 口径未在本次检查中发现这个曲线公式，但尚未做全面排除审计。
- R0 资金关系构造、早买名单与出资路径不调用此卖出估值，不因本缺陷改变；关系**预测收益**仍未测试。封存周未打开。

## 修复顺序

1. 保存所有已执行旧 SQL 与费用，不回写历史执行文件。将旧样本过滤 SQL 标记废弃，生成名字明确的新 SQL：只在曲线卖出分支改为 `y+q`，沿用已冻结的 S0 mint 名单，抽样权重始终从旧冻结表读取，不按修正后结果重新挑币。
2. 先跑一日修正版，核 695 个 mint、不受影响的入场列、以及没有新成交的同池卖回 21 笔；还要抽实际有买卖事件的币对照链上数量与费用。前述“已保存 SQL 与 S0 一致”不能替代此项独立卖出对账。
3. 一日通过后才决定两周全窗成本与执行形状。算出修正后的固定退出基础回收，再复核旧事实库中依赖此式子的结论。早期旧结论暂标待复核，不能拿它们否决 DQ-21。
