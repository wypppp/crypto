# 代码审计用的小型测试样本（10-02）

> 配合 [代码审计索引](../2026-10-02_代码审计索引.md) §4。给审计方在自己的环境里离线运行两个共用函数，与预期输出逐项比较。
> 不含 DQ-22 的 55 条留出（逐条断言哈希规则）、封存周 2026-06-15～07-12、DQ-22 前向窗口的任何数据。

## 怎么运行

```
python3 run_samples.py
```

- 要求：仓库检出在代码审计索引所在的提交；Python 3.8+，numpy、pandas；不联网（脚本会拦截任何下载）。
- 输出“perp 不一致 0 项；valuation 不一致 0 项”即通过。执行模型 10-02 在本机运行的结果就是这样。

## 内容

| 路径 | 是什么 |
|---|---|
| `perp/archive/` | 4 个开发期做空事件（ARB、TIA、AEVO、FLOKI）用到的 25 个 data.binance.vision 公开归档文件（永续日线、标记价日线、资金费月文件），原样复制自 DQ-22 的缓存；缓存时已逐文件核对官方 CHECKSUM |
| `perp/archive_manifest.csv` | 上述文件的 sha256 与字节数 |
| `perp/s3_listing.json` | `perp_replicate.first_day` 列 S3 目录的结果（10-02 实时列出）。包括 `1000ARBUSDT` 这类不存在的合约，结果为空 |
| `perp/expected.csv` | 预期输出：冻结结果 `1_实验/币安新币_上线后做空_DQ-22/runs/events.csv` 的对应行，30 天与 7 天各取状态、爆仓、资金费、结算次数、价格回收、总回收 |
| `valuation/expected.csv` | A 周检查点面板（`1_实验/pump曲线_检查点动态决策_DQ-8A/raw/F3_devA.csv`）里按种子 20261002 抽的 16 个状态（曲线 10、池 6），以及对应 mint 的入场状态；预期的买入代币数与卖出回收比 |
| `build_samples.py` | 生成以上文件的脚本（只运行一次）。它离线重跑了 4 个事件，与冻结结果逐项相符后才写出；估值部分另用独立的逐行实现核对冻结函数 |
| `run_samples.py` | 审计方运行的脚本 |

## 已知限制

- 现货对照（`H*_r_spot`）只作描述，不在样本里；运行时关掉。
- 估值样本只覆盖 Python 版（`analyze_dq8a.py`）。各 SQL 生成器里内嵌的同一公式（索引 §2）不在样本里，需要对照 Dune 结果另核。
