## 一、两个实测发现的处理

### 1. 买入事件表缺 cashback 与回购费两列

**先试原始事件解码，小样本，≤5 credits**

- 卖出表有这两列，买入表没有，大概率是 Dune 的买入解码表用了旧版 IDL，而链上事件里其实有这些字段。
- 做法：
  - 从 `solana.instruction_calls` 里取 PumpSwap 自调用的事件数据（Anchor event-CPI 的原始字节），按新版 IDL 的偏移解码；
  - 先拿已有列逐字段对齐，确认偏移正确，再读出尾部的新字段。

**解码不成，就记“未知”（NULL），不阻塞**

- 买入成本按用户实付 `user_quote_amount_in` 计，这是真实流出。
- cashback 是事后返还给交易者的钱，不计它只会**高估成本**，方向是保守的。
- 回购费是协议费的内部拆分，不影响交易者成本，也不影响池子储备。
- 以上写进 README。

### 2. 非 SOL 计价池（2026-09 约占 7%）

- **主分析**：只用 SOL 计价池。
- **USDC 池**：作为单独一层，按美元记账；换算成 SOL 时，用按时点的分钟价格（例如 Dune `prices.usd`），并注明价格来源。
- **其他 114 种计价资产的池**：在母表里计数、标出，不进主分析。
- 每层各自报告币数与比例，不混加。

### C2. 新发现：虚拟报价储备（比两个实测发现更要紧）

PROBE21b 顺带解出了 `virtual_quote_reserves`，发现它在 2026-09-23 已经非零（约 17.58 SOL）。

**定性**：
- 恒积成交式只有加上它才对得上：卖出 `quote_out＝floor((q0＋vq)·b_in／(b0＋b_in))`，`buy` 指令 `quote_in＝ceil((q0＋vq)·out／(b0−out))`，逐笔 55/55；只用池报价储备时买入 0/40、卖出 1/15。
- 也就是说 PumpSwap 按“有效报价储备＝池报价储备＋vq”成交。

**定年**（`sql/PROBE21c_虚拟报价储备定年.sql`，11.56 credits；39 个开发周日期、避开封存期，每天只取当日建的池在 12:00～12:05 的调用，只读字节长度与 vq）：
- 事件布局随时间变长：卖出 320→368（2025-05）→384（2026-02）→400（2026-06）→425（2026-07-18 起，带 vq）→441（09-21）→449（10-03）。
- 07-18：当日建池的卖出 1,084 笔、43 个池，vq 全为 0。
- 08-03 起各抽样日大多非零：08-03 是 77 个池中 75 个，09-24 买入 53/53 个池；中位 17,584,505,288 lamports，个别池为 0 或数百 SOL。
- 所以生效在 2026-07-18～08-03 之间（官方文档 2026-07-15 提交 `2c22246b` 引入该字段，当时写“所有池为 0”）。

**同一池是否恒定**（0 credits，用已有的 2026-09-23 v2 逐笔样本）：
- 48 个池全天 148,288 笔卖出，按卖出式反解的 vq 区间每池交集都非空，最宽 26 lamports；
- 36 个池在 17,584,505,288～17,584,505,805 之间，12 个池为 0。
- 买入不能这样反解：`buy_exact_quote_in` 的成交式不同，混进去会出现约 64 SOL 的假值。

**原先的说法哪里错了**：
- DQ-35 README 与生成器写“09-30 起有带符号的 vq（官方文档 2026-09-29 提交）”，DQ-37 README 写“含 09-30 起的负虚拟报价储备”。

- 事实库 F27、F49⑥、DQ-1 结果第 157 行早就写过“该值若变为非 0，Dune 储备就不等于有效储备”，但一直没核链上是否已非零。这次补上。
