# 河北企业环保数据元数据目录模板

> 版本：v0.2
> 日期：2026-08-20
> 用途：执行普查 `T-022 / Round C` 及 `T-026 / B-ENV` 对照；判断核心工序可观测性、覆盖率，以及内部/公开环保镜像的时效、颗粒度与修订，不导入价格，不训练收益模型
> 文档职责：内部数据交接结构的唯一真源；当前任务状态看[推进记录](推进记录.md)
> 对应矩阵：[河北商品边际供需候选矩阵](05-河北商品边际供需候选矩阵.md)
> 入口：[README](README.md)

> **2026-08-25 状态更正：休眠。** 使用者没有本模板假设的内部系统，当前不需要、也不应填写这些表。模板仅在未来确实获得独立内部来源后复用；河北公开平台数据由 `07` 和 `data/runs/` 单独审计，不能倒装成这里的内部交付。

## 0. 现在怎么用

第一份交付只做 `T-022` 元数据目录：使用稳定匿名 ID，保留系统原始行业、产品、设施、工序、监测点名称和共享关系。此时不需要企业真实名称，也不要导出全省一年的小时值。

唯一例外是 `T-026`：为启动 30 天时钟，可以先选少量能与公开平台唯一匹配的点位，前向保存同测量窗口的内部/公开首版响应、查询时间和哈希。它与全年历史导出是两件事。

推荐交付顺序：

1. 第 1 节元数据目录；
2. 第 3、4 节字段及状态代码字典；
3. 第 2 节公开产能母表和设备交叉关系；
4. 只有满足第 7 节条件后，才取 `2-5` 个设备的短窗小时样例。

## 1. 第一轮需要什么

第一轮只需要元数据目录，不需要企业真实名称，也不需要导出一年小时数值。稳定的匿名 ID 必须保证以后同一实体仍使用同一个 ID。

最小目录粒度是一行一个“监测点—生产设施”关系。如果一个监测点对应三台生产设施，填写三行并使用同一个监测点 ID；如果关系未知，也单独填写一行并明确标记 `unknown`，不能猜测一一对应。

| 字段 | 必填 | 填写规则 |
| --- | --- | --- |
| `enterprise_id` | 是 | 稳定匿名企业 ID；不得每次导出重新编号 |
| `plant_id` | 是 | 厂区 ID；同一企业多厂区须拆分 |
| `universe_vintage` | 是 | 当前 `U-OBS/U-PROC` 版本；现行值为 `v2@2026-08-24T17:05:00+08:00` |
| `as_of` | 是 | 目录查询的截止时间和时区 |
| `city` / `county` | 是 | 市、县级即可；无需精确地址 |
| `industry_raw` | 是 | 系统原始行业分类，不先人工归并 |
| `product_raw` | 能取得则填 | 系统或许可中的产品原名；未知写 `unknown` |
| `production_line_id` | 能取得则填 | 生产线/炉组/机组 ID；未知写 `unknown` |
| `production_facility_id` | 是 | 生产设施稳定 ID |
| `production_facility_name_raw` | 是 | 系统原始名称，例如“1#浮法线玻璃熔窑” |
| `process_name_raw` | 是 | 系统原始工序名称，不先标准化 |
| `control_facility_id` | 能取得则填 | 脱硫、脱硝、除尘、污水处理等治理设施 ID |
| `control_facility_name_raw` | 能取得则填 | 治理设施原始名称 |
| `monitoring_point_id` | 是 | 监测点/排口稳定 ID |
| `monitoring_point_name_raw` | 是 | 监测点原始名称 |
| `medium` | 是 | `waste_gas / wastewater / VOC / ambient / other` |
| `topology` | 是 | `one_to_one / shared_outlet / one_device_multi_outlet / unknown` |
| `shared_facility_count` | 能取得则填 | 共用排口对应设施数；未知写 `unknown` |
| `design_capacity_value` | 能取得则填 | 只填公开许可或系统已有值，不估算 |
| `design_capacity_unit` | 随产能填 | 如 `t/y`、`t/d`、`t/d-melt`、`m2-sinter`、`m3-BF` |
| `capacity_source` | 随产能填 | 具体公开 URL、内部字段名或 `unknown` |
| `capacity_record_id` | 随产能填 | 指向第 2 节产品产能母表；不得仅凭企业名自动匹配 |
| `operating_status_source` | 是 | `PLC / manual / platform_derived / monitoring_device / unknown` |
| `first_visible_lag` | 是 | 如 `previous_complete_hour`；不能确认则写 `unknown` |
| `available_history` | 是 | 当前为滚动一年；若企业不同则如实填 |
| `revision_behavior` | 能取得则填 | 是否回填、覆盖、保留版本；未知写 `unknown` |
| `field_set_id` | 是 | 指向下方字段字典的版本 ID |
| `notes` | 否 | 只记事实性特殊情况，不写交易判断 |

建议用 CSV 或数据库导出，列名保持上表英文 ID；原始中文名称留在 `*_raw` 字段中，不做不可逆清洗。

## 2. 产品产能母表与设备交叉表

覆盖率分母不能由监测目录自己生成。须另建 `U-ECON` 产品产能/消费能力母表，再与第 1 节逐设备交叉。

| 字段 | 填写规则 |
| --- | --- |
| `capacity_record_id` | 一个产品—生产线/设备—有效期记录一个 ID |
| `enterprise_id / plant_id` | 与内部目录使用同一稳定匿名 ID |
| `product_name / specification` | 精确到能与合约经济对象比较的产品/规格 |
| `pricing_market / deliverable_grade` | 定价地理市场、交割品级/替代品规则；不适用写 `NA` |
| `production_line_id / production_facility_id` | 能绑定则填；只有企业总产能时写 `unknown` |
| `capacity_value / capacity_unit` | 设计或有效产能，原单位与标准化单位都保留 |
| `capacity_basis` | `design / approved / effective / consumption_capacity / unknown` |
| `operating_status` | `operating / planned / under_construction / long_idle / demolished / replaced / unknown` |
| `effective_start / effective_end` | 产能和状态的有效时间；不得把已拆产能留在当期分母 |
| `source_type / source_url` | 排污许可副本、环评、产能置换、法定披露或其他来源 |
| `published_at / accessed_at / snapshot_hash` | 字段级证据必填；无原始发布时间写 `unknown` |
| `evidence_level / last_verified_at` | 按普查协议 `I0/F/M/L/H/U/X` 和最近核对时间 |
| `crosswalk_status` | `unique / shared / known_unobservable / capacity_unknown / relation_unknown` |

覆盖率报告必须同时给出：

```text
唯一映射的核心产能
共享排口对应产能
已知不可观测产能
产能数值未知
设备—产品关系未知
```

产能未知项保留在分母不确定性中，不删除，不按企业数替代。

## 3. 字段字典模板

不同企业、介质和监测点字段可以不同。每一种字段组合登记一个 `field_set_id`，不要求强行拼成统一宽表。

| 字段 | 含义 |
| --- | --- |
| `field_set_id` | 字段组合版本 |
| `source_field_name_raw` | 系统原始字段名 |
| `normalized_concept` | 例如 `flue_gas_volume / flow_velocity / temperature / oxygen / concentration / mass_emission / status / qc_flag` |
| `pollutant_or_metric` | 烟尘、SO2、NOx、NH3、NMHC、COD 等原始对象 |
| `unit_raw` | 原单位，不能凭数值猜测 |
| `measured_or_converted` | `measured / converted / derived / unknown` |
| `actual_or_standard_condition` | `actual / standard / unknown` |
| `dry_or_wet_basis` | `dry / wet / unknown` |
| `instant_or_hourly_aggregate` | `instant_mean / hourly_mean / hourly_total / unknown` |
| `calculation_rule` | 若质量排放由浓度×流量计算，记录公式或系统说明 |
| `valid_range_or_limit` | 字段中括号值是量程、排放限值或其他含义；不能确认写 `unknown` |
| `missing_zero_negative_semantics` | 空、0、负数、哨兵值、低于检出限的定义 |

## 4. 状态与质控代码字典

状态和质控必须分开。一个小时“正常生产”且某污染物“校准”时，生产状态与该分析仪有效性不是同一个变量。

| 字段 | 值 |
| --- | --- |
| `code_set_id` |  |
| `raw_code` | 例如 `N/C/K` |
| `raw_label` | 例如“正常”“校准”“核查比对” |
| `applies_to` | `production_facility / control_facility / monitoring_device / pollutant_channel / platform_record / unknown` |
| `generated_by` | `PLC / enterprise_manual / platform_rule / monitoring_device / unknown` |
| `effective_start/end` | 代码定义是否有版本时间 |
| `research_treatment` | 首版只允许 `valid / maintenance / calibration / fault / invalid / unknown` |
| `definition_source` | 系统说明、文件或 `unknown` |

来源和适用对象未知时，`research_treatment` 必须先记 `unknown`，不能因标签叫“正常生产”就标为生产设备正常。

## 6. 公开环保镜像对照模板

对可在公开平台匹配的同一点位连续记录至少 30 天；不能只打开两次就推断更新周期。

| 字段 | 含义 |
| --- | --- |
| `internal_point_id / public_point_id` | 同点位映射；不确定时不匹配 |
| `public_platform / public_url` | 全国、河北或市级具体入口和查询 URL |
| `field_internal / field_public / unit` | 同字段、单位、实测/折算、实况/标况核对 |
| `Tmeasure` | 同一物理测量时段 |
| `Tavailable_internal / Tseen_internal` | 内部端首次可查和本系统实际查到时间 |
| `Tavailable_public / Tseen_public` | 公开端首次可查和本系统实际查到时间 |
| `aggregation_internal / aggregation_public` | 小时均、小时总量、日均、日总量等 |
| `poll_interval / clock_offset` | 两端轮询间隔和时钟校正 |
| `revision / missing / qc_difference` | 回填、覆盖、缺失、精度和质控差异 |
| `response_hash / screenshot_hash` | 每次查询的不可覆盖证据 |

此对照只验证数据唯一性、时效和颗粒度。它不能代替 Mysteel/隆众/卓创等产业共同信息基准。

## 7. 何时才取小时数值样例

目录完成后，按以下顺序缩小范围：

1. 将只有污水总口、公共锅炉、共享火炬且无法绑定核心设备的点位排除出信号候选集，但完整保留在 `U-OBS` 母表及排除日志；
2. 用第 2 节产能母表计算可唯一映射覆盖率与未知份额；
3. 仅对通过普查 `G1a`、核心点位存在且工具达到 `W1` 的方向取开发集详细数值，用于小样本字段检查和状态可行性抽样；不得称为正式状态校准或进入前向结果分母，正式状态校准须等待 `W2`；
4. 每个候选先取 `2-5` 个设备、连续 `7-14` 天，必须包含至少一个维护、校准、停运或复产片段；
5. 数值样例保留原始字段、首次可见时间、查询时间和文件哈希，不以截图或手工复制表格作为正式输入；
6. 公开确认事件只用于状态校准，不进入正式前向收益分母。

## 8. 数据最小化

- 企业名称可匿名，但 ID 必须稳定；
- 不导出与候选商品无关的企业经营、人员或个人数据；
- 第一轮不需要全省一年数值，也不需要上传公开源已经能提供的内容；
- 原始数据、映射表和派生状态分层保存，模型输出不得覆盖原始快照；
- 本模板只定义研究所需字段，不改变数据使用授权或任何合规边界。
