## 0. 这份文档解决什么

三张事件日志解决“某一次事件怎么记”；本文档解决四个更上层的问题：

1. 三条轨各自在验证什么假说；
2. 信息从原始数据到期权支付需经过哪些因果环节；
3. 下一步应该先做什么，哪些事情还不能做；
4. 满足什么条件才能从“数据可用”推进到“可交易假说”。

本文档不改变上位协议的 `B0` 默认不交易结论。前向日志未触发淘汰，只表示值得继续观察，不等于已存在 Edge，更不等于可以实盘。

## 1. 冻结约束

| 约束 | 对三条轨的含义 |
| --- | --- |
| 收益结构 | 只用最大损失限于已付总权利金、费用和不可退换汇成本的买方期权表达；须在自动行权/期货转换前退出，不用裸期货或裸卖期权替代 |
| Edge 来源 | 必须来自已有语言、地理、时区、专业或已批准候选专有输入；专有性和交易增量须先审计，“我会研究得更深”不算 |
| 工具 | 必须有精确合约、可达账户、真实双边报价和可退出深度 |
| 信息口径 | 企业用电与内部站点数据获准进入日志，但是否构成 Edge 待审计；其他外部事实必须附具体公开 URL，账户/费用等非触发运营证据须留原件和哈希 |
| 样本 | S、M、F 轨各自是不同总体；不合并凑样本；各轨必须冻结事件开始/结束、冷却期、升级/解除/复产反转和政策附件并簇规则 |
| 执行价 | 入场用当时 ask，退出用当时 bid；不用中间价、收盘价或事后最优合约 |
| 低频 | 接受机会少；事件不足时结论是“证据不足”，不因时间压力放宽标准 |

## 2. 共同研究架构

每条轨都必须分别通过下列六层。上游一层失败，下游收益不得用来替它辩护。

```text
位置领先
  -> 数据点时可得且真的比公共信息早/更完整
  -> 实体状态
  -> 数据能正确识别铁水、粗钢或管制影响，而不是只有相关性
  -> 经济映射
  -> 该状态确实改变指定标的的基本面边际
  -> 定价残差
  -> 在 T0/T2 时尚未被代理市场、正股或 IV 充分吸收
  -> 表达与执行
  -> 期权在当时真有可执行 ask、退出 bid、足够期限和确定性合约选择
  -> 净交易价值
  -> 扣除价差、费用、未成交和污染事件后仍为正
```

因此，研究不只记 P&L，还要对每次失败定位：

| 失败层 | 典型结果 |
| --- | --- |
| 位置失败 | 公共产业源或代理市场已经更早知道 |
| 状态失败 | 用电/污染变化未对应真实工序变化，或管制产品与 MP 无关 |
| 经济映射失败 | 状态判断正确，但未改变矿耗、MP 净受益或硅锰可变需求 |
| 定价残差失败 | 信息为真且有经济影响，但在 `T2` 前已被价格和 IV 吸收 |
| 表达/执行失败 | 没有双边报价、价差太宽、账户不可达、合约选择不确定或无法退出 |
| 净价值失败 | 可执行，但按真实 ask/bid、费用和资金占用计算的组合净值不为正 |

## 4. S 轨详细说明：河北钢铁 → SGX 铁矿石期权

### 4.1 核心命题

市场能很快看到“河北发布重污染预警”，但不一定能同步知道：

- 哪些钢厂真正执行；
- 停的是轧线、烧结还是高炉；
- 执行强度是否超过/低于公开命令；
- 是否已提前复产，或预警解除后仍未复产。

S 轨不交易公告本身，而是交易“公告叙事与实际铁水状态之间的偏差”。

### 4.2 数据分工

| 数据 | 主要作用 | 不能单独证明 |
| --- | --- | --- |
| 企业用电 | 识别跨厂工序活动异常，提供细颗粒度时间戳 | 若未完成企业-工序映射，总用电不等于铁水 |
| 国/省控站污染物 | 识别区域燃烧/扬尘状态、执行扩散和解除/升级风险 | 未经气象校正的 PM/NO2 不等于单厂产量 |
| 公开环保通知 | 定义行政要求和时间窗口 | 通知不等于已执行 |
| Mysteel/等效产业源 | 定义市场共同信息集和 `Tpub` | 二手调研不等于实时全省状态 |

### 4.3 必须验证的因果链

```text
企业用电/工序代理状态
  + 气象归因后的站点污染残差
  -> 高炉、烧结、球团、制氧等铁前工序实际变化
  -> 河北铁水和矿耗的方向/持续时间
  -> 中国进口矿近月需求边际变化
  -> SGX 62% 铁矿石期权支付
```

只有轧线、石灰窑、原料车辆或环保设备用电变化时，不得推导铁水。自备电厂、高炉煤气发电和外购电切换必须纳入异常映射。

### 4.4 为什么买方期权仍可能失败

- 铁矿石是全国/全球市场，河北冲击可能被矿山发运、港口库存和宏观政策淹没；
- 产业盘可能拥有更快的高炉/采购关系信息；
- 信息正确时，期货可能已反应，期权 IV 也可能已上升；
- 近月平值附近可能流动，但目标虚值档未必有真实退出深度。

### 4.5 S 轨的最小可接受产出

1. 一份企业-工序映射表，能区分铁前、炼钢、轧制和辅助设施；
2. 一份站点空间簇与气象归因规则；
3. 一份专有数据相对公开站点/产业调研的唯一性审计；
4. SGX 账户、合约、时段、权利金、费用和报价深度审计；
5. 按 [S 轨日志](01-河北钢铁-SGX铁矿石期权.md) 形成的完整前向事件分母。

## 5. M 轨详细说明：稀土/磁材管制 → MP 期权

### 5.1 核心命题

M 轨不假设“中文消息到美国之前有几小时空窗”。MP 正股可在盘前定价，单股期权不能盘前成交。真正待验证的是：

> 美国盘前价格是否只交易了“China restricts rare earths”标题，而没有准确区分元素、化学形态、纯度、合金/磁材形态、最终用途和许可例外。

因此，M 轨是跨语种解释残差，不是跨时区抢跑。

### 5.2 产品映射是第一道门

每份公告必须在 `T0` 前回答：

1. 受控的究竟是哪种元素和化学/产品形态；
2. 它是 MP 的已有/近期产品、MP 的必要投入，还是与 MP 无关；
3. 管制收紧对 MP 净上是受益、受损还是中性；
4. 英文市场当时的解释与这个冻结判断差在哪里。

镓、锗、锑、泛化工事故和无直接 MP 产品关系的公告不进入样本。

### 5.3 主要污染因素

- MP 美国国防合同、补贴和政策支持；
- Mountain Pass 产量、Fort Worth 磁材产能爬坡和技术里程碑；
- 财报、指引、融资、增发和内部人交易；
- 美国本土关键矿产政策或同业事件。

这些事件与中国信号同日出现时，信号资格、执行处置和市场混杂状态分别记录；事件仍留在 admitted 全分母中，不得事后根据 P&L 决定是否排除。

### 5.4 执行现实

- `Tequiv` 记录英文公开世界首次达到“元素/形态/用途或目的地/许可例外/MP 映射”全部冻结标准的时间；首篇英文标题只记为辅助 `T1`；
- `Tpre` 记录 MP 正股盘前已发生的反应；
- `T2` 只能在美股期权常规时段发生；
- 若不能在常规时段看到真实期权报价，不得用预挂一个事后看似合理的限价代替；
- 若盘前已超过冻结的“主要反应已完成”阈值，执行处置记为 `no-trade-already-priced`，但仍留在 admitted 分母。

### 5.5 M 轨的最小可接受产出

1. MP 产品/投入物和受控物的版本化映射表，以及 `Tequiv` 的准确解释判据；
2. MP 期权时段、账户、费用、报价和退出深度审计；
3. 每次事件的 `Traw/Tseen/T0/T1/Tequiv/Tproxy/Tpre/T2/Tout`；
4. 按 [M 轨日志](02-稀土磁材管制-MP期权.md) 形成的独立前向分母。

## 6. F 轨详细说明：河北粗钢 → SF/SM 期权

### 6.1 为什么只是条件对照

F 轨的候选机制是炼钢阶段的硅/锰可变消耗，但“粗钢变化”本身不足以推出同期 SF/SM 采购需求。必须继续估算钢种结构、吨钢可变添加强度、厂内库存以及招标/交货滞后。

- 只有烧结/球团/高炉变化：S 轨可能有效，F 轨信号资格为 `rejected`；
- 可确认转炉/EAF/粗钢变化：只能进入 candidate；只有合金用量加权需求及库存/采购时滞也通过冻结规则，才能 admitted；
- 只有轧制变化：不得推导 SF/SM 需求。

### 6.2 为什么可能不如铁矿石

- SF 供给受内蒙古、宁夏、青甘陕电价、能耗、开工和兰炭影响；
- SM 还受内蒙古、宁夏、西南产量、锰矿到港和港口库存影响；
- 钢厂月度招标可以平滑短期消耗变化；
- 河北数据观察不到铁合金主产区的供给冲击。

因此，F 轨必须与 S 轨对同一事件、同一权利金口径做头对头比较，不允许事后声称“某一次 SF 更敏感”。内部站点污染数据在 F 轨只作区域环境和执行背景，不得单独决定 admission、方向或强度。

### 6.3 三道激活 Gate 与逐事件 admission 门

1. **产品存在性**：郑商所有 SF/SM 期权正式挂牌公告、现行合约规则和真实合约代码；
2. **账户可达性**：期货公司书面确认开通条件、验资、测试和交易经历；
3. **目标链可执行性**：实际目标 DTE/delta 档存在连续双边实时报价和 L2 深度，一手 all-in 成本适配 `1万元AUM × 风险比例`，且不会遗留期货头寸。
4. **逐事件 admission 门，不是 activation Gate**：可事前形成钢种/吨钢硅锰可变消耗加权的粗钢变化，并冻结库存、招标和交货滞后规则。

前三道 Gate 任一道未通过，F 轨不激活，且不得用 SF/SM 线性期货替代；需求映射门不通过的单个事件只能 rejected，不能进入 admitted 分母。

## 7. 数据工程与唯一性审计

### 7.1 内部数据快照最低字段

| 类型 | 必存字段 |
| --- | --- |
| 企业用电 | 企业ID、测量窗口 `Tmeasure`、原始 `as-of`、`Tavailable-internal`（若可观测）、`Tseen-internal`、导出时间、原始值、单位、缺失/修订标记、查询参数、文件哈希 |
| 污染站 | 站点ID、国控/省控、经纬度、污染物、`Tmeasure`、内部/公开端各自的 `Tavailable/Tseen`、原始值、精度、质控、缺失、修订版本、导出时间、文件哈希 |

不得覆盖原始快照。修订数据生成新版本，并保留“决策时可见版本”和“后验最终版本”。

### 7.2 污染站数据唯一性审计

内部站点数据的“难获取”不能直接计为 Edge。先连续 30 天对比内部与公开端：

| 比较项 | 问题 |
| --- | --- |
| 覆盖 | 省控站或额外站点是否为公开端缺失的空间覆盖？ |
| 速度 | 在两端相同轮询频率、失败重试和同步时钟下，内部/公开端各自的 `Tavailable/Tseen` 相差多少？ |
| 精度 | 内部值是否有更高精度或未舍入值？ |
| 质控 | 是否有公开端没有的设备、校准、异常和修订标记？ |
| 历史 | 是否能保留公开端无法稳定获得的点时历史与修订链？ |

两端必须保存轮询间隔、失败重试和时钟偏差。若 `Tavailable` 不可观测，只能报告本系统的 `Tseen` 差，不能声称源级领先。若内部数据与公开端高度一致，无额外覆盖、无领先、无质控/修订信息，它只是工程便利，不计作独立 Edge。

### 7.3 三组前向增量对照

S 轨对每个事件同时记录：

| 模型 | 当时可用输入 | 作用 |
| --- | --- | --- |
| `M0` | 公开预警、公开站点、公开产业源 | 市场共同信息基准 |
| `M1` | `M0 + 企业用电` | 检验用电数据是否提前/纠正工序判断 |
| `M2` | `M1 + 内部国/省控站` | 检验站点数据是否进一步提前、减少误报或改变交易决策 |

三组模型必须在同一决策时点分别输出并同时哈希：candidate/admitted/rejected 判断、方向、预注册置信度档和最早可交易时点。S 轨正式信号资格固定使用 `M2`；`M0/M1` 只作影子对照，不得事后择模。置信度档、admission 阈值和“改变决策”的定义必须在 P4 前冻结，不能事后只描述最好的模型。

累计至少 8 个独立 S 轨 candidate episode 后，若 `M2` 从未相对 `M1` 改变事件纳入、方向、置信度档或可交易时点，且未减少任何一个经后验确认的误报，污染站数据降级为验证资料，不再声称为交易 Edge；这不自动淘汰企业用电驱动的 S 轨。

## 8. 推进阶段与门槛

### 阶段 P0：研究边界冻结

**目标**：先冻结研究问题与开发纪律，而不是在不了解数据分布前任意填写数值阈值。

**必须产出**：

- 三轨各自的假说边界、允许来源、禁止替代工具和失败层；
- candidate 的发现口径，以及事件开始/结束、冷却期、升级/解除/复产反转、公告附件/修订的聚类规则；
- P1-P3 的开发数据时间窗、允许校准的字段和禁止查看的事件后收益；
- `信号资格 / 执行处置 / 污染 / 解决 / 结果` 五个正交字段及各统计分母；
- 所有规则文件的版本号和内容哈希。

**退出条件**：P0 边界完成并不允许进入正式前向盘；日志内数值 `[PRE-REGISTER]` 可以在 P1-P3 开发期校准，但开发事件一律不计入 P4 分母。

### 阶段 P1：数据完整性与点时审计

**目标**：确认“我当时真能看到什么”。

**必须产出**：

- 两类内部数据的字段字典、更新频率、时区、缺失、质控和修订规则；
- 不可覆盖的原始快照和哈希流程；
- 污染站数据 30 天唯一性审计；
- 公开来源 URL 注册表和页面快照流程。
- 内部/公开端的 `Tmeasure/Tavailable/Tseen`、轮询频率、失败重试和时钟偏差审计。

**一票否决**：无法保存决策时版本，或只能在事后获得修订后数据。

### 阶段 P2：工具与账户无收益审计

**目标**：不看信号赚不赚，先确认期权是否真能买、真能卖。

三轨共通硬门：

- 最小一手的全部权利金、费用和换汇成本必须能装入 `1万元 AUM × 预注册单事件风险比例`，不是默认投入全部 1 万元；
- 机会容量另审计可部署总权利金 `USD 100k / USD 300k` 在入场与退出时的 L2 加权价格和冲击，不能用名义价值或 OI 替代；
- 冻结实时可交易报价源、最大 quote age、订单完成窗口、未完全成交处理和确定性合约选择算法；
- 冻结到期前强制退出、无法退出、DNE/弃权、自动行权/期货转换和异常交易日处理；任何路径不得生成股票、空股或期货敞口；
- 券商个性化权限/费用可作为非触发运营证据，但须保留签发方、时间、原件和哈希。

**S 轨**：

- 可用身份能否开立并持续使用支持 SGX 铁矿石期权的账户；
- 精确合约、报价单位、现金乘数、到期、期权类型、行权/结算、交易时段和费用；
- 连续至少 10 个交易日保存目标 DTE/行权价档的 bid/ask 与数量。

**M 轨**：

- 美股期权账户权限、费用、数据延迟和常规交易时段；
- MP 目标 DTE/行权价档的实时 NBBO/可交易报价、数量、deliverable/adjusted 状态和退出深度；
- 无法在开盘时看到实时报价的执行处置必须冻结为 `no-trade-no-quote`，不得假设成交。

**F 轨**：

- 官方证明产品存在、账户可达和目标 DTE/delta 档真实流动性的三道 activation Gate；F2 同时要求一手 all-in 成本可装入小账户预算且不会转换成期货风险；
- 任一 Gate 不过，F 轨保持阻断。

### 阶段 P3：开发校准和非交易预演

**目标**：在明确标记的开发数据上校准映射和数值规则，不查看或使用事件后期权收益。

**必须产出**：

- 用已知维护/限产/复产过程校准企业-工序映射、触发阈值和事件聚类，但不查看或纳入其期权收益；
- 并行输出 S 轨 `M0/M1/M2`，使用同一时点、冻结输出结构和哈希，不得只保留最好的一组；
- 校准 M 轨产品映射、`Tequiv` 判据、代理市场/首动阈值和盘前已定价阈值；
- 先做一次早期 smoke run 检查字段链路，再分别为 S/M 做一次封存前全链 rehearsal；P3-S 封存后再做 readiness run；F 仅在 Gate 全过后执行；
- 记录从 `Tseen` 到 `T0` 的实际人工/系统延迟。

**退出条件**：不能从总用电稳定区分铁前/炼钢/轧制/辅助设施时，S/F 不得进入正式前向事件；M 无法一致判定产品重合和 `Tequiv` 时不得进入正式前向事件。

### 阶段 P3-S：正式协议封存

进入 P4 前，每条拟启动轨必须：

1. 填完该日志全部 `[PRE-REGISTER]`，包括 admission、事件簇、代理市场、期权选择、权利金、流动性、固定退出和到期处置；
2. 固定开发集截止时间，封存全部开发事件，确认其不进入正式分母；
3. 保存规则版本、完整内容哈希和生效时间；
4. 封存后通过一次从发现、判断、哈希、真实报价到固定退出的 readiness run；readiness 不得用于回改同版本规则。

P4 开始后修改任何冻结字段，必须新建版本并从零建立新版本的 admitted 分母。

### 阶段 P4：正式前向虚拟盘

**目标**：使用已冻结规则收集完整分母，快速否证位置、映射与执行。

**规则**：

- 所有 candidate 均保留；资格、执行、污染、解决和结果分别填写；
- admitted 只能由 `T0` 前的冻结规则决定；已定价、无报价和有市场混杂不得把事件移出 admitted 全分母；
- 三轨分别累积至少 8 个按冻结聚类规则确认的独立 admitted 事件；
- 每周更新[推进记录](推进记录.md)，不修改已冻结事件；
- 根据各轨日志的淘汰线随时可以提前停止。

只有达到至少 8 个、且冻结 `Tout` 均已过去的独立 `matured admitted` 后才进行 P5。状态正确率只用其中 `resolved` 子集，`unverifiable` 率另报；执行可用性用全部 matured admitted；P&L 只用 `virtual-entry` 子集。事件不足只能记“证据不足”。90 天没有 3 倍事件不自动否决低频凸性；出现一次 3 倍也不自动证明 Edge。

### 阶段 P5：阶段性裁决

对每条轨分别产出一份裁决卡：

| 问题 | 必须提交的证据 |
| --- | --- |
| 位置是否存在 | S/F 报告 `T0/Tpub/Tproxy`；M 另报告 `T1/Tequiv/Tpre`；使用全 admitted 分布，不是媒体个案故事 |
| 状态是否可识别 | 事前判断与后验工序/政策结果逐事件对照 |
| 映射是否存在 | 在排除预注册混杂后的标的反应，并报告反例 |
| 凸性是否可买 | 逐笔最大总损失、标的×IV情景网格、真实 ask/bid、深度、费用、未成交、到期归零及强制退出/自动行权边界 |
| 收益是否依赖单一赢家 | 全部净P&L、去掉最好一笔后净P&L和最差事件 |
| 容量是否足够 | `1万元AUM × 风险比例` 的最小整数手可行性，以及可部署总权利金 USD 100k/300k 的实际 L2 入场/退出深度和往返冲击；币种和当时汇率明确列出 |

阶段性结论只允许：`TAKE FORWARD / CONTINUE / INSUFFICIENT EVIDENCE / ELIMINATE`。

- `TAKE FORWARD` 只表示可进入更严格的历史点时复现和新前向确认；
- `CONTINUE` 表示未被否证但样本或工具证据仍弱；
- `INSUFFICIENT EVIDENCE` 不得被改写成“暂时通过”；
- `ELIMINATE` 后不得用新故事在原样本上复活，新假说必须新建版本并使用新数据。

### 阶段 P6：实盘前评审（当前不开启）

即使 P5 得到 `TAKE FORWARD`，仍然不自动允许 1 万元实盘。必须回到上位协议，另行完成：

- 账户、身份、地区、税务、入出金与数据使用审计；
- 真实实时影子报价/影子委托与对账；
- 独立的 sealed 确认窗口，不得复用开发样本；
- 与 `B0/B1` 的统一财富路径比较；
- 单笔最大权利金、相关事件聚类风险、账户容量和停止规则；
- 使用者单独签署的资金决策。

## 9. 从今天开始的具体顺序

不应该直接“等下一个事件”。正确顺序是：

1. **冻结 P0 研究边界**：三轨假说、开发窗口、事件簇规则、状态轴和分母；此时不硬填数值阈值。
2. **建立原始快照管道**：先保存原始数据、`Tmeasure/Tavailable/Tseen` 和哈希，再做特征；不得只保存加工后信号。
3. **开始 30 天站点唯一性审计**：以相同轮询制度确认内部数据相对公开端究竟多了什么。
4. **同步审计 SGX 工具**：先过 1 万元最小表达门，再审计连续 10 日真实报价和美元 10万/30万容量档。
5. **在开发窗口校准 S 轨**：企业/工序映射、基线、触发阈值、站点簇、气象校正和 `M0/M1/M2`；不看事件后期权收益。
6. **完成 S 轨 smoke run / rehearsal**：演练 `Tseen -> T0 -> 报价快照 -> Tout`，只暴露字段和执行问题，不算 readiness。
7. **做 P3-S 最终封存**：填完全部 `[PRE-REGISTER]`、封存开发集、保存版本和哈希。
8. **封存后做 S 轨 readiness run**：全链通过且不回改规则，才允许 P4 计数；失败则新建规则版本后重新封存和 readiness。
9. **低占用并行 M 轨**：只做 MP 产品/投入物表、`Tequiv` 判据、工具审计、封存和 readiness，不扩张到 ALB/SQM/FMC/DQ/JKS。
10. **一次性核验 F 轨三道 activation Gate**：任一不过就保持阻断；三 Gate 通过后再开发逐事件需求 admission 门。
11. **开始正式前向记录**：只有对应轨完成 P0-P3、P3-S 及封存后 readiness，新事件才可能按冻结规则进入 admitted 分母。

## 10. 每周固定复盘

每周只回答以下问题，不重新寻找新方向：

1. 本周出现了多少 candidate/rejected/admitted；admitted 中各执行处置和市场混杂状态分别多少？
2. 哪一层失败最多：位置、实体状态、经济映射、定价残差、表达/执行还是净交易价值？
3. 内部站点数据有没有相对企业用电改变任何一次事前决策？
4. 有多少次信号是真的，但期权不可执行或已太贵？
5. 是否出现必须立即淘汰的硬证据？
6. 本周是否修改过规则？若修改，新版本从哪个时间开始，原样本如何封存？

答案追加到[推进记录](推进记录.md)；涉及研究优先级、轨道淘汰或资金权限的决定，同时追加到[阶段二决策日志](../阶段二决策日志.md)。
