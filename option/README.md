## 2. 来源规则

### 2.1 允许作为事实输入

1. **已授权内部数据**：河北企业级用电数据、河北国控站/省控站小时污染物数据。它们没有公开 URL，但经使用者明确确认可进入日志，是仅有的两类无公开 URL 候选输入。其唯一性、状态识别能力和交易增量仍须前向审计，不能预先称为 Edge。
2. **外部来源**：必须保存事件当时可公开访问的具体 URL、页面发布时间和本地快照哈希。
3. **行情/券商报价**：可无公开 URL，但必须保存数据商/券商名称、合约代码、带时区时间戳和原始报价快照。它只证明可执行性，不作为事件触发源。
4. **非触发运营证据**：账户权限、适当性、费用和数据订阅等券商/数据商书面文件可无公开 URL，但必须保存签发方、签发时间、适用账户、原文件与哈希。它只证明工具可达性，不得作为方向信号。

### 2.2 不允许作为触发

- 没有可访问 URL 的公众号转述、群聊、口述、截图或“听说”；
- 无法确定原始发布时间的二手报道；
- 事后补找的“更早消息”；
- 只有价格波动，没有独立事件来源的推测。

这些可记入“线索栏”，但不得决定方向、入场或事件计数。

## 3. 共通时间戳

| 字段 | 定义 | 填写规则 |
| --- | --- | --- |
| `Tmeasure` | 物理测量所对应的小时/窗口 | 只用于内部用电和站点数据；不得当作可交易时间 |
| `Traw` | 公告原始发布时间，或内部数据的原始 as-of | 不得用抓取时间替代 |
| `Tavailable` | 数据在对应内部/公开端首次可供查询的时间 | 能观测则保存原始响应；不能观测则明确写 `unknown` |
| `Tseen` | 使用者或系统实际可见时间 | 自动记录，不手工回填 |
| `T0` | 特征、方向和交易规则全部冻结的时间 | `T0 >= Tseen`；之后不得改方向 |
| `Tpub` | 第一个等效公共产业源的发布时间 | 必须附具体 URL；没有则写“未观察到” |
| `Tproxy` | 代理市场第一次突破预注册噪声阈值的时间 | 用冻结的分钟 bar 和阈值，不凭肉眼回填 |
| `T2` | `T0` 之后，冻结合约选择规则生效后首个满足流动性规则的真实可成交报价 | 必须 `T2 >= T0`；保存报价场所、quote age、bid/ask/数量；不用中间价 |
| `Tout` | 预注册退出时间 | 按当时 bid 或保守可成交价计算 |

所有时间同时保存原时区和 `Asia/Shanghai` 转换值。

内部端与公开端的速度比较必须分别保存 `Tmeasure`、`Tavailable-internal`、`Tseen-internal`、`Tavailable-public` 和 `Tseen-public`，并记录两端轮询间隔、失败重试和时钟偏差。两端轮询制度不同或 `Tavailable` 不可观测时，只能比较“本系统实际发现速度”，不得写成数据源天然领先。

## 4. 事件状态与统计分母

事件状态使用五个正交字段，不得再把 `admitted/no-trade/contaminated` 塞进一个互斥状态：

| 轴 | 允许值 | 含义 |
| --- | --- | --- |
| 信号资格 | `candidate / admitted / rejected` | `admitted` 只由 `T0` 前冻结的来源、阈值、因果和独立性规则决定 |
| 执行处置 | `pending / virtual-entry / no-trade-already-priced / no-trade-no-quote / no-trade-rule / gate-blocked` | 是否真正形成按 ask 计价的虚拟仓位 |
| 市场混杂状态 | `none / known-pre-T0 / discovered-post-T0` | 指公司/宏观/供给等归因混杂，与环境污染数据无关；与资格、执行和盈亏分开记录 |
| 解决状态 | `open / resolved / unverifiable` | 实体状态能否在事后确认 |
| 结果标签 | `NA / win / loss / false-positive / right-info-wrong-price` | 只在预注册退出后填写 |

分母固定如下：

- 候选召回分母：全部 `candidate`，包括后来 rejected 的线索；
- 位置和表达可用性分母：全部已到达冻结 `Tout` 的 `matured admitted`，包括无报价、已定价和有市场混杂的事件；
- 状态正确率分母：`matured admitted` 中 `resolution=resolved` 的事件；`unverifiable` 单独计率，不能悄悄删除；
- 干净映射结果：另报 `market-confounder=none` 且 `resolved` 的子集，但不得替代全分母；
- P&L：只对 `virtual-entry` 计算逐笔收益；其他 admitted 事件按零资本部署另列，不得从位置/执行失败率中消失。

`matured admitted` 指信号资格为 admitted 且预注册 `Tout` 已过去的事件；`open/resolved/unverifiable` 是实体状态验证轴，不能用来延后或提前 `Tout`。
`matured admitted` 的执行处置不得仍为 `pending`；若存在，说明日志不完整，P5 必须阻断直至按当时证据补齐或标记为不可验证，不能将其从分母删除。

## 5. 前向纪律

1. 事件必须按共同原因聚类。同一次污染过程、同一份政策或同一个事故影响多厂/多股，仍只算一个独立事件。
2. `T0` 之前完成事件纳入、因果链、方向、合约选择算法、计划权利金和退出规则。
3. `T0` 后发现污染因素，事件继续保留在 admitted 全分母中，污染轴标记 `discovered-post-T0`；不得因为亏损而删除。
4. 无合格报价时记录“有信号、不可执行”，不允许用期货、正股或事后最佳合约替代。
5. P0-P3 可在明确的开发窗口内校准字段，但开发事件不得进入正式分母。进入 P4 前必须完成 P3-S，冻结文件顶部全部 `[PRE-REGISTER]` 字段和内容哈希；修改后必须新建版本，只影响之后的事件。
6. 前向虚拟盘只能快速否证。未触发淘汰不等于获得实盘资格。
7. 买方期权不得持有进入自动行权、转成股票/期货或经纪商处置窗口。到期前强制退出时点、经纪商 cutoff、无法退出、DNE/弃权、异常交易日和强制平仓规则必须预注册；否则“最大损失限于已付权利金与不可退成本”不成立。
8. 每轨须冻结并发持仓的总权利金上限、同一冲击簇合并上限和资本不足时的事件优先级。整数手成本超过剩余预算时，执行处置记 `no-trade-rule`，不得假设分数合约或额外资金。

## 6. 报价、收益与容量统一口径

- 价差比例统一定义为 `(ask - bid) / ask`；任何字段中的“价差/ask”均使用这个正值公式。
- 入场现金：`entry_cash = Σ(ask_level × contracts_level × cash_multiplier) + open_fees + FX_cost`。
- 退出现金：`exit_cash = Σ(bid_level × contracts_level × cash_multiplier) - close_fees - FX_cost`。
- 净 P&L：`exit_cash - entry_cash`，按事件 `T0` 前冻结的汇率源与基准币种换算。
- 每个合约必须记录报价单位、tick、合约/现金乘数、币种、权利金结算或保证金方式、期权类型、交割物和是否为 adjusted contract。
- 没有逐档数据时，只能使用最佳 ask/bid 且计划手数不得超过显示数量。
- 报价必须来自账户可交易的实时场所/NBBO，记录 quote age 和冻结的订单完成窗口；延迟网页只证明产品存在，不能生成 `T2` 或虚拟成交。
- `OI` 和成交量是辅助筛选，不能替代当时报价和深度。
- 净收益倍数：`(退出净值 - 入场总成本) / 入场总成本`。
- 同时报告去掉最佳一笔后的累计 P&L，但不把“90天必须出现 3倍”作为通过条件。
- 小账户可行性与机会容量分开：前者以 `AUM=人民币1万元 × 预注册单事件风险比例` 计算可用权利金预算；后者直接审计可部署总权利金 `USD 100k / USD 300k`，不是标的名义价值。
- 容量不能由 OI 或名义成交量推断。每次在 `T2` 和冻结 `Tout` 都按实际 L2 计算三档的整数手数、加权成交价、可成交比例和往返冲击；无 bid 或不足量按预注册失败规则处理，不能沿用 `T2` 的显示深度。
- 每次 `T2` 另存最大损失（已付总权利金、开仓费用和不可退换汇成本）及冻结的标的变动 × IV 变动情景网格，用于验证事件持有期是否仍有右尾凸性；“买了期权”本身不算验证完成。
