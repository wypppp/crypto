# 二、交易基础知识

## （一）K线/成交量/趋势与震荡

先定路况（是趋势还是震荡），再看脚印（K线形态），最后验钞（用成交量确认真假）。

价格告诉你发生了什么，成交量告诉你发生的有多激烈，OI告诉你这件事还有多少人在坚持，会持续多久。

**K线**：价格的语言

* 实体越大，说明这一方越坚决
* 影线是被拒绝的价格
* 单根K线会骗人，一组K线才有意义

**成交量**：验钞机

* 验证K线的真假
* 量 = 认同度。没量的上涨是虚的，放量的上涨才是有人真掏钱。
* 一段时间内交易了多少，不管是新开还是平仓都算，代表 **热闹程度**

**Open Interest 未平仓量**：当前市场上，仍然没有平仓的合约总数量。

* 现在还留在场子里没平的总数，代表 **资金的黏性和决心**。

**趋势**：方向

* 特点：亏小钱，赚大钱

**震荡**：绞肉机

* 占了市场70%的时间
* 本质：多空力量均衡，没有新故事
* 特点：赚小钱，亏小钱，心态崩

## （二）限价单 / 市价单 / 盘口深度 / 滑点/ Maker | Taker 费率

限价单：提供流动性的Maker

市价单：拿走流动性的Taker

盘口深度：买卖双方的队伍厚度，市场当前有哪些人在等着买卖

滑点：实际成交均价 - 预期价格

Maker / Taker 费率：Maker 是摆摊的，Taker 是买东西就走的。交易所奖励摆摊的，惩罚着急的

* maker费率低甚至为负，做市商策略的来源；
* taker费率高

## （三）期货：基差、交割合约 vs 永续合约

**基差**：期货价格 - 现货价格。核心规律：到期收敛。所以基差越大，回归的动力就越强，这就是套利空间。

* **基差 > 0，叫升水/期货溢价 Contango**：说明大家看多，愿意用更高价格买未来。
* **基差 < 0，叫贴水/期货折价 Backwardation**：说明大家恐慌或急于做空，现货反而更贵。
* 是 期现套利（Cash-and-Carry Arbitrage） 、 套期保值（Hedging）等策略的核心变量。

**交割合约 vs 永续合约**

* 交割合约是传统期货，靠时间收敛；永续合约是币圈发明的永动机，靠费钱来硬拽着和现货对齐
* 永续价格 > 现货，多头太挤，那么多头每8小时给空头付钱，费率可能是 +0.01%。反之亦然
* 费率长期为正时，说明市场极度看多，容易到顶。

### 永续合约补充概念

**指数价格 Index Price** ：全市场的公允价

* 多个主流现货交易所（币安、OKX、Coinbase等）现货价格的加权平均。不是一个交易所的价格，是全市场的平均。

**标记价格 Mark Price**：指数 + 期货相比现货的溢价

* 标记价格 = 指数价格 + 溢价 Premium / 资金费率基差 Funding Basis

  * 溢价 = 合约盘口中间价 - 指数价格，再取一个移动平均平滑掉。
* 用途：

  * 计算未实现盈亏 PNL
  * 触发 强平 Liquidation

**最新成交价 Last Price**：看到的K线价

## （四）期权：call/put/行权价/权利金

期权至少同时受到多个因素影响：

* **标的资产价格** （涨还是跌）
* **剩余到期时间** （时间越少，期权价值通常越低）
* **市场预期波动率** （预期波动越大，期权通常越贵）
* **利率、分红等因素** （部分市场也会影响定价）

Call 看涨期权：你有权在未来以行权价买。

Put 看跌期权：你有权在未来以行权价卖。

权利金 Premium：买这个权利要付的钱。权利金 = 内在价值 + 时间价值。

## （五）期望值、盈亏比、胜率、最大回撤、夏普比率

胜率和盈亏比决定期望值，期望值决定你长线赚不赚，最大回撤和夏普决定你能不能活到长线。

1. 先算 **胜率 × 盈亏比**，得出 **EV**。EV不为正，后面都不用看了。
2. 再看 **最大回撤**，能不能承受？如果EV是正的但回撤50%，你拿不住等于零。
3. 最后看 **夏普**，同样的EV和回撤，夏普高的更值得加仓。

胜率 = 盈利次数 / 总交易次数。

盈亏比 = 平均盈利 / 平均亏损。赚钱的效率

* 趋势交易者盈亏比都很高，但胜率低。震荡交易者胜率高，盈亏比就低。

期望值 EV = 胜率 × 平均盈利 - (1-胜率) × 平均亏损

* 可以破解胜率的骗局。

最大回撤 = (峰值 - 谷底) / 峰值

* **控制回撤比追求收益重要10倍**
* **个人交易者最大回撤超过20%，策略就要停掉反思；超过30%，心态基本就崩了。** 用仓位控制回撤，不是靠技术。

夏普 = (策略收益率 - 无风险利率) / 收益率的标准差。至少>1，>2优秀。

* 分子是超额收益，你比存银行多赚了多少。
* 分母是波动率，你的收益有多不稳定。

**R倍数 R-Multiple** ： 衡量效率

* R = 盈亏金额 / 风险金额
* 以后说盈利几R

## （六）做空的机制与成本

融券/杠杆借币做空、期货/永续合约做空、期权做空（买 Put 或卖 Call）。

什么时候才值得做空：熊市主跌浪、对冲、高资金费率

**做空必须带止损！**

## （七）止损单 / 止损限价单 / OCO / Reduce Only

**止损单  / 止损市价单**：先设一个触发价，到了就变成市价单，立刻吃掉盘口跑。

**止损限价单**：触发价 + 限价，两个价格。触发后，变成限价单挂着等。

**OCO 二选一订单** One-Cancels-the-Other：同时挂两个单，一个止盈，一个止损，成交一个，另一个自动作废。

* OCO 里的止盈和止损，可以各自选市价或限价。最常用的是：**止盈用限价单，保证利润；止损用市价单，保证离场。**

**Reduce Only**：限制订单只能减少现有合约仓位，不能增加仓位或在平仓过量后反向开仓

* 例如持有 1 BTC 多仓，同时挂出多个止盈单，如果不使用只减仓，部分订单成交后剩余订单可能继续卖出并形成空仓。

## （八）订单有效期：IOC / FOK / GTC

**GTC 一直有效直到取消** Good Till Cancelled

* **什么时候用**：90% 的时候都用它。定投、抄底挂单、挂止盈，都用 GTC。你就是耐心等。

**IOC 立即成交否则取消** Immediate Or Cancel

* **什么时候用**：最常用的算法单。
  1. **扫单但不想留痕迹**：你不想让别人看到你的大单挂在那里，只想吃现有流动性。
  2. **套利和量化**：同时在两个交易所下单，这个成交了那个才继续，剩下的必须撤。
* IOC 是 Taker 的典型用法，图里例子 100股成交60取消40就是它。

**FOK 全部成交否则全部取消** Fill Or Kill

**什么时候用**：大资金保滑点。

1. **大户不想被拆单**：我就是要100个BTC，一次吃不到我就不要，避免吃了70个把价格抬上去了，剩下30个更贵。
2. **防止部分成交的尴尬**：做对冲时，两个腿必须数量一致，部分成交会导致裸露风险。

## （九）杠杆与合约细分

**U本位 vs 币本位合约**

* 赚了钱，你想拿U，还是想拿币？结算货币不同，币本位合约的盈亏是非线性的
* U本位是赚现金的打工人，币本位是赚股份的合伙人。熊市用U，牛市囤币用币本位。

**币币杠杆 / 借贷加杠杆 / 杠杆代币**

**币币杠杆**：交易所里借币进行现货交易

* **适合**：短期方向交易，灵活开多开空，当天或几天内结束
* **机制**：你存保证金，问交易所借钱或借币去交易。借U买币叫做多，借币卖币叫做空。

**借贷加杠杆**：主动借钱或借币，再自由使用。抵押贷，循环贷

* **适合**：长期持有并放大敞口。比如你长期看好 BTC，不想卖，用 BTC 抵押借 U 再买 BTC，熊市也愿意扛。
* **机制**：不是在交易对里借，是在借贷区借。抵押资产，借出另一种资产，再拿借出的去买。

**杠杆代币**：比如 BTC3L / BTC3S

* **适合**：单边趋势行情，拿1-3天。绝对不适合长期持有和震荡市。
* **机制**：你买的不是币，是一个自带3倍杠杆的基金代币。交易所帮你背后去做期货、调仓，你只管买它就行，不用管保证金、利息、强平。
* BTC3L 就是 3倍做多 BTC，BTC涨1%，它涨3%。BTC3S 就是 3倍做空，BTC跌1%，它涨3%。
* 致命点：**每日自动调仓 + 磨损 Decay**

## （十）仓位管理方法论

仓位管理方法论回答"这笔该下多大"。先决定亏多少，再决定买多少。

**只在盈利时加仓，亏损绝不加仓**。

**核心公式**：仓位规模 = 风险金额 / 止损距离

**常见仓位管理方法**：

**凯利公式**：算最优仓位

* 目标是最大化长期几何增长率。
* 致命陷阱：f*对p、b的估计误差极度敏感——胜率估高一点，算出来的仓位就可能大幅超配，破产概率不是变小而是变大。
* 实务上极少有人用满仓凯利，常用1/4或1/2凯利：
  * 一是对p、b的估计本身带误差
  * 二是满仓凯利路径的波动（回撤深度）极高，就算公式"对"，心理上也扛不住。

1. **波动率倒数法（vol-targeting）**：平衡仓位

* 仓位与该资产波动率成反比，让组合里每个仓位承担的风险大致相等。
* 加密里这条比A股更要紧——BTC和某些山寨币的波动率能差好几倍，同样"一份仓位"承担的风险完全不是一回事。

# 三、阶段1-A 加密市场结构 —— 与A股的差异

### （一）永续合约与资金费率：无交割日的期货靠什么锚住现货？谁付谁？怎么算、多久结算？

1. 永续合约的价格靠资金费率趋近在现货价格附近，但短期内允许明显偏离。

   * 推测锚定机制：若永续价格高于现货，多头须持续付款给空头。理论上会抑制做多意愿+鼓励期现套利。
   * 期现套利此时并不是“无风险”操作。**"delta被对冲" ≠ "无风险"** 。风险点有以下两个：
     * 保证金/强平风险。永续空头和现货分别占据仓位，如果价格急涨，空头会立马浮亏并占用更多保证金，现货的浮盈不会自动实时补充。
     * 资金费率方向反转风险。资金费率每8小时自动计算一次，建仓时正费率不代表后续一直正费率，随时可能贴水。
2. 资金费率为正，永续合约价格>现货（升水），多头付给空头；反之亦然。

   * 最重要的是理解：持仓价值 × 资金费率 = 支付/收入
   * 意味着长期持仓时资金费率会侵蚀收益
3. 怎么算：

   1. 计算溢价指数Premium Index(P) = [Max(0, Impact Bid Price − Price Index) − Max(0, Price Index − Impact Ask Price)] / Price Index

      * Price Index：现货指数价格（多个主流现货交易所加权平均）
      * Impact Bid/Ask Price：用"冲击保证金名义价值"（Impact Margin Notional, IMN）在盘口上测算出的平均成交价，用来抵抗薄盘操纵
      * IMN = 200 USDT / 该合约最高杠杆档位对应的初始保证金率
      * 每5秒计算一次
   2. 计算时间加权平均（8小时资金间隔为例）

      * Average Premium Index (P) = (1×P₁ + 2×P₂ + ... + n×Pₙ) / (1+2+...+n)
      * n = 60/5 × 60 × 8 = 5,760 个数据点
      * 越接近结算时刻的数据点权重越高
   3. 加上利率分量，套入damper

      * Funding Rate (F) = [Average Premium Index (P) + clamp(利率 − P, 0.05%, −0.05%)] / (8/N)
      * 默认利率：0.03%/天，折算到8小时结算间隔即每次0.01%（ETHBTC 例外，利率设为0%）
      * clamp(x, min, max)：x超出±0.05%区间就截断在边界上
      * 换句话说：只要溢价指数落在 −0.04%～0.06% 区间内，最终资金费率就等于利率（0.01%），不受溢价影响
   4. 加cap/floor二次限幅

      * Floor = −0.75 × 维持保证金率
      * Cap = 0.75 × 维持保证金率
      * 对BTCUSDT等一批指定交易对（官方页面列出约20多个），这个封顶公式生效；其余USDⓈ-M永续合约统一封顶在 ±2%。
4. 多久结算：

   * 默认结算间隔为 **每8小时** ，固定在 00:00 / 08:00 / 16:00 (UTC)。
   * 只有在有持仓的情况下，且持仓跨越了结算时间点，才会被扣/收资金费；提前平仓可以躲开这次结算。
   * 实际扣款时间点有约15秒的偏差窗口。
   * 补充规定：
     * 如果某合约上一次资金费率结算触及了cap或floor，下一次结算频率会临时从8小时/4小时改成**每1小时**一次，直到费率回落。
     * 处于1小时结算频率的合约，如果连续16个周期资金费率的绝对值都 ≤0.025%，会在第17个周期**自动恢复**为4小时结算。
     * 当前结算频率通过实时资金费率页面或API（GET /fapi/v1/fundingInfo）查询

### （二）清算机制：维持保证金、标记价格、逐仓 vs 全仓、仓位档位、清算连环、ADL

什么是清算/爆仓：当你的保证金不足以继续承担亏损时，交易所强制关闭你的仓位。

1. 初始保证金 vs 维持保证金

   * 初始保证金（Initial Margin）：开仓需要的钱。决定最大开仓规模、杠杆倍数。
   * 维持保证金（Maintenance Margin）：维持仓位最低的钱。决定是否爆仓。
2. 维持保证金（Maintenance Margin）与触发条件

   * 保持仓位继续存在所需的最低保证金。
   * Collateral = Initial Collateral + Realized PnL + Unrealized PnL < Maintenance Margin
   * 账户余额(本金+已实现盈亏+未实现盈亏)跌破维持保证金这条线,就会触发清算。
   * Margin Ratio = Maintenance Margin / Margin Balance
   * Margin Ratio 到 100% 就是清算点,官方建议**保持在80%以下**。
   * 维持保证金是 **按仓位大小计算的,不是按你用的杠杆倍数计算的** 。
   * 反直觉的事实：小仓位在被清算时更容易变成"破产仓位“。因为对小仓位而言,有效维持保证金可能低于清算清算费率本身,不管最终成交价是多少。
3. 标记价格(Mark Price)

   * 主要与最新成交价(Last Price)比较
   * 清算永远由Mark Price触碰清算价触发，可以避免插针
4. 逐仓(Isolated) vs 全仓(Cross)

   * 逐仓：一个仓位只使用分配给它的保证金。风险隔离更安全，但容易被强平。
   * 全仓：所有账户余额共同支持仓位。系统会使用剩余账户资金补保证金。所有仓位共同承担风险，更难被单个仓位清算。
5. 仓位档位(杠杆分层 / Leverage Brackets)

   * 仓位名义价值越大,允许的最高杠杆越低、要求的维持保证金率越高,呈阶梯状分层。防止巨鲸爆仓造成市场冲击。
6. 清算流程

   1. Mark Price触及清算价 → 触发清算
   2. 立即取消该用户在该仓位下的所有挂单(逐仓模式只取消该币种的单;全仓模式取消账户全部挂单)
   3. 系统先尝试用“一笔大额IOC订单(IOCO)”把仓位甩卖进市场,尽量减少保证金缺口而不是直接全部强平
   4. 如果甩卖后剩余资产已经能满足维持保证金要求(扣除已实现亏损和清算清算费后),清算就此停止
   5. 如果IOC没能完全成交,剩下部分变成"破产仓位"(Bankrupt Position),由期货保险基金(Futures Insurance Fund)按破产价格接管,基金承担这部分损失
   6. 如果保险基金也无法覆盖 → 触发自动减仓(ADL)
7. 自动减仓(ADL, Auto-Deleveraging)

   1. **排队规则** :系统按一个综合了**盈利程度和杠杆水平**的指标(官方称为LeveragePnlQuantile)给交易对手方的持仓排队—— **盈利越多、杠杆越高的仓位,排在ADL队列越靠前** ,会被优先强制平仓来对冲掉那笔破产仓位的敞口。被ADL的一方是在**对面方向且没做错任何事**的盈利用户,不收取交易手续费,按被强平那笔仓位的破产价格成交。
   2. ADL的风险和"你自己有没有做错"无关—— **你可能因为方向做对了、杠杆开得高,而被别人的破产仓位连累强制平仓** 。
   3. 币本位合约(COIN-Margined)比U本位合约(USDⓈ-Margined) **更容易触发ADL** ,因为所有用同一种币做保证金的币本位合约共享同一个保险基金,基金规模相对更小。
8. 清算连环(Liquidation Cascade)

   1. 价格下跌 → 触及一批多头仓位的清算价
   2. 这些仓位被强制平仓,清算引擎的IOC甩卖单本身就是市价卖单 → 进一步打压价格(尤其在盘口薄的时候滑点更大)
   3. 这个新的更低价格又触及下一批(维持保证金率更薄、或开仓价更高)的多头清算价 → 循环下去,形成瀑布式下跌
   4. 这个机制解释了为什么Coinglass一类平台的"清算地图"能显示潜在大量杠杆仓位集中区域，所以才能大致预判连环清算可能发生的价位区间

* 高频交易：CEX-深度、速度、成本
* DeFi：钱包 + DEX-资产必须链上
* 长期持有：自托管-降低平台风险

CEX和DEX滑点区别

* CEX滑点类似股市，来自"吃掉订单簿上的多档挂单"。DEX滑点来自一个确定性的数学公式。
* **DEX的滑点是可以提前精确算出来的** ——给定池子当前的储备量和你的交易规模,代入公式就能算出确切的成交价,不需要"看盘口猜"。CEX的滑点只能通过看当下盘口快照估算,而且你看到快照和你的单子真正成交之间,盘口可能已经被别人的单子改变了。
  * AMM → 恒定乘积 x × y = k。买得越多，价格越来越贵。
  * 不仅是买的人越多，价格因为“市场情绪”上涨。**更是因为**自己的交易，就会改变池子的储备比例，从而改变下一笔交易的价格。
* DEX有一个CEX没有的额外风险层:你的交易本身是"公开排队"的*。DEX交易要先进入区块链的 内存池(mempool)等待被打包进区块,这段时间里任何人都能看到你这笔"待处理"的交易内容。这就给了三明治攻击(Sandwich Attack)可乘之机——有人看到你的大额买单还没成交,抢在你前面插入一笔买单把价格推高,等你的单子成交后价格进一步被推高,再立刻卖出获利,你实际吃到的滑点会比"理论计算值"更差。这正是笔记里提到的MEV/夹心攻击的具体发生机制——它和"滑点"其实是同一个问题的两个层面:滑点是价格移动的结果,MEV是价格被人为移动的原因之一。
* 也正因为这个"下单到成交之间价格可能变化"的时间差,DEX交易界面通常要求你设置一个 **滑点容忍度** (比如1%)——如果实际成交价格偏离超过这个容忍度,交易会直接失败回滚(但Gas费依然要付,这是DEX交易失败也要付费的一个具体例子)。

honeypot + NTV + Rug Pull

* honeypot 对市场的扭曲：它们限制卖出，使价格和交易活动看起来很繁荣，但实际流动性被困在合约中。价格上涨是真实发生的，但“你拥有可以兑现的财富”不一定是真的。
* 三个价格的区分
  * Displayed Price：界面告诉你1 COIN = 10 ETH
  * Mark-to-Market Value：钱包里有100 COIN，于是系统告诉你100 × 10 = 1000 ETH
  * **Realizable Value**：真正的问题：把 100 COIN 卖掉以后，到底能拿回多少 ETH？
* NTV:Net Traded Value
  * 与其只看“现在价格是多少”，不如看看这个 token 到目前为止到底发生了多少真实交易，并用当前价格把这些净交易量转换成价值。
  * NTV ≈“到现在为止净交易了多少 token”×“现在每个 token 的价格”
* Rug Pull：先让你正常交易，然后把池子里的流动性抽走。

#### 2.链上Gas费

1. **Gas** = 衡量在EVM上执行一次操作所需计算量的单位。每笔交易无论成功失败都要付费。
2. 总费用 = 消耗的gas单位数 × (Base Fee + Priority Fee)
3. **Layer 2扩容**可以降低Gas成本，降低的不是计算量而是单位交易承担的链成本。
4. gas费会波动，牛市会暴涨。因为区块空间有限，Ethereum每个区块能处理的数据有限。大量用户同时操作供小于求。

### （四）稳定币 (USDT vs USDC 储备模式差异；脱锚机制与历史)

稳定币（Stablecoin）：设计目标是保持相对稳定价值的加密资产。

能够维持1USD的原因：拥有储备资产（Reserve）

稳定币主要类型

1. 法币抵押型（Fiat-backed）。USDT/USDC。
2. 加密资产抵押型：DAI。不是1:1美元储备，而是超额抵押。
3. 算法稳定币。TerraUSD（UST）。

#### 2. 脱锚机制与历史（De-peg Mechanisms & History）

##### (1) 脱锚的基本机制

法币锚定型稳定币的核心锚定依托于**一级市场赎回套利机制**（套利者在二级市场低于 `$1.00` 买入，向发行方以 `$1.00` 赎回美金现金）。当以下因素发生时，会触发脱锚：

1. **流动性挤兑与抛售（Secondary Market Liquidity Run）**：二级市场（DEX/CEX 盘口）短时间内出现巨量抛单，而一级市场赎回通路由门槛、银行休市或额度限制无法瞬间消化套利，导致二级市场价格短暂与 `$1.00` 偏离。
2. **托管银行破产/资产冻结（Bank Insolvency Risk）**：发行方存放现金储备的法币商业银行发生倒闭或监管冻结，引发对储备资产足额率的恐慌。
3. **算法死循环（Algorithmic Death Spiral）**：如无足额法币储备的算法稳定币（如 TerraUSD / UST），依靠双代币铸造销毁套利，失信时触发无底洞超发引发归零。

USDT/USDC这类**足额抵押型稳定币**的脱锚,本质是"流动性/信任的暂时错配";UST这类**算法稳定币**的脱锚,本质是"设计机制本身的死亡螺旋"——两者虽然都叫"脱锚",但风险的 **可逆性完全不同** 。但UST从第一天起就是无真实抵押的算法设计,死亡螺旋是它机制里内嵌的必然路径;USDT/USDC是真实抵押,只有在抵押资产本身大幅贬值+挤兑同时发生的极端情况下,才会退化成类似UST那种自我强化的循环。 **换句话说:UST的死亡螺旋是"设计必然",USDT的类似风险是"极端尾部情形"** ——概率完全不同,但一旦真触发,循环的**数学形状**是相似的。

##### (2) 历史典型脱锚事件

* **USDC SVB 银行倒闭事件（2023 年 3 月）**：

  * **起因**：硅谷银行（Silicon Valley Bank, SVB）被监管接管，Circle 披露其 `720 亿美元` 储备资产中有 `33 亿美元` 的现金储备滞留在 SVB 无法取出。
  * **脱锚表现**：市场引发恐慌抛售，USDC 价格在大盘及 DEX 资金池中瞬间下探，最低跌至约为 `$0.87` ～ `$0.88`。
  * **结局**：随着美联储及 FDIC 宣布对 SVB 存款提供全额担保，Circle 承诺全额补足任何潜在缺口，USDC 在 72 小时内迅速回升并重新锚定至 `$1.00`。
* **USDT 历史脱锚事件**：

  * **2018 年 10 月事件**：因对 Bitfinex 与 Tether 储备资金链断裂的市场传言，USDT 出现剧烈抛售，在部分交易所（如 Bittrex）短时下跌至约 `$0.87` ~ `$0.90`。
  * **2022 年 5 月事件（UST 崩盘连带反应）**：算法稳定币 UST 归零引发全网加密资产海啸，恐慌情绪波及 USDT，在部分交易所（如 Kraken）一度短时跌至约 `$0.92` ~ `$0.95`。Tether 在随后的数周内顺畅兑付了上百亿美元的赎回申请，随后价格恢复平价。

### （五）真实交易成本:现货与永续费率表、滑点、资金费率成本的量级

真实收益公式=价格收益-交易手续费-滑点成本-资金费率-其他成本

* 现货主要：手续费、滑点
* 永续增加：资金费率、强平风险

不同策略影响成本的主要因素：

* 高频交易（交易次数多）：手续费+滑点
* 趋势交易：手续费+滑点+资金费率
* 长期持有：机会成本+托管风险

交易手续费和资金费率是两笔完全独立的成本,不能混在一起算"手续费"。

#### 三、滑点

产生原因：订单规模 > 当前流动性

**事实**:BTC/ETH这类主流交易对,在Binance这样的头部交易所,1万美元级别的市价单,滑点通常**极小**(盘口深度足以吸收这个量级而几乎不移动价格)。

**推断**：滑点大小取决于三个变量的组合——**交易规模相对盘口深度的比例、当下盘口的稀疏程度(小市值币天然更稀疏)、以及下单时是否恰逢流动性单薄的时段**。

#### 五、资金费率成本的量级

**事实推算**:

* 默认利率分量是**0.01%/8小时结算**(前提是溢价指数落在damper区间内,即市场没有明显偏多或偏空)
* 折算成**日成本**:0.01% × 3次/天 = **0.03%/天**
* 折算成**年化成本**(如果全年费率都稳定在默认值,这是一个理论上限参考,不是预测):0.03% × 365 ≈ **10.95%/年**

极端行情下资金费率成本的波动幅度,比手续费的波动幅度大得多,是永续合约里最容易被低估的成本项。

# 四、论文知识

* 概念解释

  * pump.fun是solana链上的一个发币+交易平台；Uniswaps是DEX，已发布Pools.trade对抗pump
  * 新币生命历程：新币诞生 → 早期交易 / 发售（Launchpad Sale阶段，价格按 Bonding Curve 绑定曲线涨） → Migration（卖到80%时，工厂自动把币和收到的SOL一起搬到 Raydium 这种大交易所，建一个公共池子） → 上 DEX → 散户大量进入市场 → 正常交易/内部人开始卖 → 价格崩溃
  * Bonding Curve：越早买的人，价格越低；越晚买的人，价格越高。
  * Insider：并非传统的内幕交易，而是开发者 + 与开发者存在协调关系、拥有信息或操作优势的账户。

A Sea of Coins：先告诉你“新币市场为什么看起来赚钱、实际上哪里出了问题” ➡️ MELT：再告诉你“既然风险来自早期参与者的行为，那能不能在危险真正爆发之前，从行为轨迹里把它识别出来？”

* 新币已经出现在 Uniswap V2 之后，我们看到的巨大涨幅到底有多少是真的
* 过去的欺诈手段：Honeypot(买得到，卖不了)/Rug Pull(流动性被抽走)/Sandwich(低流动性放大价格冲击)
* 时间错觉(swap time ≠ physical time)。swap time 下看起来非常漂亮的一些盈利机会，在真实 physical time 下可能根本无法执行

MELT：如果一个 token 在 DEX 上最后发生了巨大风险，那么我们能不能不要等它崩掉以后再识别，而是在它还处于 launchpad 阶段的时候就识别出来。

* MELT 不是预测 memecoin 价格，而是通过把链上交易转换成行为，再通过钱包关系恢复隐藏实体，提取早期集中控制和协调交易特征，用机器学习提前识别高风险 token。
* 在Launchpad阶段检测：谁在买？/买了多少？/谁和谁可能是一伙的？/是否有人用很多钱包？/交易速度怎么样？持仓是不是极度集中？从而预测未来风险确定哪个币危险程度高。
* **不能简单研究“价格”。应该研究人怎么行动**。原始链上交易只是底层程序调用，本身并没有直接表达“某人正在协调操纵市场”这种高层语义。真正有意义的信息需要通过行为抽取、聚合、特征工程以及跨账户关联才能得到。
* 论文排除资金来源为CEX的地址，因为CEX的转出记录通常只是普通用户提现，没法区分是不是协同控制。专业操盘手可以靠分批走不同CEX账户来绕开这条检测。
* Bundle Trace（捆绑路径）：① Multi-account co-purchase（多个账户在同一笔交易里共同执行买卖）、② Fund-flow relationship（不同账户由同一个资金来源地址资助）、③ Jito Bundle ID（Jito 可以让多笔交易以 bundle 的形式进行原子化执行。如果不同钱包的交易反复出现在同一个 Jito bundle 中，那么这些钱包很可能存在协调关系）
  * Multi-account co-purchase，是最容易被彻底躲开的一条。根本没必要把多个账户塞进同一笔交易里联合签名。
  * Jito bundle能躲开，但有代价。代价是失去了"原子化同时成交"这个真实好处（保证所有马甲钱包同一区块内一起买到，不被人插队）。所以它可以躲，但躲开意味着放弃一个真实收益，不是纯粹白躲。
  * Fund-flow relationship不可能完全躲开，但可以躲开论文实际用的这个具体检测法。 论文特意排除了资金来源是中心化交易所（CEX）的情况，因为CEX提现看起来就是普通用户在正常用钱，没法区分是不是同一伙人。这就留了一个明摆着的口子：老练的操盘手只要让每个马甲钱包从不同的交易所账户分别提现启动资金，而不是从同一个链上地址直接转账，这条检测线索就直接失效——钱最终还是同一伙人的，但论文这套方法完全看不出来。
