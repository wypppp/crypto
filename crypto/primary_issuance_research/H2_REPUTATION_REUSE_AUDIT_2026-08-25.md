# H2 声誉复用审计（2026-08-25）

## 结论先行

**“贡献换代币额度”暂不应作为主方向投入。** 现有公开证据能够证明平台内存在声誉复用机制，却不能证明这种机制已经产生足够大的经济复利。

更准确地说：

- `H2a 技能可迁移`：部分成立；同一开发者可以在相邻任务中重复获奖；
- `H2b 声誉可迁移`：平台内机制成立；Legion Score 和历史 CoinList Karma 会/曾会影响后续销售；
- `H2c 经济可复利`：未证实；没有公开数据表明获配概率提高多少、边际工时下降多少、年度可叠加利润有多大；
- `跨平台复用`：未证实；没有可重建的 CoinList / Legion / 项目贡献者联合身份与申请结果面板。

因此，H2 不是简单的“真”或“假”：**机制存在，但足以改变财富结果的效应量不可观测。** 对用户当前的资金与时间约束，这仍属于不可承保假说。

## 1. 把 H2 拆成三个可检验命题

只找出 5–10 个重复赢家，最多支持第一层，不能直接支持完整 H2。

| 命题 | 需要看到的证据 | 当前状态 |
|---|---|---|
| H2a：能力复用 | 同一个人在相互独立的项目中重复交付高质量贡献 | 弱支持 |
| H2b：声誉复用 | 控制当期贡献质量后，旧 GitHub、平台积分或历史获配会提高下一次获配概率 | 平台规则支持，效应量未知 |
| H2c：经济复利 | 随经历增加，每次获配所需新增工时下降，且年度净收益和容量上升 | 无证据 |

真正的承重墙是 H2c。若一个成熟贡献者仍需为每个项目重新投入 100–300 小时，重复中奖只是“强者重复劳动”，不是资本化声誉。

## 2. 为什么“找 5–10 个重复获配者”不是便宜的总体检验

### Zama 的获配总体不能映射到公开身份

Zama 官方披露 5,500 个 OG NFT 的类别数量，其中创作者 3,794、开发者 789、测试者 585、社区贡献者 332；但同时明确表示不发布各期排行榜。链上 OG NFT 合约只能给出持币钱包，不能可靠给出：

1. 钱包对应的 GitHub / X 身份；
2. 该钱包通过哪个贡献类别取得资格；
3. 该人还申请过哪些其他项目；
4. 未获选者和投入工时。

来源：https://www.zama.org/post/zama-og-nft-claim-portal-is-live

这使公开样本天然只包含主动展示成功经历的人，存在严重赢家选择偏差。即使找到十名重复赢家，也无法估计重复成功的基率；找不到也不能证明没有。

### 可确认的重复赢家只证明项目内技能延续

Zama 2025 年 12 月公开结果中，`Gavs / gustavovalverde` 同月同时获得 fhEVM Hub 悬赏第一名，并以 Zentity 入选 Builder Track。这证明专业能力可以在同一技术栈的相邻任务复用，但不是跨项目贡献者额度，也无法证明第二次成功由旧声誉而非第二份高质量代码造成。

来源：https://community.zama.org/t/zama-developer-program-december-2025-winners/4127

## 3. 平台规则确实支持“平台内声誉资产”

### Legion：H2b 的机制证据最强

Legion 官方把 Legion Score 称为多数销售的核心排序因素，组成包括链上活动、社交影响、GitHub 经历、平台参与和过去销售后的投资行为；并明确表示维护分数会提高当前及未来销售的获配机会。

但项目仍可设置项目特定条件并人工复核。官方没有发布按分数层级划分的申请数、获配率、中位额度或收益，所以无法把“提高机会”换算成每小时期望价值。

来源：https://help.legion.cc/en/articles/13189853-how-are-allocations-determined-in-a-legion-sale

### CoinList：曾有可量化的弱效应，但制度并不稳定

CoinList 旧 Karma 机制曾披露：Platinum 层在某场 2024 销售中的获配机会约为 Rust 层的 3 倍。这证明平台历史可以跨销售复用；但仍缺两个决定性分母：各层绝对获配率，以及获得/维持高层级的现金、风险和时间成本。

而且销售可以不采用 Karma，例如 Aligned Layer 销售明确按先到先得，Karma 不影响分配。到 2026 年，CoinList 又暂停旧 Karma，称在全链上、非托管转型中重新设计该机制；历史已被快照，但以后如何使用尚未确定。

来源：

- https://websocket.coinlist.co/help
- https://old.coinlist.co/help/why-can-t-certain-residents-and-citizens-participate-in-the-aligned-layer-token-sale
- https://old.coinlist.co/help

结论：CoinList 说明“声誉可以有用”，同时也说明它是平台可单方面修改、销售可选择不用的租赁资产，不是用户拥有的永久资本。

## 4. 与专利无效检索的相同与不同

### 相同之处

- 申请者/竞争者母体不公开；
- 选中常含项目方裁量；
- 大量失败投入不被补偿；
- token 特价额度有硬上限，Zama 单资格最多投入 $200；
- 只观察赢家无法给付出的免费期权定价。

### 不同之处

- Zama 部分赛道公开规则、名次和现金奖，共披露发放 $374,000；
- 代码、测试和技术内容会留下公开作品集，可用于合同、就业或下一项悬赏；
- Legion 明确把 GitHub、历史平台行为和投后行为纳入未来销售；
- Zama 等项目在 TGE 后仍有现金悬赏和 Builder 项目，而不只是一次 token 额度。

所以两者不是完全同类。**若目标只算 token 额度，类比成立；若把现金悬赏、合同和职业资本也计入，它应被重分类为“专业服务/悬赏生意”，而不是一级投资策略。**

## 5. 当前裁决

### A. 贡献换代币额度

从“优先方向”降为 **C：无真金、无百小时级前置投入，等待数据**。

原因不是已经证明负 EV，而是：

```text
EV = P(资格 | 身份、贡献、竞争) × 实际额度 × 可实现净回报
     + 现金/合同收入
     - 新增工时成本 - 资金与方向风险
```

其中最重要的条件概率和新增工时都无法从公开数据估计。用 Zama 的 11.88x 和 $2,176 上限替代这两个分母，会系统性高估方向。

### B. 协议悬赏 / 技术承包

作为独立的运营型生意保留待查。它有不同的研究问题：公开奖金总额、有效提交数、重复获奖者占比、获奖后合同转化率、所需技能和实际工时。Zama 已证明现金池真实存在，但尚未证明用户从零起步后的时薪和百万目标容量。

这条路线可以利用 LLM / RAG 背景，但模型只能降低交付成本，不能替代本人建立可验证身份、沟通和持续维护。

## 6. 重新开启“贡献换额度”所需的最低证据

满足任一项才值得重新投入研究预算：

1. Legion 或 CoinList 公布至少五场销售按信誉层级划分的申请数、获配率和额度；
2. 获得至少 30 名参与者的匿名面板：每次申请、分数/履历、结果、额度、工时和最终回报；
3. 能从销售合约重建跨场参与/获配钱包，并有可靠方式连接同一身份和贡献履历；
4. 做小规模前向实验，但预先设置每项目工时上限，并把现金悬赏、合同线索和 token 资格分别记账。

在这些条件出现前，不建议把 1.5 万元运营预算用于持续数月的无偿“刷贡献”。
