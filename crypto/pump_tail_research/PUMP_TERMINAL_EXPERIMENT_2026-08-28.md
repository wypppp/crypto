# Pump.fun 终局实验：T+30s / T+60s × entity × 可执行收益

> 状态：在读取新增特征和执行结果前冻结；只读历史 development，不授权实盘。  
> 优先级：排在 CCA 历史执行审计、CCA 前向观察器部署和 MetaDAO 前向观察器部署之后。观察器开始被动积累样本后可执行本实验，无需等待其最终解封。  
> 目的：用一次有明确终止条件的实验，处理现有研究仍留下的两个反事实——T0 至 T+5m 之间未测，以及 entity 对可执行收益尚未测。

## 1. 关闭范围与仍开放的窄问题

以下结论保持关闭，不因本实验重开：

- T+5m 及以后选毕业币右尾；
- T+5m15s 首触发 TP/SL 策略；
- 毕业后被动 LP 手续费策略。

唯一开放的问题是：

> 在无需毫秒级基础设施、但需要秒级自动监控的 T+30s 或 T+60s，使用当时已经公开可见的基础特征和保守 entity 特征，能否选出一个按真实池冲击和费用计算后、跨两个市场状态仍为正的固定仓位策略？

本实验不声称能够否定一切想象中的私有资金图、内部信息或同块策略。它决定的是：是否继续为“普通公开数据、点时可得、个人可运营”的 Pump 毕业后策略投入研究预算。

## 2. 两个冻结候选

只允许两个主候选，不增加第三个延迟点：

1. 决策截止 T+30s，固定计算和广播耗时 15s，成交锚 T+45s；
2. 决策截止 T+60s，固定计算和广播耗时 15s，成交锚 T+75s。

两个候选共同使用：

- 固定仓位：每币 **$250**；
- 入场门：成交锚时 `0.05 × 报价端储备美元值 >= $250`；
- 止盈：整仓可退出净值首次达到 2.0x，按 2.0x 封顶；
- 止损：整仓可退出净值首次低于或等于 0.5x，按首次真实可退出值结算；
- 超时：4h，以此前最后一个真实池状态结算；
- 实际链上费率，买入和卖出各额外计 100 bps 执行损耗；
- 恒定乘积双边池冲击和整仓退出，不用未来最高现货价代替成交。

$100 和 $500 仓位、其他 TP/SL/持有期只作描述性压力测试，不得替代主裁决。

## 3. 冻结样本与双状态要求

必须用相同 SQL 和相同本地代码覆盖：

- 2026-01-01 至 2026-02-28；
- 2026-05-01 至 2026-07-24。

不得只在其中一个时期开发参数后，把另一个时期改作不同口径。两个时期的 Jan、Feb、May、Jun、Jul 共五个自然月作为稳定性分段。

历史结局已经被研究者部分看过，因此本实验只能关闭方向或生成未来确认候选；历史正结果不能直接授权交易。

## 4. 点时特征

每个延迟点只使用该截止时已经出现的事件。特征名字和变换在查询返回前冻结。

### 4.1 BASE

- 报价币、初始报价储备与毕业时容量；
- creator 在当前毕业前已经发生的毕业次数；
- 截止时价格/毕业价、最高和最低倍数、池储备和容量变化；
- 买卖笔数、报价成交额、净买额、独立钱包/买家/卖家；
- creator 自买卖、单钱包成交额最大占比和成交额 HHI；
- UTC 小时和星期周期编码。

T+30s 不得读取 30s 之后的状态；T+60s 不得读取 60s 之后的状态。

### 4.2 WALLET_HOLDING 与 ENTITY_MERGE

沿用 `ENTITY_E1_IMPLEMENTATION_2026-08-28.md` 已冻结的保守实现：

- 迁移前逐钱包净持仓集中度；
- creator 持仓；
- 同一 Pump 交易内 2–8 个不同 user 且全部为 transaction signer 时才形成 atomic controller group；
- entity 持仓/成交集中度、覆盖率和 top entity 可售筹码相对池储备。

费 payer 相同、同区块、相似金额、公共路由和高扇出资金源不得合并。direct-funder、Jito 和 GNN 不在本实验失败后的追加菜单中。

## 5. 冻结模型和样本外预测

主模型为既有 HGB 参数，不重新调参：

- `learning_rate=0.05`
- `max_iter=200`
- `max_leaf_nodes=15`
- `max_depth=3`
- `min_samples_leaf=100`
- `l2_regularization=1.0`
- `random_state=20260824`

主特征为 `BASE_PLUS_WALLET_HOLDING_PLUS_ENTITY`。`BASE`、`BASE_PLUS_WALLET_HOLDING` 和 L2 Logistic 只作消融，不可在测试结果出来后取代主模型。

训练目标固定为该延迟、主执行规则下的 `net_roi > 0`。每个时间折只用更早的 train 拟合，validation 分数最高 10% 的阈值原样应用到下一段 test。所有最终收益只汇总首次样本外 test 预测。

具体日期折在特征查询执行前由脚本按每个状态的日期顺序机械生成；每折必须满足 train < validation < test，禁止随机切分。若任一状态无法形成至少一个含 100 个 test 样本的时间折，数据质量门失败。

## 6. 主指标

T+30s、T+60s 分别报告：

- 可执行母体数、选中数、正收益数；
- 选中集合平均和中位净 ROI；
- 按 UTC 日期 block bootstrap 的均值区间；
- Jan/Feb/May/Jun/Jul 五段 ROI；
- 选中容量 P10/P50/P90；
- 每周可部署名义本金与日历顺序账户曲线；
- BASE、BASE+holding、BASE+entity 的收益差异；
- atomic entity 覆盖率、组件大小和人工误合并审计。

不得用 AUPRC、count precision 或最高现货倍数替代净收益。

## 7. 历史 development 通过条件

两个延迟候选构成两次主检验，因此 bootstrap 使用 Bonferroni 调整后的单侧 97.5% 下界。某个候选只有同时满足以下条件，才允许进入未来 E2：

1. 样本外选中至少 100 个，且 Jan–Feb、May–Jul 两个状态各至少 20 个；
2. 合并平均净 ROI > 0，且按日 block bootstrap 单侧 97.5% 下界 > 0；
3. Jan–Feb 与 May–Jul 两个状态的平均净 ROI 都 > 0；
4. 五个自然月至少四个月平均净 ROI > 0；
5. 选中集合容量 P50 >= $250；
6. 每周可部署名义本金 P50 >= $10,000；
7. 点时生成、唯一 mint、费用和池状态完整性检查全部通过；
8. BASE+holding+entity 相对 BASE 的平均净 ROI 增量不为负，避免主结果由新增图特征拖累后仍被错误归因于 entity。

若两个延迟均不通过，Pump 终局实验失败，直接执行第 9 节关闭承诺。

## 8. 唯一允许的未来确认

历史候选通过只允许一次 E2：选择通过候选中**延迟更长的一个**，以减少速度依赖；模型、阈值、特征和执行规则全部原样冻结，在冻结日之后的新毕业币上前向运行，待结局成熟后只解封一次。

E2 必须重新满足第 7 节第 1、2、5、6、7 条，且平均 ROI 为正的自然月不得少于观察月的一半。E2 不通过即关闭，不返回历史样本修改规则。

## 9. 终止承诺

出现以下任一情况，整个“普通公开数据的 Pump 毕业后交易/LP/entity”研究预算永久归零：

- 两个历史候选均不通过；
- 历史候选通过但唯一 E2 不通过；
- 点时数据、秒级特征计算或成交基础设施无法稳定达到冻结时限；
- entity 覆盖率或误合并质量门失败。

关闭后不得用以下方式复活：新增 T+10s/T+90s/T+2m、改变 TP/SL/持有期、挑诊断仓位、增加 direct-funder/Jito/GNN、换标签为 rug/风险或只保留单一有利月份。任何依赖内部信息、同块 bundle 或私有订单流的机会属于不同业务，不再记为本方向的遗留反事实。
