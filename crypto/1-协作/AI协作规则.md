# AI 协作规则（路线图配套工具）

> 创建：2026-08-04 · 配套《加密资产研究路线图 v1.2》
> **这份文档不属于路线图修订**：它不改变目标、出口标准、预注册规则、时间预算或"不实盘"边界，因此不进变更日志、不触发冻结条款。它只规定"怎么用AI干活"。
> **写完就停。** 不要把它扩成 prompt 工程项目——那是准备递归的新入口。四个模板够用，用一个月后再按实际磨损调整。

---

## 一、核心判断：AI 的边界不在能力，在于"谁的能力在增长"

这份路线图的产品**不是那些卡片和备忘录**，而是三样东西：

1. 你能**独立做出可被判错的判断**
2. 你能**审计别人（包括AI）给你的材料**
3. 你知道**自己愿不愿长期重复这种工作**

AI 可以在两天内把10张机制卡、6个镜头、一份投资备忘录全部写完，质量还不差。**但那三样东西一个都不会增长**，而阶段5的决定完全依赖它们。所以委托原则是：

> **搬运可以给 AI，判断不能给 AI，反驳一定要给 AI。**

最后半句是重点：**多数人把AI当资料员，这是它第三好的用法。它最高的用法是当你的对手。** 你在研究里唯一无法自己提供的东西，就是一个不断试图推翻你的人。

## 二、四层委托分级

### T1 全权委托（AI做，你抽检）

没有判断含量的搬运与格式化：

- 术语解释、英文文档翻译与摘要
- 把交易所合约规格页/费率表整理成表格
- 把你的口述笔记套进模板格式
- 计算指标（累计收益、最大回撤、波动、Beta）、画图
- 数据抓取脚本、格式转换

### T2 协作（AI起草，你逐条核对到一手来源）

- 机制卡与镜头的**事实字段**初稿
- 死法案例的时间线梳理、对照组候选名单
- 投资备忘录的筹码结构部分（流通量/FDV/解锁/集中度）
- 回测与数据处理代码

**T2 的铁律**：任何要进你笔记的**数字**，必须你自己在来源页面上亲眼看到过。AI 给的数字一律视为"待核实的线索"，不是事实。

### T3 禁止委托（这就是路线图的产品，让AI做等于交白卷）

- **Mandate 的每一条**（尤其响应能力、待核实项、风险预算）
- **硬门槛的通过/不通过判定**
- **shortlist 的打分与取舍**、"我愿不愿长期重复"
- **机制卡的四个核心判断**：谁付钱 / 为什么还存在 / 需要我有什么 / 它怎么死
- **决策日志的每一条**（方向、概率、失效条件）——AI 写的判断不是你的判断，零训练价值
- **实验结论**（淘汰/证据不足/继续）、**阶段4-A 的 go/no-go**、**阶段5 的优先级决定**
- **出口问题的脱稿回答**

### T4 主动让AI当对手（最高价值，最被低估）

- 红队你的每张机制卡、候选卡、投资备忘录
- 审计你的回测代码找前视偏差（**包括审计它自己刚写的代码**）
- 找你论点的最强反方证据
- 检查你是否把推断写成了事实
- 扮演不同角色质询你（风控官 / 怀疑论者 / 竞品分析师 / 做空方）
- 阶段5 让它论证"你应该退出"，看你能不能反驳

## 四、固定上下文块（每次新会话开头粘贴）

```
【项目上下文】
我在执行一份自己写的加密资产研究路线图：纸面研究，不实盘，不建生产系统，
本阶段不做链上交互。产出物是可被判错的判断，不是漂亮的报告。

当前阶段：______
本次任务：______
你的角色：材料提供者 / 红队 / 代码协作者 / 考官  ← 选一个，不要串角色

禁止：
1. 不要给我方向建议（"你应该做趋势跟踪"这类）。我不需要结论，需要材料和反驳。
2 .不要编造任何具体数值。查不到就写"未获取"。
3. 不要把推断写成事实。事实/推断/假设三类必须分别标注。
4. 不要因为我的措辞而附和我的倾向。
5. 不要先夸再批，不要安慰。
```

## 五、四个模板（够用，不要加第五个）

### 模板1 · 事实提取（最高频）

```
任务：为【对象】提取可审计事实清单。不要写成文章。

输出格式，每条一行：
事实陈述 | 数值 | 一手来源URL | as-of日期 | 类型（事实/推断/假设）

硬性要求：
- 查不到或不确定的，写"未获取"，禁止估算、禁止"大约"、禁止"根据一般情况"
- 每个数值必须能在你给出的URL里被找到
- 不同来源口径冲突时，两个都列，并说明口径差异是什么
- 不要给结论、不要给建议、不要评价好坏
- 最后单独列出：这个话题里你查不到、但对判断很重要的信息有哪些
```

### 模板2 · 红队（最高价值）

```
任务：推翻下面这份产出。默认它是错的，你的工作是找出它为什么不成立。

【粘贴我的卡片/论点/结论】

要求：
- 按 致命/严重/次要 分级；每条给出具体失效场景（在什么条件下它就错了）
- 至少给出3条我自己没写进"风险"栏的问题
- 如果我把推断当成了事实，直接指出是哪一句
- 如果我的收益来源说不通（找不到付钱方或风险承担者），直接说
- 不要安慰、不要先夸再批、不要给改进建议——只找问题
- 最后回答一句：如果只能删掉这份产出里的一句话，删哪句？为什么？
```

### 模板3 · 代码协作（1-D 与 4-B 用）

```
任务：实现【需求】。

第一步（先不要给代码）：
1. 列出你将使用的数据字段、时间对齐方式、时区约定
2. 列出这个实现里所有【可能产生前视偏差】的位置
3. 列出你打算怎么处理缺失值，以及该处理是否会带入未来信息
4. 列出这个实现里【幸存者偏差】可能从哪里进来
等我确认后再写代码。

代码要求：
- 每个 shift / rolling / resample 旁边注释"为什么是这个方向/这个窗口"
- 额外输出一份可手工复算的3行中间结果（含每列的中间量）
- 不要静默 fillna，不要静默 dropna；任何丢弃都要打印丢弃了多少行
- 手续费与滑点作为显式参数，不要写死在逻辑里

写完后自己做一遍：假装你是审计员，找出这段代码里最可能出错的三个地方。
```

### 模板4 · 考官（出口问题验收）

```
任务：你是考官，不是老师。就【主题】考我，验证我能否脱稿回答。

规则：
- 一次只问一个问题，等我回答后再问下一个
- 我答错或答得含糊时，只指出"哪里不对/哪里含糊"，不要直接给答案，追问一次
- 追问后我仍答不上，才给答案，并告诉我这属于哪类缺口（概念/机制/数据/经验）
- 不要夸我，不要说"很好"。答对了直接下一题
- 全部问完后，只输出：我答得最弱的两个点是什么
```

## 六、这个任务里 AI 的五种失效模式（按危险程度排序）

### 1. 数字幻觉 —— 最危险

金融数值（TVL、解锁量、费率、历史价格、协议收入）的编造率高，**且编出来的数字看起来极其可信**（量级对、格式对、甚至带小数）。而这些数字恰好是你要用来做判断的。

> **规则：任何进入你笔记的数字，必须你自己在来源页面上看到过。AI 给的数字只是"去哪里找"的线索。**

### 2. 附和你的倾向 —— 最隐蔽

你说"我觉得趋势跟踪适合我"，它就会帮你论证趋势跟踪。**你前面向5个大模型描述背景+倾向、拿回5套各自自洽的框架，就是这个失效模式的产物。**

> **规则：提问时不要泄露你的倾向。** 要做对比就让它**同时论证正反两面**，或者**开两个独立会话，各让它论证一边**，然后你比对。

### 3. 把"历史上有效"当成"因果机制"

它会流畅地说"XX指标与价格正相关，因此可以用来预测"，却说不出谁在付这笔钱。

> **识别方法：追问"具体是谁承担了这个风险、谁付出了这笔钱"。答不出具体对手方或风险承担者，它就是在描述相关性。**

### 4. 不理解"点时可得"

默认会用**今天的**资产池、今天的成分、今天的排名去回溯历史——幸存者偏差与前视偏差的主要来源。除非你在prompt里明确要求，它不会自己想到。

### 5. 流畅性掩盖空洞

一段读起来很顺的分析里，事实、推断、假设混在同一句话里。

> **规则：要求分行标注类型，不接受散文体的研究材料。**

## 七、关于你的6卡4090服务器（诚实结论）

**这份路线图基本用不上它。** 原因：

- 没有不能上传的敏感数据（全是公开市场数据）
- 金融事实的准确性上，本地小模型比云端前沿模型更差，而准确性正是这里的关键约束
- 需要的算力只是跑 pandas 和画图，笔记本足够

**不要为了用上服务器而扭曲研究方案。** 它的价值在创业线（收入模型C：批量处理、内容生产、工具产品），不在这条研究线上。如果某天你需要批量摘要上千份英文文档或跑长期无人值守的数据管道，再把它拉进来。

## 八、一条自查题（每周问自己一次）

> **过去这一周，如果把我所有和AI的对话记录删掉，我还剩下什么？**

剩下的东西如果只是一堆AI生成的文档，这一周就是白干的。剩下的应该是：你能脱稿讲出的判断、你亲眼核对过的数字、你独立写下的失效条件、以及你在红队攻击下改过的想法。
