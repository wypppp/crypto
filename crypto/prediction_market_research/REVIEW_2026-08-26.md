# Polymarket 做市方向与外部评估复核（2026-08-26）

## 结论

做市方向不应因河北本地代理链路的延迟实验被关闭；但也没有任何可接受的前向数据证明策略为正。最准确的状态是：

> **候选保留，等待美国云服务器完成数据质量验证；收益、容量和百万目标适配均未通过。**

外部评估最有价值的两点是：不能把 `+0.863%/周转额` 当作新人基线，以及原来的 `edge ≥ 0.20%` 与 `周转 ≥ 10x/日` 联合门槛没有直接锚定个人目标。它最重要的错误是把 212 个未来 90 天内超过一万笔成交的钱包的“前 30 天”称为无偏新人基线；这是按未来活跃度选择后的条件样本，仍有幸存/持续运营偏差。

## 1. 逐项裁决

| 外部评估的说法 | 裁决 | 理由 |
|---|---|---|
| `-27.52%` 是唯一第一人称测量 | 部分正确 | 是唯一有成交回放的本地先导，但行情质量失败，不能作为正式收益估计。它是工程报警，不是可外推的策略 edge。 |
| 返利只有 `+0.53%`，缺口 51.7 倍 | 数学正确，证据用途被夸大 | 只描述那份失真的先导。它不能正式否决低延迟、带 fair value 的做市，也不能精确否决“返利覆盖小额基础亏损”的版本。 |
| `+0.863%` 是纯后验幸存者统计 | 方向正确，表述过强 | 钱包用前 45 天已结算结果选择、后 45 天评分，时间顺序没有直接偷看后半段 PnL；但母体先用完整 90 天 `>10k fills` 选择，且没有跨月份独立复验，因此只能产生假设，不能当新人基线。 |
| 本地延迟归因不清 | 正确 | 当前环境全部常见代理变量均已设置；本地代理是强嫌疑，但顺序实验不能证明硅谷服务器一定通过。 |
| fair value/逆向选择过滤从未正式跑过 | 正确 | 代码已实现一版，但没有质量合格的市场数据，因此没有有效收益结果。 |
| 1,400 美元能否达到 10x 日周转未测 | 原先正确；现在已有描述性先验 | 现有聚合数据可估 90 天平均 maker 周转/资本，但不能替代新进入者的排队和成交容量实验。 |
| 212 钱包前 30 天是无偏新人基线 | 错误 | 212 本身由未来 90 天高活跃选出；本地文件也只有 45 天聚合，不是逐笔或 30 天。 |

## 2. 现有数据新增结果

结果由 `analyze_maker_followups.py` 从现有三个 CSV 直接复算。

### 2.1 后来成为高频者，也不是天然赢家

| 条件样本 | 钱包数 | 盈利钱包占比 | 钱包中位 edge | 资本加权 edge |
|---|---:|---:|---:|---:|
| 前 45 天，全部角色 | 212 | 40.09% | **-0.268%** | +0.190% |
| 前 45 天，resting maker | 193 | 48.70% | **-0.046%** | +0.157% |
| 后 45 天，全部继续做 maker 的钱包 | 134 | 41.79% | **-0.454%** | **-0.165%** |

所以 `+0.863%` 不是一般高频 maker 的收益率，而是早期表现筛选后少数运营者的条件结果。它证明“存在可持续赢家”的可能性，不提供“我加入就能获得”的概率。

### 2.2 1,400 美元附近的周转不是天然 10x/日

描述性容量上界定义为：

```text
90 天已结算 resting-maker turnover（所有市场）/ 90 / 完整 90 天现金路径资本上界
```

在资本 $1,000–2,000 的 34 个可计算钱包中：

- 资本中位数：$1,357；
- 日 maker turnover 中位数：$387；
- 所有市场 turnover/capital：P50 `0.314x`、P75 `1.014x`、P90 `2.282x`、P95 `12.241x`；
- 只计 Crypto-5m 的近似值：P50 `0.124x`、P75 `0.489x`、P90 `1.562x`、P95 `12.236x`；现有聚合表没有单列 15m，所以目标 5m+15m 应位于 Crypto-5m 与所有市场两条描述线之间；
- 达到 `10x/日`：2/34，约 **5.88%**。

这不是可执行容量估计：它没有复原下单队列、同时订单规模、同一运营者多钱包和当期可见深度。但它足以推翻“10x 日周转对 $1,400 是默认可达”的假设。

### 2.3 条件赢家高度集中

前 45 天 Q5 钱包在后 45 天的 resting-maker 利润中：

- 第一名贡献 35.80%；
- 前五名贡献 67.24%；
- 前十名贡献 89.83%。

目前只能算钱包集中度；逐市场和逐时段集中度需要重新查询逐笔数据。同一运营者多钱包还会使真实集中度更高。

## 3. 原通过门需要改，但不能降低证据标准

背景文件的第一阶段资本目标是“一年内 1 万元到 10 万元”。若全年每日可复投，其净资本收益门槛为：

```text
required daily return = 10^(1/365) - 1 = 0.6328%
required 30-day return = 20.83%
```

因此应冻结的是联合经济量：

```text
净 edge/周转额 × 可实现日周转/资本 - 固定成本/资本 ≥ 0.6328%/日
```

原门槛 `0.20% × 10x = 2%/日`，若可连续复投，数学上对应约 81.1%/30 天、1,377x/年，明显高于“一年 10x”阶段目标。外部评估关于“可能误杀够用方向”的批评成立。

但不能因此删除以下证据门：无前视、保守 queue、基础 PnL 非负、日 block bootstrap 下界大于零、返利减半压力、故障压力和集中度检查。应该修改的是经济门的形式，而不是降低对数据质量和统计置信度的要求。

在 1 万元档：

- 若日周转 `10x`，所需净 edge 约 `0.0633%/周转额`；
- 若 edge 为 `0.20%`，所需日周转约 `3.16x`；
- 若采用资本 $1,000–2,000 条件样本的所有市场周转中位数 `0.314x`，则所需净 edge 约 `2.02%`；只计 Crypto-5m 的 `0.124x` 时约需 `5.10%`，都远高于现有候选证据。

当策略实际可承载资本达到 5 万美元以上，按用户接受的年收益目标改用 `2^(1/365)-1 = 0.1901%/日`，并重新实测容量；不能假定收益随资本线性增长。

## 4. 外部评估提出的五项分析，真实价值与成本

| 项目 | 现有数据能否完成 | 决策价值 |
|---|---|---|
| peak capital vs 日 resolved turnover | 只能做 90 天平均近似；已完成 | 有价值的先验，但不能代替自己的排队容量 |
| 212 钱包前 30 天 | 当前只有 45 天聚合；重跑也仍是未来高频条件样本 | 不能称新人基线，优先级低于前向策略数据 |
| 1/5/15 秒 markout | 不能；现有 CSV 无逐笔 token/时间/BBO | 高价值，应由美国云服务器的新行情直接测 |
| fill 价相对 0.5/距结算时间 | 需重跑逐笔 SQL | 可描述运营区间，但市场价本身不是外部 fair value |
| PnL 的市场/时段集中度 | 钱包集中度已完成；市场/时段需逐笔 SQL | 高价值，正式实验必须报告 |

真正全体 31,503 个首次可观察钱包的 30 天基线需要新的链上查询。它可描述参与者基率，但无论正负都不能替代特定 fair-value 策略的前向检验，因而不是启动云端实验前的阻断项。[Dune 执行 API](https://docs.dune.com/api-reference/executions/endpoint/execute-query)需要 API key；Polymarket 官方的[链上数据资源页](https://docs.polymarket.com/resources/blockchain-data)另推荐 Dune、Goldsky/CryptoHouse、Allium。

## 5. 云服务器实验顺序

### Gate A：同时同市场 A/B 延迟归因

- 河北本地代理与硅谷服务器同时订阅相同 BTC-5m token；
- 按 `transaction_hash + asset_id + source timestamp` 匹配同一事件；官方[实时行情文档](https://docs.polymarket.com/market-data/realtime-data)明确给出这些成交字段和毫秒时间戳；
- 两端都记录 CLOB `/time` RTT/偏差，避免本地时钟误差；
- 至少跨 24 个连续市场（2 小时），不能只挑一个低流量窗口；
- 云端每市场 `last_trade_price` 至少 30 条时，P95 ≤ 5 秒、P99 ≤ 10 秒，且无持续增长的 age slope。

若云端通过、本地失败，支持代理归因；两端同事件同时迟到，支持服务端/上游补发；只有某个连接随机失败，则需要多连接冗余或更换客户端。

### Gate B：72 小时云端工程采集

只验证覆盖率、重连、迟到、写盘和市场切换，不输出收益结论。72 小时通过后才开始冻结的 14 天收益实验。

### Gate C：14 天收益与容量

fair value、库存 skew、stale filter 和参数在开始前冻结。主输出改为：

```text
净日资本收益 = base PnL + actual/estimated rebate + rewards - 云成本
              ------------------------------------------------------
                            peak external capital
```

同时报告返利归零/减半、资本 $1,400 与 $50,000 的深度约束、开发工时和第 3 个月预计维护工时。

## 6. 分支承诺

- A/B 云端仍未过延迟门：关闭“普通公网短周期做市”，不再用本地网络解释。
- 云端质量通过、但 14 天基础 PnL 下界 ≤ 0：关闭 fair-value 被动做市；补贴不能单独救活。
- 基础 PnL 为正但联合日资本收益低于 0.6328%：不作为 1 万到 10 万主线；只在大资本档年化 ≥100%、容量与工时合格时保留为辅助策略。
- 联合目标通过但收益集中在一天/一个币/少数异常市场：延长独立样本，不进入实盘。
- 全部门通过：只进入最多 $100、两周工程实盘，验证真实排队、撤单和到账返利。

## 7. 制度更新

截至 2026-08-26，官方[费用表](https://docs.polymarket.com/trading/fees)仍列 Crypto taker fee rate `0.07`、maker rebate `20%`，但当前[Maker Rebates](https://docs.polymarket.com/programs/maker-rebates)写为每日以 pUSD 支付。官方[pUSD 说明](https://docs.polymarket.com/concepts/pusd)称它是 Polygon 上由 USDC 支持、可按合约 unwrap 的 ERC-20。历史公开 `MAKER_REBATE` 活动仍作为历史付款证据，不能据此固定未来支付资产或规则。
