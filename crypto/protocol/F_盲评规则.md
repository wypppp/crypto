# 附录 F · 多模型评审规则

## 1. 两轮结构

**第一轮 · 同题盲评**：各模型拿**完全相同的事实包与截止时间**，**不带此前任何评审结论**，独立输出：
判决（STOP / PROBE / HISTORICAL）｜三个最关键前提｜最大死因｜置信度。互不可见。

**第二轮 · 对抗**：再分配 steelman / red team / method auditor。

## 2. 裁决规则

- **不按 2:1 投票。** 多模型不是多份独立证据——它们可能共享训练材料与系统性错误。
- 每条关键事实必须落到**一手来源或可复算结果**；转述不算证据。
- 冲突由**证据质量 + 代码复算 + 定义一致性**裁决。
- **三家一致但无外部证据 → 结论仍为 `UNVERIFIED`。**

## 3. 已发生的评审失效案例（记录用）

- **锚定**：评审只在已搭好的框架里挑毛病。v3–v6 期间没有一次评审说"推倒"，每一版都在"新增报告义务"。杀死 HIP-3 的那条（oracle 外部定价）来自去读一手文档，而不是评价方案。
- **协议膨胀**：三份评审对 v1 大纲共提出约 25 条新增要求。**若全部并入，协议会比它治理的研究更重**——这是 v3→v6 失败形态升了一层。**故本协议分两层：操作核心 ≤2 页，其余入附录。**
- **重开已裁决项**：评审曾试图把"财富目标 vs 找真 alpha 谁优先"重新变成待议项，而使用者已明确裁决"只接纳能承担主要财富目标的方向"。**已裁决项不因评审提问而自动重开；重开需要新的实证数据（原则 #9）。**
