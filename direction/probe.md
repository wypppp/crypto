### 检查项 2:每单位名义额的 edge 不能直接进账户级复利递推

Mandate B-1 的递推是 `W ← W × (1 + f·r)`。**`r` 必须是一轮完整账户资本周转的净收益**,不是一笔成交的 edge,**也不是一个 episode 的中位数**。

已发生的三次违反:

- **GPT5-A2**:以「组合结算窗口数 × 总仓位 75%」为收益基数。`λ_opp = 1,095 = 3 × 365` 在定义上假设**全年每个结算点都有 5 个币在持仓**;且 `λ=500` 与 `f=0.75` 是**同一假设的两次计费**。
- **OP5-D2 的反解**:把做市映射到 B-3 的 `n ≥ 250` 行,并把 `δ = 0.66%`(`3× 往返` 的**筛选阈值**)当成本地板。实际往返 0.22%,且**做市方不付 taker 往返**。
- **v0.2 的 Probe F 杀线**:用 **episode 中位数**去判整个分支。中位数为负不排除少数长 episode 贡献全部利润(例如 60% 略亏 + 40% 大赚)。**这是同一形态的第三次违反,v0.3 已删除该杀线。**

**正确形式**:

```
账户级每轮净收益 = Σ(成交名义额 × 每元净 edge) / 账户权益
```

先按**预先冻结的槽位选择规则**重建账户时间线,再进递推。任何 Probe 报 `r` 时必须同时报它对应的周转口径与聚合方式。

#### 2a:`B-1` 的 `f = u·L` 有两种互斥读法,母体不同不能混用

`候选卡.md` 附件二 B-1 写 `f = u·L`(u = 实际资本利用率),同时又写 `n = min(λ_exec, K × 365/H_天)`。
**这两句只在连续型母体上同时成立**,在事件型母体上同时用就是把资本闲置计两次。

| 母体 | `n` 的含义 | `f` 的正确取值 | 闲置/并发/容量从哪里进 |
|---|---|---|---|
| **连续型**(carry、做市) | 结算或复利期数 | `f = u·L`,u 为期内平均利用率 | u 本身 |
| **事件型**(n = λ_exec) | **已执行事件数** | **`f = φ`,单次事件的仓位比例** | 闲置 ⟹ 已由 λ_exec 的稀疏性表达,**不得再乘占用率**;并发 ⟹ 由 `n = min(λ_exec, K × 365/H)` 进入;容量 ⟹ 由 `f = min(φ, C_abs/W)` 进入(`AUDIT_12.md` 记的 v3.0 口径) |

**v0.3 在 Probe L 上违反了这一条**:λ=60 已是 λ_exec,却又把 f 从 0.10 乘占用率降到 0.05 / 0.03。已删除。

#### 2b:计数单位与仓位单位必须同源

按什么计数,就用什么口径的仓位与收益,不得交叉:

| 计数单位 | 仓位 | 收益 |
|---|---|---|
| 按**已执行仓位**计(`λ_exec`) | 单笔 `φ` | 单笔净收益 |
| 按 **cluster / episode** 计 | `f_cluster = Σφ_i`(该 cluster 内全部已选仓位) | 该 cluster 的**聚合**净收益 |

**v0.3 在 C1 上违反了这一条**:出口线用 `λ_cluster`,反解却配单笔 `f=0.50`。一个 cluster 可含一笔或两笔同时仓位,两者不同源。已改为按 cluster 聚合。
(注:确定性上界下两种口径只差 `0.25r²` 的二阶量;但 B-1 是**顺序递推,无法表达同时持仓**,所以按 cluster 计数时必须聚合。)

#### 2c:五次之后,不再往下加行

检查项 2 至此已记录**五个实例**:GPT5-A2(名义额→权益)、OP5-D2(筛选阈值→成本)、v0.2 的中位数杀线(中位数→均值)、
v0.3 的 Probe L(占用率→仓位)、v0.3 的 C1(cluster→单笔)。**每次搬运的具体形态都不同**,说明这不是五个可以逐条堵住的疏忽。

共同点是同一个动作:**把一个局部量手工搬进账户级闭式递推**。

⟹ **规则**:再出现第六次时,不要再往本节加一行。把它当作"该闭式递推不适合手工套用"的信号,
**直接按冻结规则重建账户时间线并数值求解**,不做闭式反解。
本文件里的所有反解表(§1)自此只作**量级定位**用,不作判决依据;判决一律要求账户时间线。

### 检查项 6:改母体是允许的,但它产生一张**新卡**

v0.6 写过"不得改母体",**这条已废止**。Mandate 要找的是可行的利润机制,不是维护某个场所;
`mandate.md §0` 明确子方向来自**市场摩擦**,场所只是实现选择。冻结规则要保护的是两件具体的事,不是场所本身:

1. **冻结必须发生在拉数之前**,不得看到结果再调参;
2. **不得沿用旧卡的先验与编号**。

因此换场所的正确做法是:

| 允许 | 禁止 |
|---|---|
| 换场所、换母体,只要数据可得 | 换完仍用原卡编号 |
| 换完**重新冻结**全部参数并记录时间 | 沿用原卡的 `λ / q / f` 假设 |
| 换完给**新卡 ID**,注明派生自哪张 | 沿用原卡的"无反向证据"状态 |
| 把原场所版本留作**跨场所稳健性检查** | 用新场所的结果去替原卡"平反" |

⚠ 特别地:原卡的**死因是否随场所迁移,必须逐条重问**。例如 `#40`(HL 拥挤度已被免费工具覆盖)是 HL 特有的,
但换到 Binance 后**必须重新问同一个问题**(Coinglass 等是否已覆盖),**不得**因为换了场所就默认该死因消失。

### 检查项 7:**我自己管道的输出,也不是实测**

检查项 1 是对**别人卡里**的数字设的。2026-09-03 的教训是:**它对我自己写的 print 语句同样适用,而我一次都没用过。**

本轮实际发生的失误,归为四个生成器:

| 生成器 | 实例 |
|---|---|
| **A · 把脚本打印当测量** | `sorted(duration)` 排序后按事件时间序配符号 ⟹ **HIPPO 1,356h 被写成 8h**;`grep -c` 在单行 XML 上数行数 ⟹ 退市币 ALPACAUSDT 被误判为归档中不存在;cap 按**字符串**计数 ⟹ "10 个值"实为 8 个;`abs(gap-1.0)<1e-6` ⟹ HIPPO 因亚秒偏移出局,一度得"正侧=3" |
| **B · 一次失败的访问路径 = 关于世界的事实** | `fapi.binance.com` 451 ⟹ 写成"cap 表不可得"(**从未试过 `www.binance.com/fapi/...`,实际 200**);HL GET 405 ⟹ 写成"本机不可达"(**从未试过 POST**);S3 超时 ⟹ 差点写成"桶不可得"(实为沙箱主机限制) |
| **C · 想要的结果检查得更少** | "正侧 = 0"、"HL 无历史 OI" —— 都很干净、都关掉一个分支、都差点发出去。救回"正侧=0"的不是刻意核查,是**碰巧注意到 `max(正值)=+2.0000%` 与之自相矛盾** |
| **D · 冻结与执行同进程,无闸门** | C1-BN 实跑时截止日由 2026-02-28 漂到 2026-09-03、留出方式由时间换成符号,**漂移时没有任何东西会响** |

**必须说的不对称**:这次所有错都**削弱**了结论,所以被发现了。
若 HIPPO 的 1,356h 配给了 CUDIS,错误会让论证看起来**更强**——**而没有人会去质疑一个更强的支持性结论**。
⟹ **加强结论的错误更危险,却更难被抓。**

#### 七条机制(不是"更仔细")

| # | 机制 | 针对 |
|---|---|---|
| 1 | **报告里每个数字必须从文件读,不许从终端誊抄。**生成报告的脚本读 CSV/JSON,不复述我看到的 | A |
| 2 | **没有先打印分布,不许写容差常量。**`1e-6`、`0.001` 两个都是拍的 | A |
| 3 | **任何「X 不可得」需 ≥2 条不同访问路径 + 每条的实际错误码。**451/405/超时是三个不同事实;`000` 不是事实 | B |
| 4 | **一致性断言必须在出报告之前跑**:`count(正)==0` 要与 `max(正值)` 对撞;`λ_episode ≤ λ_symbol`;各分类桶求和 == 总数 | C |
| 5 | **结果越是关掉分支、越省事,越要加检查**(把天然激励反过来) | C |
| 6 | **冻结文件由脚本运行时读取,不由我读。**样本边界、留出定义、阈值作为 config 载入并**回显到输出头**;漂移变成不可能,而非"不鼓励" | D |
| 7 | **能机械化的自查,不外包给评审。**评审不可替代的是"冷读产物、不受我的叙事牵引",不是替我跑断言 | 全部 |

⚠ 机制 4 单独就能拦住本轮 6 个错里的 3 个。
