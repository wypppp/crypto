## 一、这个项目在做什么

在币安现货**新币首发上市**这一事件上，建立一个**来源可追溯、逐条可对账、可复现**的研究母体，为后续的价格侧测量提供锚点。

**当前尚未产出任何收益、频率或价格代理结论。** 全部工作停在"母体是否可信"这一层。

工作分五个阶段，每阶段独立产物、独立断言、fail-closed：

```
L_03 分类     公告 → 候选事件(不做首次/新增裁定)
L_09 B_RESOLVE 用归档日粒度证据裁定 B 候选
L_10 TIME_CHAIN 应用时间更新公告,保存完整版本链
L_11 JOIN      三阶段逐条连接 → U_master = U_trade ∪ U_announcement
L_12 精确 T0    在公告所列交易对中取 >= T_scheduled 的最早 aggTrade
```

## 三、这个项目真正的产出：一套被反复击穿又修好的验证纪律

回头看，代码和数字只是副产品。真正积累下来的是**一份"我会怎样骗过自己"的清单**——每一条都是被实测打脸打出来的。

### 3.1 反复出现的同一个病：成功标记强于证据

精确 T0 这一支，同一个不变量被**连续击穿四次**，每次我只堵了被指出的那一条路径：

| 次 | 缺陷 | 表现 |
|---|---|---|
| 1 | 交易对下载失败只记 `errors` 后继续标 OK | 令 GALABNB 失败仍报 206/206、退出码 0 |
| 2 | 归档内 config 与产物 sha 不符 | 包看着完整，实际重跑被前置检查阻断 |
| 3 | **缓存读取路径**未验证 | 改缓存 `checksum_verified=false`，记录被静默滤除，仍标完整 |
| 4 | 准入只校验元数据，**不验成交行**；且新下载路径根本没调用准入函数 | 成交时间改到阈值前 1μs，仍标完整、`lag=-0.000001s` |

**最终修法不是再堵一条路径，而是改按不变量设两层独立防护**：

- **记录准入** `record_ok`——缓存与新下载**调用同一个函数**，校验元数据 + 成交行（时间 ≥ 阈值、≥ 当日最早、UTC 日期匹配、id 非负有序、价量**有限且为正**、标志合法）
- **结构性完整**——要求"已验证交易对集合 == 公告清单集合"，不依赖任何具体失败路径
- **写出前独立断言**——对产物本身核验，不复用准入函数

配 **17 个注入反例**（A–Q），其中 **G 与 O 专门绕过第一层**，用来证明第二层不是复述。

### 3.2 断言必须验证它声称验证的东西

- `1MBABYDOGE 事件数 == 1` 长期为绿，绿的来源却是**另一篇公告**的新报价对事件。它声称验证空格规范化，而那段代码**从 v1.8.8 起就是死代码**——`PAIR` 的 base 字符类排除空白，`re.sub(r'\s+','',b)` 永远无事可做。后果是 2024-09-16 的 1MBABYDOGE 首发上市**缺失了七个版本**。
- `expect_times` 比较时间**集合**，发现不了"资产在两批之间互换"。反例实测：交换 APE 与 CETUS 的批次时间，**事件总数与时间集合完全不变**，旧检查通过。改为比较 `(base, T_scheduled, generator)` **完整多重集**后才拦得住。
- TIME_CHAIN 静态索引下，连续两次更新 A→B→C 的第二跳变成 AMBIGUOUS，**而全部断言照样通过**——缺陷完全不可见。

### 3.3 名称形态不是证据

- 曾用"代号以 B 结尾且 T0 ≥ 2026-06"把 56 个资产判为代币化股票，还把这个判断**排在"是否被公告提及"之前**，因而掩盖了它们其实有 bStocks 专项公告。改为按公告证据识别。
- 更早还有 `FUSDT → Ford`、`TUSDT → AT&T` 的同类误判。

### 3.4 弱判据的否定结论最危险（本轮自查发现）

我用标题级判据扫 catalog 49，得 0 命中，宣布"不含首发上市公告"。随后在 catalog 48 上标定该判据：**漏检率 76.2%**——正文含首发上市强措辞的 671 篇里，511 篇标题不含，其中 **125 篇实际就是上市类事件**（`Introducing X on Binance Launchpool / HODLer Airdrops!`，措辞全在正文）。

**结论已撤回**，正在抓 3,041 篇正文重扫。这是第五个变体，也是第一个我自己先查出来的。

### 3.5 其它被实测推翻的东西

- `sorted(duration)` 配时间序符号 → HIPPO 1,356h 被写成 8h
- `grep -c '<Key>'` 在单行 XML 上数的是行不是匹配 → 误判 ALPACAUSDT 不在归档
- 批量 curl 返回 `000` 被当成"不可达"，实际 HL 是 GET 405（POST 可用）、fapi 是 451 地理封锁
- 从未试过 `www.binance.com/fapi/...`，据此宣称费率上限表"无法获取"了好几个版本
- 引用了一条**不存在的条款**去正当化一个事后加的名称过滤器
- 违反自己冻结的样本（C1-BN 跑到 2026-09-03 而非冻结的 2026-02-28，还调换了留出类型）
- 直接 `json.dump` 覆写 config，异常时留下**被截断的 config**，靠 `archive/v1.8.29` 按哈希恢复

### 3.6 沉下来的机制

1. **报告里的数字必须从文件读，不得从终端转抄。**
2. **每个版本的 config + 代码 + 产物 + SHA 一起归档**，且包内 config 必须与全部产物的 `config_sha256` 一致——归档要能**原样重跑**（v1.8.40 实测 46/46 逐字节一致）。这条规矩在 config 被写坏那次真的救回了东西。
3. **config 是唯一可执行来源**，正则以字符串存储、由代码编译；改判据先改 config。
4. **config 用原子写入**：临时文件 → 校验可解析 → `os.replace`。
5. **任何"不可获取"的声称需要 ≥2 条访问路径 + 记录错误码。**
6. **每条修复都要配注入反例**，且反例必须能触发 fail-closed——只看行为变化不算。
7. **证据不足者明确保留待裁定**，不为清零强行归类。
8. **分类阶段不得读 T0 文件**（有 `open` 守卫，注入即 `ISOLATION VIOLATION` 退出）。
9. **留出集的行情文件根本不下载**，文件系统级可核验（实测 t0rows 中留出对文件 0 个）。

## 四、被外部审查纠正的关键判断

这些不是我自己想到的，是审查逐条打回来的：

- **不能把"归档取代公告"当作方案**，应做**双框架联合母表**
- **仅凭"未匹配上市公告"排除 TRADE_ONLY 违反冻结口径**——`join_classes` 明写它们"照常参与收益统计"。我那样做等于让公告解析能力**第二次**决定研究母体。
- **标题上市声明可用，但必须逐资产指向**，不能用 `body_or_title` 无条件关键词匹配
- **盘前应按交易阶段排除，不能永久剔除整个交易对**
- **`SCHEDULE_UPDATED_OR_CANCELLED` 是标签不是互斥类别**，参与守恒会重复计数
- **负 lag 为零是筛选条件保证的**，不能据此证明没有提前成交；独立证据应改用"当日最早成交早于阈值的交易对"（实测仅 `RED/REDUSDT` 一对，正是盘前）
- **`agg_trade_id == 0` 支持首笔判断，但不宜扩大**为对历史覆盖风险的整体排除
- **身份关联 ≠ 资格排除**：`NU + KEEP → T` 不是简单改名，旧 `LUNA → LUNC` 不等于新 `LUNA`，`FXS → FRAX` 不能按字符串合并

## 六、一个有策略含义的实测发现

滞后哨兵（206 条完整验收事件）：

| 统计 | 值 |
|---|---|
| 恰为 0.000s | **190** |
| ≤1s / ≤1h / >1h | 1 / 7 / 7 |
| 最大 | **28,800s（8 小时）** |

15 条晚开的事件，逐条检索 ±4 天内提及该资产的全部公告，**在已检索范围内未找到任何时间变更公告**；抽取也无误（原文确实写 CVX `06:00`、OP `04:00`），而该公告所列的**全部**交易对都在更晚的同一时刻开盘。`tentatively` 措辞无判别力（延期组 2/15，准时组 1/191）。

**含义：公告时间不能当作可执行的开盘时刻。** 约 7% 的事件实际晚开、最长 8 小时，且事先无公告可依。这加强了 `lambda_exec` 仍为 `UNIDENTIFIED` 的判定。价格代理以**实际 T0** 为锚，故测量本身不受影响。
