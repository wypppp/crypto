| 候选 | 在窗口内由该工厂新建、恰有一侧 WETH 的池 |
| 另一侧名称 | `target_token`，即目标代币；**新池不证明代币首次发行或首次交易** |
| 唯一键 | `(chain_id, factory, pair)`；同工厂 token0/token1 有序对唯一 |
| 确认快照 | 运行开始固定 `finalized` 块号、时间戳、hash；不随 `latest` 漂移 |

地址由 [Uniswap 官方部署表](https://developers.uniswap.org/docs/protocols/v2/deployments)支持；具体端点仍须核对代码存在、router.factory/WETH、pair.factory、token0/token1、factory.getPair，并留代码 hash。读取接口符合不单独构成字节码完全等价证明。

全量枚举方案：

1. 按**实际区块时间戳**定位 `b_start = 首个 timestamp >= 起点的块`、`b_end = 首个 timestamp >= 终点的块 − 1`。
2. 在 `b_start−1` 读 `allPairsLength()` 得 `i0`，在 `b_end` 读得 `i1`。
3. `[i0,i1)` 是新建池的工厂索引区间，`N_all = i1−i0` 是**所有配对资产**的新池数。
4. 逐索引读 `allPairs(i)`、token0/token1，确认 WETH 条件，得候选数 `N`。保留非 WETH 与读取失败条目，核对 `已确认 WETH + 已确认非 WETH + 待识别 = N_all`。
5. **有待识别条目时 N 未知，不能声称完整分母或进行正式抽样推断。** 可以交付覆盖率与阻塞日志，不能只采读得到的池。

[Factory 源码](https://github.com/Uniswap/v2-core/blob/master/contracts/UniswapV2Factory.sol)支持注册表和索引推导。此法不依赖大范围 `eth_getLogs`。枚举不是“两个调用完成”，后续工作量随 `N_all` 增长。

## 2. 首次 Mint、触发截止与随访

**触发资格明确限定为：候选的首次 Mint 在上述创建窗口结束前发生。** 本版新增这个截止，避免无限等待首个 Mint、事后剔除尚未成熟对象。截止后才发生 Mint 的池不追加入本次可触发集合。

| 时间/字段 | 定义 |
|---|---|
| `pair_created` | 工厂创建事件的块、交易和日志位置 |
| `first_mint` | 该 canonical V2 pair 历史上首个 Mint 的块与日志位置 |
| `trigger_status` | `triggered_in_window` / `no_mint_by_cutoff` / `trigger_unknown` |
| `entry_state_block` | `mint_block + 1` 的**块末状态** |
| `entry_reference_time` | `entry_state_block` 的实际 timestamp |
| `exit_reference_time` | `entry_reference_time + 2,592,000 秒` |
| `exit_state_block` | 首个 timestamp 不早于 exit_reference_time 的块，使用其**块末状态** |

`eth_call(..., block)` 使用指定区块的状态快照。这里的“+1 块”是**快照设计**，不宣称订单在下一块内部已成交：它已包含那一块的真实交易。真实可成交时间、排序和自身参与后的路径尚未重建。记录参考时间与实际使用快照的时间差。

**首次 Mint 的定位：** 对标准 V2，首次成功 mint 永久锁定最低 LP 份额，`totalSupply()>0` 在此后保持为真；可在已验证的假/真边界上二分。**空 `eth_call` 返回不是零**：需 `eth_getCode` 明确证实合约尚不存在，否则是解码/数据失败。定位后核对相邻块状态，并用**该块单块 Mint 日志**交叉验证、取最早交易/日志位置。

`getReserves()>0` 不满足这一条件；`sync()` 能在首次 Mint 前更新储备，储备以后也会变化。首次 Mint 是本轮选择的触发，不是“此前物理上绝不可能 swap”的定理。[Pair 源码](https://github.com/Uniswap/v2-core/blob/master/contracts/UniswapV2Pair.sol)

30 天按秒定位；12 秒是 PoS slot 长度，slot 可以缺块，不能固定换成区块数。随访是否成熟由上述 exit 时间与冻结快照比较，不根据“窗口距今几个月”猜测。[Ethereum PoS 文档](https://ethereum.org/developers/docs/consensus-mechanisms/pos/)

## 3. 抽样与分母

- 在 N 全部识别后，按工厂索引升序建立抽样框，取 `n = min(300, N)`；N=0 则报告空母体，停止推断。
- 无放回抽样：Python `random.Random(20260909).sample(range(N), n)`；保存 Python 版本、完整抽样框 hash、种子、抽中的索引与 pair 列表。不能因失败/难测而替补候选。
- 提前核验用的正常控制币默认 DAI；必须首次 Mint 早于候选窗口。控制币和人工选择的受限案例不计入 n，不贡献发生率。

**本版主发生率口径明确为：全部新建 WETH 候选中，在截止前触发且按本规则成功入场、能够确认 `M >= 10` 的比例。** 与“买入成功后的命中率”分开报告。

| 分母 | 用途 |
|---|---|
| `N_all` | 全资产新池枚举完整性 |
| `N`、抽中 `n` | 全部 WETH 新池的机会基础率；主分析分母 |
| 抽中且触发的数量 `n_triggered` | 触发覆盖；包含后续买入失败者 |
| 抽中且买入成功的数量 `n_entered` | 单笔 M 分布的条件分母 |
| 可以判定右尾与否的数量、完整随访数 | 数据质量；不得自动当作更干净的替代主分母 |

`no_mint_by_cutoff` 的主机会指示量 Z=0，**M 不适用，不记作交易全损**。已证实在有效模拟环境下买入失败的候选，本规则无入场，Z=0，记录失败 gas；环境搭错或数据缺失则 Z 未知。

## 4. 买入数量的测量

投入 **0.05 ETH = 50,000,000,000,000,000 wei**，固定规模，直接路径 `[WETH,target_token]`。

标准 V2 储备公式（整数向下取整）：

```
quote_out = floor(amount_in * 997 * reserve_out / (reserve_in * 1000 + amount_in * 997))
```

它给无额外代币行为假设下的池端报价，不等于钱包到账。储备方向必须由 token0/token1 决定，不能固定使用 reserve0。

**主测量取同一次执行中的 `token.balanceOf(wallet)_after − before`。** supporting-fee-on-transfer 的买/卖方法没有返回值；普通买入函数的 `amounts` 是预先计算的报价。只拿函数返回值或 Transfer 日志，不能替代余额测量。[Router02 源码](https://github.com/Uniswap/v2-periphery/blob/master/contracts/UniswapV2Router02.sol)

`quote_out − received` 记录为 `quote_credit_gap`；有符号差值不是自动识别的税率，可能来自储备/余额偏离、代币行为、反射、重基或测量错误。原始数量一律用整数，decimals 仅用于展示。

**脚本 v2.0 的实现：** 在临时地址注入内嵌 Probe 运行时代码，通过一次 `eth_call` 依次读取余额、调用 supporting 方法、再读取余额；记录余额前后值、成功阶段和原始 revert bytes。无部署、签名或广播。trace 接口与 Multicall3 均非必需。

这是一只**合约测量钱包**。目标可能读取 `msg.sender`、`tx.origin`、代码长度或资格，因此正常控制币通过不能推成对所有 EOA 策略等价。正式样本须声明匹配该钱包模型，或另有经验证的 EOA 测量实现；有上下文敏感行为而无法验证等价的样本标为 `model_unsupported`。

模拟的 `amountOutMin=0`、deadline=快照 timestamp+3600 是测量选择，不是实盘滑点建议。真实滑点保护、纳入区块与排序未覆盖。

## 5. 卖出、持仓状态与失败

按冻结退出快照卖出该笔买入所得的全部可出售持仓。**两个历史区块各做一次 eth_call 不会保存第一次买入的状态。**[Geth overrides 文档](https://geth.ethereum.org/docs/interacting-with-geth/rpc/objects)

本脚本的有限探针：在退出快照按两个不同哨兵值探测余额映射槽，要求唯一匹配、读回符合、移除覆盖后恢复；注入买入币数，再实际执行 approve(0)、approve(amount)、卖出，读取**同一次执行中原生 ETH 余额增量**。不再假定授权已经存在，也不使用“地址余额不同”作为卖出错误分类通过标准。

**这只验证测量能力，不是完整 30 天持仓回放。** 正式样本还须确定：买入区块/时间、冷却、黑白名单、份额或重基、持有期到账变化、代理升级，以及自身交易对池状态的影响如何处理。槽位找得到不证明状态充分；固定扫描找不到也不证明不能卖。

本轮只接受具备可审查状态适配依据的样本近似；其余仍留在原样本并标未知。不能只保留普通 ERC-20 再称为全母体。

| 状态 | Z/M 处理 |
|---|---|
| `no_mint_by_cutoff` | Z=0；M 不适用；无交易成本 |
| `entry_failed_verified` | 本冻结规则未入场，Z=0；M 不适用；扣实际/情景失败成本 |
| `entry_unknown` | Z 未知、M 未知；不能当作未入场 |
| `measured_exit` | 记录实际余额增量、残余币数、全部成本，计算近似 M |
| `exit_failed_verified` | 只有在状态充分、成本明确且规则规定单次尝试时，才可记本路径现金回收 0、M=0；不宣称代币永久不可卖；残余持仓另列 |
| `execution_reverted_unknown` | 原始 revert 证据保留；Z/M 未知，不改名为蜜罐或不可卖 |
| `model_unsupported` | 状态或钱包语义不足，Z/M 未知 |
| `data_missing` / `decode_error` | 数据失败，Z/M 未知；RPC 错误不能冒充链上失败 |
| `right_censored` | 尚未到退出快照，Z/M 未知 |
| `zero_reserve_observed` / `code_absent` | 诊断字段；单凭它们不直接设 M=0。储备、实际余额和上下文需核查 |

保留过程字段（触发、入场、退出、模型、数据）而不是一个互斥字符串覆盖一切。收益失败与测量失败分开；确认无现金回收也不等于经济上永无残值。

## 6. 成本和倍数

设成功买入的候选：投入本金 `A=0.05 ETH`；退出时卖出调用实际转入钱包的 ETH 为 `R`（**尚未减 gas**）；所有实际尝试、授权的 gas 成本合计 `G`。

```
I = A + G
M = R / I
本路径净现金流 = R − A − G
```

上述净现金流不自动等于已实现交易损益：若退出失败或仍有持仓，未处置成本基础与残余资产另列，不把 A 全部当作已实现亏损。已实现损益按账本 §5.4 的处置数量配对规则计算。

LP 费、价格冲击和合约执行的转账扣减已体现在 R/到账币数，不重复扣。ETH 输出与 WETH 不能未经说明混用。M>=10 是净现金回收 10 倍总投入，现金盈利 9 倍投入；它不是收益期望值。

| 成本 | 本轮处理 |
|---|---|
| LP 费 | 标准 V2 的 0.3% 已在合约/997 公式中体现 |
| 确定性价格冲击 | 已在指定规模的公式/执行中体现，不再额外减一次“滑点” |
| gas 单价 | `baseFeePerGas + priority_fee`；只用 base fee 不能称为全费率 |
| gas 用量 | 有可解释的同路径估计则记录方法；测量 helper 的总 gas 不等于真实单次 EOA swap gas |
| 未校准敏感性 | swap 每边 120k/150k/200k gas；每次 approve 50k；priority fee 0/0.1/1 gwei，形成预先声明的 9 组 swap/tip 情景；**均为设计假设，不是上下界保证** |
| 授权 | 独立列出本规则需要的授权次数与每次 gas；脚本两次授权处于同次模拟，不假装复原 EOA 两笔交易的中间状态 |
| 失败尝试 | 计所有失败买入、授权、退出尝试；拿不到 gas 时标未知或按冻结情景计，不只扣成功买入 |
| 竞争/MEV | 本轮未测；不能给解析/单点模拟结果冠以“全部成本已扣净” |
| 运营、汇率 | 不进本次 ETH 单笔 M；在账户工作包单列，不能用此表直接证明人民币净利目标 |

这些情景不是挑最好结果的参数搜索。报告所有情景与每项未覆盖成本。主汇总用 150k、0.1 gwei 作为设计参考，并同时报告跨情景稳定/不稳定的右尾归类；因尚未校准，不称为市场准确成本。

## 7. 报告与统计主张

报告 `n_entered` 上 M 的经验分布，明确未知数量：`0`、`(0,1)`、`[1,10)`、`[10,50)`、`[50,100)`、`[100,∞)`。每档列个数、R 总额和路径净现金流总额，残余持仓另列。不同费用下不可只平均 M 推出账户利润。

对固定样本 n，令确认 Z=1 数为 k，Z 未知数为 u，则样本机会率识别区间为：

```
[k/n, (k+u)/n]
```

它仅表达缺失值导致的不确定性，**不是总体 95% 置信区间**。对条件入场发生率另用对应分母，不能混用。缺失偏差方向无证据时写“不确定”，不要强迫猜测方向。

**H1 是本轮唯一正式主检验：** 固定历史候选母体中，Z=1 的比例至少 1%。

- 仅在完整抽样框、有效随机抽样、统一测量模型、成本口径和足够可判定结果下分析。
- 对固定有限母体，使用无放回的**超几何分布**。零命中且无未知时，检验 `K >= ceil(0.01*N)` 的尾概率为 `C(N−K,n)/C(N,n)`（组合数无定义的情形按概率 0 处理）；这是抽样设计推断，不要求固定母体各候选经济结果相互独立。
- 若明确采用独立同分布二项近似，n=300、零命中单侧 95% 上限为 **0.993608%**；临界样本量 299。此近似不自动适用于未来时期或相关的非随机便利样本。
- p=0.5% 时，300 次零命中的概率约 **22.23%**。因此拒绝“至少 1%”不等于“没有 10× 空间”。
- 有未知结果时不使用零命中捷径；先报识别区间。必要时对未知全部为成功的保守情景做同口径推断，否则 H1 标“证据不足”。
- 成本情景给出敏感性结果；仅参考情景通过不能宣称所有情景成立。模型误差未受控时只报告条件结果，不给真实市场发生率背书。

**D2 为描述性诊断：** 条件 M 中位数及低于 0.5 的占比，附分母/未知与成本情景。原来的 H2 已删除：直接读取样本中位数不是一个完整总体检验。平均/中位亏损不能判死筛选价值。

H1 低于本轮 1% 灵敏度时，本轮可按资源规则关闭；理由是“该配置下未达到本轮关注的发生率”，不是“机会不存在”。发现个别右尾也不证明可预测、可重复或足以实现三年目标。

## 8. 冻结、数据使用与停止

1. 先完成本配置的设计字段与测量器能力验证；在读取候选收益前固定。协议版本、脚本 hash、原始来源和控制样本留档。
2. 解析区块边界、全量枚举并保存抽样框和样本；不能利用候选收益决定是否进入抽样框。
3. 写 `config_frozen.json`：`payload` 包含上述所有设计字段和解析结果；`payload_sha256 = SHA256(UTF-8(json.dumps(payload,sort_keys=True,separators=(',',':'),ensure_ascii=False)))`。**hash 在 payload 外，消除自指**。保存冻结时间、输入文件 hash、环境版本。
4. 本轮 300 个为**描述性基线/开发资料**。看过其收益后不能再称其中后 150 个为未使用检验集。下一次信号确认须用尚未看过的时期/样本，或新的前向窗口。
5. 只按固定终点做 H1，不按中途结果停样本或改变规则。`looks` 留审计记录；**计数器本身不控制多重检验或可选停止**。因预算提前结束只交描述性结果，不声称原固定样本显著性仍有效。
6. 发现前视、错误接口、状态重建失效或分母污染，立即暂停并传播到依赖结论；修改后创建新实验版本，保留旧结果。

每条数据分别保存：`event_time`、`observed_at`（本次程序实际取得）、`feature_cutoff`、`intended_order_time`，另存实际状态快照的块号/hash。历史回填的 observed_at 不是过去首次可得时间；没有当时接口记录时，历史可及时取得性保持未验证。

## 9. 能力验证脚本与启动条件

本脚本仅是前置测量器，**不包含 300 个候选采集器或基线计算器**。

| 检查 | 必须给出的证据 |
|---|---|
| T1 | chain id；固定 finalized 快照 |
| T2 | 本配置真实时间窗口上的历史 allPairsLength，索引端点、配对资产和 getPair 交叉核对；不假称已经全量枚举 N |
| T3 | 控制池首次 Mint 的历史 totalSupply 边界和单块 Mint 事件；支持老币，不限回看 400k 块 |
| T4 | 两个历史快照上用两个数值证实 code/balance/stateDiff **实际生效**，移除后恢复；只收到成功响应不算通过 |
| T5.buy | 同次调用实际余额增量和 ETH 支出 |
| T5.sell | 历史退出快照、受限槽扫描、实际授权与卖出后的 ETH 增量；只支持有限状态探针 |
| T6 | 在同一执行环境注入受控普通、双侧税、缺余额、缺授权和受限合约；核对金额、错误阶段与受限错误码 |
| T7 | 本次用到的历史块 hash 在结束时仍一致 |

普通代币与历史“蜜罐”两个地址结果不同不够。脚本已移除未使用的 `--honeypot` 参数；人工标签不再冒充测试用例。

脚本返回：0=所选模式的必需检查完成；1=检查失败；2=必需检查未执行。无 RPC 也会输出 UNRUN 日志。离线模式即使返回 0 也不是端点通过。任何异常尽量写入完整日志；参数语法错误由命令行解析器返回 2。

**正式基线启动采用依赖条件，不能机械要求所有可选技术都可用：**

- 真实端点 T1–T7 通过；不要求未使用的 trace/Multicall 接口通过。
- 配置/成本冻结，完整 N 和样本已保存。
- 对候选状态、钱包语义、缺失分类有明示适配规则；不支持的对象保留为未知。
- 在少量候选上完成端到端质量检查，证明分母、时点、金额、状态和成本字段能够一致输出；该部分若查看了候选收益，计入本轮开发资料，不留作未来独立检验。

脚本不自行宣告 `baseline_ready=true`，不自动启动正式样本。它的 PASS 不能替代另外几项尚未实现的条件。

## 10. 数据源、调用预算与运行方法

不依赖 Etherscan 的身份归因；需要归档 **状态读取和执行**，并支持所选历史 stateOverride。RPC 服务可以要求 API key；无需提供真实钱包、私钥或身份信息。

Alchemy 当前官方端点表列 Free `eth_getLogs` 单次 **10 块**；这不表示不能用日志，而是不能按旧版“每次 2000 块”估算。单块事件交叉核对仍须在实际端点验证。[Alchemy 官方限制](https://www.alchemy.com/docs/chains/ethereum/ethereum-api-endpoints/eth-get-logs)

调用成本估计必须包含：时间戳二分、2 次计数、约 `3*N_all` 次地址与资产枚举、抽样对象首次 Mint 二分/交叉日志、每笔余额/授权适配和买卖模拟、历史 hash 复核、失败/限流重试。槽扫描最坏成本随扫描上限增长。RPC 请求次数不等于供应商计算单位或实际费用；本版删除“约 5000 次、免费档一定可完成”。

探针默认最多 700 次 RPC、600 秒、每秒 3 次；最多一次针对指定 HTTP 限流/临时错误的重试。耗尽即留日志。实际调用、返回/错误与耗时逐项保存；后续批量预算据此重估。探针的等待时间与主动工时分别记录，不自动延长 8 小时。

运行（Python 3.10+）：

```bash
mkdir -p runs
python -m pip install 'eth-hash[pycryptodome]' eth-tester py-evm
python verify_capabilities.py selftest --out runs/local-selftest.json
# 在本地环境设置 ETH_RPC_URL，勿把含凭据的 URL 写入共享日志。
python verify_capabilities.py run --out runs/endpoint-verification.json
```

> **输出一律写 `runs/`，不得写包根目录。** 包内的 `offline_verification.json` 与
> `verification_log.json` 是**受 manifest 约束的历史证据**，被 `verify_package.py`
> 按 hash 校验；写到那两个路径会破坏包完整性且原字节无法恢复。此前本节的命令正是
> 直接指向那两个文件，与 START_HERE 的要求冲突，已在 v2.1 修正（见 `ERRATA-v3.md`）。

默认控制代币 DAI；不是本轮候选或投资选择。必要时用 `--token` 指定另一个窗口前已存在的控制代币；更换必须留原因。二次执行会覆盖指定输出路径，需保留前次记录时换一个 `--out` 文件名。

内嵌测量合约包含 Solidity 源码与字节码，不需用户下载编译器。编译参数已写在脚本头；离线对照使用独立 py-evm 执行。脚本对 RPC 的方法有只读白名单，没有签名或交易广播功能。
